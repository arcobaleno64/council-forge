## Issue

**Issue: v1 RACI audit 缺乏 fail-closed、JSON output 與 alias rejection**

v3.4 plan §4.2 列出五大必要行為：
1. Fail-closed（unknown agent / path → FAIL，非 pass-through）。
2. Structured JSON output（raw_violations / waivers_applied / post_waiver_violations 分離）。
3. Alias strictness（alias 非 first-class canonical proof，strict mode 下拒絕）。
4. `--fix` rejection（exit 2）。
5. No docs-as-code fallback（path 無法識別 → FAIL，非 fallback 到 "code"）。

## Options Considered

**RACI_MATRIX_V2 vs 更新 RACI_MATRIX v1：**
- A. 更新 RACI_MATRIX v1，改用 path category → 需同步更新 validate_raci_hybrid_sync 與 docs/subagent_roles.md；後者在禁止修改範圍內。
- B. 並存 RACI_MATRIX v2，v1 保留給 validate_raci_hybrid_sync，v2 專用於 --audit-raci → 無需修改 docs；validate_raci_hybrid_sync 繼續正常運作。

**Chosen: B**

**classify_path 的 unknown fallback：**
- A. 未識別路徑 fallthrough 到 "code" 類別（現有行為）→ 不安全；任何路徑都能通過 Codex CLI RACI check。
- B. 未識別路徑返回 "unknown"，在 v2 中一律視為 violation → 真正 fail-closed。

**Chosen: B**

## Reasoning

1. **Fail-closed semantics**：`classify_path()` 返回 "unknown" 是 fail-closed 的核心。任何未在 19 個 prefix rule 或 filename rule 中命中的路徑，都無法通過任何 agent 的 RACI check（因為 RACI_MATRIX_V2 中無 agent 允許 "unknown"）。
2. **Alias = migration debt**：`ALIAS_MAP`（Codex / Claude / Gemini）是歷史遺留命名；在 strict mode 下拒絕，強制遷移到 canonical name。`--compatibility-mode` 提供可控的遷移路徑（emit warning，允許解析）。
3. **--fix 無條件 exit 2**：RACI violations 不可 auto-fix；需 decision / waiver / correction artifact。`--fix` flag 在 `--audit-raci` 下的語意是未定義的（v1 有此 flag 但語意不清）；v2 明確定義：exit 2，無論其他參數為何。
