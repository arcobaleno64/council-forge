## Issue

TASK-964 produced historical drill evidence using the deprecated alias `Codex` as the agent name. RACI Auditor v2 (implemented in TASK-1007) now enforces alias strictness — the alias `Codex` is rejected entirely (exit 2, ALIAS_REJECTED), not just flagged as a RACI violation. This means TASK-964's original drill evidence was produced under a weaker enforcement regime that did not reject aliases.

Two questions required resolution:
1. Can TASK-1010's production evidence retroactively upgrade TASK-964's maturity?
2. Which agent name is correct for the production canonical drill?

## Chosen Option

**TASK-964 remains permanently `mvp + historical limited evidence`. TASK-1010 uses canonical `Codex CLI` for the production drill.**

- TASK-964 classification: unchanged — `assurance_level: mvp`, `verification_readiness: mvp`, `Overall Maturity: mvp`, `Evidence Floor: limited`. This is a permanent classification per v3.4 §4.4.
- TASK-1010 canonical agent name: `Codex CLI` (the v2 canonical identity per TASK-1007 agent_identity.py).
- TASK-1010 evidence: production-grade — structured JSON output (`schema_version: raci-audit/v2`), exit code 1, deterministic Taipei timestamp, reviewer attestation.

## Reasoning

**Why TASK-1010 evidence cannot retroactively upgrade TASK-964**:
- v3.4 §4.4 explicitly forbids retroactive upgrade: "Repaired evidence MUST NOT retroactively upgrade TASK-964's maturity."
- TASK-964 reached the right conclusion (circuit breaker blocks out-of-bounds edits) but under a weaker evidence floor:
  - Used deprecated alias `Codex` (now rejected by RACI Auditor v2)
  - No structured JSON output (RACI Auditor v1 format)
  - No deterministic timestamp
  - No reviewer attestation
- The right-answer-for-wrong-reason classification is not a quality score — it is a historical fact about the evidence floor at the time of production.

**Why `Codex CLI` is the correct canonical name**:
- TASK-1007 implemented RACI Auditor v2 with alias strictness. `Codex` is now rejected (exit 2, ALIAS_REJECTED) rather than allowed with degraded evidence.
- The production canonical drill must use the canonical name to demonstrate that the circuit breaker correctly fails on `Codex CLI` → `workflow_contract_docs` → `VIOLATION` (exit 1), not on an alias rejection.

**Alias comparison as confirmatory evidence**:
- `--audit-raci docs/orchestration.md Codex` → exit 2, ALIAS_REJECTED. This confirms TASK-964 used a name that is now invalid.
- `--audit-raci docs/orchestration.md "Codex CLI"` → exit 1, VIOLATION. This is the production-grade result.
