## Issue

TASK-1001（Governance Lens Explicitization）於 2026-04-25 建立，含 10 個 AC，狀態為 `drafted`。v3.4 governance repair plan 執行後（TASK-1005 至 TASK-1010），TASK-1007 以 RACI Auditor v2 取代了 TASK-1001 AC-6 / AC-10 的計畫方式，但 TASK-1001 未被正式 reconcile。同時，AC-5 的 GEMINI.md 整合部分仍未完成，v3.4 plan 亦未涵蓋此項。

Three questions required resolution:
1. AC-6 / AC-10 應標記 superseded-by-TASK-1007，或仍視為 open gap？
2. AC-5 GEMINI.md integration 是否被 v3.4 任何 task supersede，或為 deferred？
3. TASK-1001 最終狀態應為何（blocked / done / superseded）？

## Chosen Option

**Decision 1**: AC-6 和 AC-10 標記 `superseded-by-TASK-1007`。TASK-1007 之 RACI Auditor v2 實作完整覆蓋且超越 TASK-1001 AC-6 / AC-10 的設計意圖。無殘餘義務。

**Decision 2**: AC-5b GEMINI.md Architecture Synthesizer dispatch mode 標記 `deferred（not in v3.4 scope）`。此為 deferred 而非 superseded：無後繼 task，工作仍需完成，留待後續獨立 task。

**Decision 3**: TASK-1001 最終狀態為 `blocked`（WORKFLOW_STATES 合法）；`superseded_by.scope = "partial"`（v3.4 §5.0 補充欄位，記錄 AC-6/AC-10 partial supersession）；`remaining_obligations = ["AC-5b: GEMINI.md Architecture Synthesizer dispatch mode"]`。TASK-1001 不得標為 done（AC-5b 無 evidence）。

## Reasoning

**Why AC-6 / AC-10 are superseded-by-TASK-1007**:
- TASK-1007 實作了 `_run_raci_audit_v2()`（guard_contract_validator.py）：fail-closed path classification（19 prefix rules）、structured JSON output（schema_version: raci-audit/v2）、raw_violations + waivers_applied + post_waiver_violations 顯式分離、alias rejection、--fix rejection。這比 TASK-1001 AC-6 原計畫的「file-level R-permission check」更全面。
- TASK-1007.verify.md AC-9 確認 raw_violations / post_waiver_violations 分離（對應 AC-10 violation/waiver 分離要求）。
- `.github/memory-bank/raci-violations-log.md` 已建立，append-only（對應 AC-10 log 要求）。
- `docs/templates/raci-auditor/TEMPLATE.md` 已建立（對應 AC-6 template 需求）。
- AC-10 C-4 ADD（unit test-first）: TASK-1007 採 docs-spec adapter，NOT_APPLICABLE_BY_ADAPTER 合法替代。

**Why AC-5b GEMINI.md is deferred, not superseded**:
- 無任何 v3.4 task（TASK-1005 至 TASK-1022）涵蓋 GEMINI.md Architecture Synthesizer 整合。
- Supersession 要求有明確的後繼 task；deferred 表示工作仍在，只是未被安排。
- Full supersession 會隱性丟失 remaining obligation，違反 v3.4 §4.5 "no criterion silently dropped"。

**Why blocked is the correct state for TASK-1001**:
- `done`: rejected。AC-5b 無 evidence，違反 v3.4 §4.5「若任何 criterion remain unimplemented，不得標 done」。
- `superseded`（full）: rejected。AC-5b 無後繼 task；full supersession 丟失 remaining obligation。
- `superseded` as state string: rejected。`superseded` 不在 WORKFLOW_STATES（guard_status_validator 會拒絕）。
- `blocked`：selected。合法 WORKFLOW_STATE；blocked_reason 指明 AC-5b open；`superseded_by.scope = "partial"`（v3.4 §5.0 schema）作為補充欄位記錄 AC-6/AC-10 partial supersession。
