## Issue

`validate_context_stack.py` lines 18-21 包含模組層（module-level）的 `sys.stdout`/`sys.stderr` 替換邏輯，在 `if __name__ == "__main__"` 或任何 CLI entrypoint 保護之外執行。這造成：

1. 在測試環境中（sys.stdout = io.StringIO，無 .encoding 屬性）import 會引發 AttributeError。
2. 作為 library 被 import 時，靜默替換呼叫者的全域 stream 物件，違反 import-clean 原則。
3. v3.4 §4.6b 要求「introduce an explicit init function that takes streams as arguments」。

Two design options:
- A: 僅將邏輯移入 `main()` 內部（簡單，但不可測試）。
- B: 引入 `init_streams(stdout=None, stderr=None)` 函式，從 `main()` 呼叫（可測試，符合 v3.4 要求）。

## Chosen Option

**Option B**: 引入 `init_streams(stdout=None, stderr=None)` 函式。

- 移除 lines 18-21 的模組層 stream 替換。
- 在 Config 區段前新增 `init_streams()` 函式，接受可選的 stdout/stderr 參數（用於測試注入）。
- `main()` 首行呼叫 `init_streams()`，保持 CLI 行為（encoding fix on Windows）不變。
- 函式使用 `hasattr(out, "buffer") and getattr(out, "encoding", "utf-8") != "utf-8"` 安全條件，避免對無 .buffer 的 stream（如 StringIO）操作。

## Reasoning

**Why Option B over Option A**:
- v3.4 §4.6b 明確要求「explicit init function that takes streams as arguments」，Option A 不符合。
- Option B 的 `stdout=None, stderr=None` 參數允許在 unit test 中注入 mock streams，驗證函式邏輯而不影響真實系統 streams。
- `getattr(out, "encoding", "utf-8")` 安全處理無 .encoding 屬性的 stream（StringIO），而原始 `sys.stdout.encoding` 直接存取在 StringIO 上會 AttributeError。

**Why no change to EXACT_SYNC_FILES**:
- `validate_context_stack.py` 不在 EXACT_SYNC_FILES，guard_contract_validator 不強制 exact-sync。
- 手動 cp source → template 已確保 sync；加入 EXACT_SYNC_FILES 需額外修改 guard_contract_validator.py + template，超出本 task scope。

**Why CLI behavior is preserved**:
- `init_streams()` 在 `main()` 首行呼叫，timing 等效於原始模組層邏輯（main() 執行時早於任何 print）。
- 條件邏輯與原始相同（encoding != utf-8 才替換），僅增加 hasattr guard。
