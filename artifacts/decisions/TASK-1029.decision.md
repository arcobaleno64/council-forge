## Issue

v3.5.0 closed 後，QC-SYNC-001 之證據結構僅含 TASK-1025 之 self-check pass（37 checks，21 為 QC-SYNC-001）。**正向證據**已立，但 **負向證據** — 即「QC-SYNC-001 真能擋下被預測之 violation」 — 尚缺。

TASK-1028 v3.5.1 plan §5.2 列六種 negative cases；TASK-1029 須證明 `run_quality_gates.py:run_qc_sync_001` 對六案皆給出 expected outcome：

| Case | Expected status | Expected reason_code |
|---|---|---|
| post-baseline source-only addition | fail | post_baseline_new_pair_missing_template |
| post-baseline template-only addition | fail | post_baseline_new_pair_missing_source |
| post-baseline source/template drift | fail | post_baseline_new_pair_drift |
| valid unexpired waiver | skipped_with_reason_code | post_baseline_new_pair_waivered_until:&lt;date&gt; |
| expired waiver | fail | post_baseline_new_pair_waiver_invalid:expired:&lt;date&gt; |

**關鍵衝突 1（如何隔離真實生產樹）**：

QC-SYNC-001 之 `SOURCE_TEMPLATE_ROOTS` 為 hardcode `[("artifacts/scripts", "template/artifacts/scripts")]`。若 negative case 之 fixture 直接寫入這些真實生產路徑，將：

- (a) 污染真實 source/template pair；
- (b) 使後續真實 QC-SYNC-001 run 之 Pass 2 fail（fixture 變成 post-baseline new pair）；
- (c) 違反 prompt §2 「do not broadly modify existing source/template paired files」與 「do not mutate real production source/template pairs to create failures」。

四種選擇：

- **A. 直接寫入真實 `artifacts/scripts/` 與 `template/artifacts/scripts/`，跑完後手動清理**：易遺漏、會留 mutation 痕跡於 git history、違反「reversible test sandbox」原則。
- **B. 改 runner 加 `--repo-root` CLI flag，fixture 用獨立 repo root**：runner 須改、root/template mirror 須同步、需驗證 byte-identical、增加 mirror sync 風險。
- **C. 寫 monkey-patch script 把 SOURCE_TEMPLATE_ROOTS 改成 fixture 路徑**：脆弱、改 module global state、violates single responsibility。
- **D. import run_quality_gates as module，直接呼叫 `run_qc_sync_001(fixture_repo_root, baseline, policy, today_iso)`**：第一參數已是 repo_root，根本無需改 runner；fixture 樹模擬 mini-repo（含 `artifacts/scripts/` 與 `template/artifacts/scripts/` 子目錄）；synthetic baseline / policy 為 in-memory dict。

對策：採 **D**。

理由：

- `run_qc_sync_001(repo_root, baseline, policy, today_iso)` 之 signature 已將 repo_root 抽象化；driver 傳 `artifacts/verify/TASK-1029/fixtures/case-XXX/` 為 repo_root，runner 內 `discover_current_pairs(repo_root)` 與 `repo_root / src_rel` 自然指向 fixture 樹。
- 真實生產樹之 `artifacts/scripts/` 與 `template/artifacts/scripts/` 全程未被 driver 觸碰。
- runner 與 mirror 不改，byte-identical 保證自動成立。
- import 為唯一 side effect；driver 設 `sys.dont_write_bytecode = True`（在 import 前）+ env `PYTHONDONTWRITEBYTECODE=1`，無 `__pycache__` 副作用。

**關鍵衝突 2（baseline 與 policy 怎麼合成）**：

case-006 需 baseline pair 含 status=drift + 與 fixture 一致之 SHA-256；case-004 / case-005 需 policy.waivers 含六欄齊備之 waiver。三種選擇：

- **A. 修改真實 `quality-baseline.v3.5.json` 與 `quality-gate-policy.v3.5.json`，加 fixture pair 與 fixture waiver，跑完後 revert**：違反 prompt §2 「do not rewrite quality baseline except for an isolated test fixture copy」之精神（「except」之 fixture copy 應為獨立檔，非 in-place modify revert）；任一 commit window 內若 push 將擴散污染。
- **B. 在 fixture 樹中放獨立 `quality-baseline.json` / `quality-gate-policy.json`，driver 載入這些檔**：增加 fixture 檔數；獨立 JSON 須與 schema 一致才能 load；多此一舉。
- **C. driver 直接構造 in-memory dict 作為 baseline / policy 參數**：runner `run_qc_sync_001` 之 baseline / policy 參數為 dict（非 file path），可直接傳入；driver 在 case-006 執行時 `sha256_file(fixture_path)` 計算 SHA 並嵌入 baseline dict。

對策：採 **C**。

理由：

- runner signature 已支援 dict 參數，無需 file 載入。
- 真實 governance JSON 全程不動。
- baseline + policy 與 fixture 同 source-of-truth（driver runtime）；無檔案 drift 風險。

**關鍵衝突 3（waiver 是否動真實 policy）**：

waivers 之來源是 `policy.waivers` 陣列。若加 fixture waiver 至真實 `quality-gate-policy.v3.5.json` 之 `waivers` 陣列：

- 違反 prompt §2 forbidden 列表精神。
- 若 commit / push，real waivers 陣列被污染，後續真實 QC-SYNC-001 run 會視 fixture waiver 為合法 waiver。
- 真實 policy 之 `waivers: []` 為 v3.5.0 既定 stance（TASK-1025 deliverable）。

對策：waivers 採 in-memory synthetic policy.waivers，**不**改真實 `quality-gate-policy.v3.5.json`。

**關鍵衝突 4（cache pollution 防範）**：

`import run_quality_gates` 之 default 行為會在 `artifacts/scripts/__pycache__/` 建立 `run_quality_gates.cpython-XYZ.pyc`；`python artifacts/verify/TASK-1029/run_negative_tests.py` 之 default 行為會在 `artifacts/verify/TASK-1029/__pycache__/` 建立 driver .pyc。兩者皆會：

- 污染真實 source 樹（`artifacts/scripts/__pycache__/` 之新 .pyc 為 git untracked，但屬 noise）。
- 影響後續 QC-IMPORT-001 之 candidate 評估（雖目前 advisory，未來 strict 後易 false positive）。
- 違反 prompt §4 forbidden 「cache-writing tools」精神。

對策：

- driver 第二行即設 `sys.dont_write_bytecode = True`（在 import 任何 module 前）。
- invocation 採 `PYTHONDONTWRITEBYTECODE=1 python -B artifacts/verify/TASK-1029/run_negative_tests.py`（env + `-B` flag 雙重保險）。
- post-execution `git status --short` 確認無 `__pycache__/` 或 `*.pyc` 新增。

**關鍵衝突 5（fixture 可重 run 但結果可能 LF/CRLF 漂移）**：

case-006 需要 baseline 內嵌之 SHA-256 與 fixture 檔之 actual SHA-256 嚴等。若 fixture 以 LF 寫入但 git checkout 時轉為 CRLF（Windows），SHA 會漂；若 driver 先計算 SHA 再讀檔比較，可能不一致。

對策：

- driver 在 runtime 即時 `sha256_file(path)` 計算 fixture src/tpl 之 SHA，內嵌至 synthetic baseline.source_template_pairs[0].sha256_source / sha256_template；無「靜態紀錄之 SHA」與「實際讀取之 SHA」漂移。
- driver 採 binary read（`open(path, "rb")`）避免 text mode encoding 干擾。
- 結果 JSON 顯示 case-006 `pass=true` 已證明此防護有效。

## Reasoning

1. **artifact-first lifecycle 延續**：TASK-1023..1028 雙標 decision_class framing 已立 v3.5.0 / v3.5.1 governance pattern；本 decision 沿用 forward-compat + backward 相容設計（YAML frontmatter 用新 taxonomy `governance-qc-sync-negative-test`、markdown body 用既有 `conflict-resolution`）。
2. **import-as-module 之必要性**：runner `run_qc_sync_001` signature 第一參數即 repo_root；提供任意 fixture repo root 即可隔離真實生產樹；無須改 runner；無須維 mirror byte-identity；最小可行隔離策略。
3. **synthetic in-memory baseline + policy 之必要性**：runner signature 已支援 dict 參數；無須 fixture file；真實 governance JSON 全程不動；waivers 之六欄齊備規則 + 過期判定皆可由 in-memory dict 完整覆蓋。
4. **cache 防護之必要性**：`sys.dont_write_bytecode = True`（import 前）+ `PYTHONDONTWRITEBYTECODE=1` env + `python -B` 三重保險；確保 driver execution 不留任何 `__pycache__` 或 `*.pyc`；保 QC-IMPORT-001 之 candidate baseline 純淨。
5. **runtime SHA 計算之必要性**：case-006 之 baseline SHA 由 driver runtime 計算並嵌入；避免「git checkout 之 LF/CRLF 轉換」與「driver 讀取之實際 byte」漂移；fixture 檔內容亦不需手動維護 SHA 註解。
6. **不 remediate baseline drift 之必要性**：違反 prompt §7 + decision §「Non-authorization」；baseline drift 之 remediation 屬未來 task lifecycle，須有獨立 decision 顯式授權。
7. **fixture 樹放在 `artifacts/verify/TASK-1029/fixtures/` 之必要性**：與 task 之 verify evidence 同 namespace；codex post-commit verifier 可在同一目錄一次取齊 fixture + driver + result JSON；commit clean-up 與 git tracking 皆 atomic。
8. **不執行 pytest 之必要性**：prompt §2 forbidden；pytest 之 conftest 收集 / fixture lifecycle / cache 機制皆增加非必要複雜度；driver 為 single-file Python script，可由 codex 直接 `python -B` 執行驗證。
