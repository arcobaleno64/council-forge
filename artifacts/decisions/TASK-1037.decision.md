## Decision

### Chosen option

Implement controlled golden CLI coverage under TASK-1037 lifecycle only.
The implementation produces:

- five lifecycle artifacts (task / plan / decision / verify / status)
- one harness script `artifacts/verify/TASK-1037/run_golden_cli_coverage.py`
- one case manifest `artifacts/verify/TASK-1037/golden-cli-case-manifest.json`
- one result JSON `artifacts/verify/TASK-1037/golden-cli-coverage-result.json`
- one controlled fixture tree under `artifacts/verify/TASK-1037/fixtures/`

The harness invokes both production runners (`run_precommit_check.py`
and `run_quality_gates.py`) via subprocess against fixture-local repo
roots, fixture-local policies, fixture-local baselines, and fixture-local
Evidence Ref policy registry copies. Production runner bytes are not
modified; fixture-local runner copies are byte-identical to the
production runners (verified via sha256 prefix).

Output contracts are robust subset assertions, not full-output byte
equality:

- `exit_code` literal per case (0 / 1 / 2)
- `json.loads(stdout)` parses; locked fields equal expected literal or
  expected prefix
- `stderr` empty unless explicitly justified
- post-run no `__pycache__` or `*.pyc` under fixture root

### Rejected options

#### Option A: import the production runner via importlib instead of subprocess

Rejected. Importlib bypasses CLI parsing, exit-code semantics, and
stdout JSON envelope, defeating the "lock CLI surface" goal of
TASK-1036. This option also pollutes the harness process with runner
module state and risks `__pycache__` writes despite
`sys.dont_write_bytecode=True`.

TASK-1035 used importlib for direct PCACC-002 function calls; that
choice was scoped to runtime extraction validation, not CLI surface
locking. TASK-1037's mission is the CLI surface lock, which requires
subprocess.

#### Option B: invoke the live runner from the live repo root

Rejected. Live runner's `SCRIPT_PATH.parents` would resolve to the live
repo root, consuming live policies / baselines / lifecycle artifacts.
This breaks fixture isolation (the harness would silently depend on the
live state of the repository rather than on its own controlled input)
and risks polluting the live repo with cache writes.

The mitigation (per-case fixture-local runner copy) is one-line writes
of byte-identical content; the cost is small relative to the
fixture-isolation gain.

#### Option C: implement all 36 planned matrix cases

Rejected for v3.5.5. The matrix's 36 cases include subsidiary surfaces
(QC-IMPORT-001 four sub-cases, QC-SYNC-001 six sub-cases including
waiver expiration, QC-SCHEMA-001 four sub-cases including malformed
JSON of governance-repair-manifest) where the marginal value of a
golden lock is lower than the fixture-engineering cost. TASK-1037
implements 24 cases that cover every required group with at least the
representative fail / pass / advisory / skipped surfaces; remaining
cases are recorded with
`implementation_status=implemented_with_limitations` or
`skipped_with_reason_code` so a future lifecycle can extend coverage
without re-deriving the case set.

#### Option D: introduce PCACC-005 to formalize golden CLI coverage as a check

Rejected. TASK-1035 / TASK-1036 status both record
`pcacc_005_introduction_authorized=false`. PCACC active surface remains
{PCACC-001, PCACC-002, PCACC-003, PCACC-004}. Golden CLI coverage is
implemented as test-evidence under TASK-1037 evidence path, not as a
new active PCACC check.

#### Option E: refresh quality baseline to match new PCACC runner sha

Rejected. QB-DRIFT-0001 (test_guard_units.py source/template drift) and
the PCACC runner sha drift introduced by TASK-1035 remain
baseline_existing without remediation or waiver. Baseline refresh
requires a separate decision artifact and is not in TASK-1037 scope.

performs post-commit PASS/FAIL verification per
`agent_roles.negative_tester`.

## Consequences

- Future runtime extraction, validator split, or policy registry expansion
  cannot silently regress the locked CLI surfaces; harness re-run will
  detect drift.
- Cases marked `implemented_with_limitations` or `skipped_with_reason_code`
  document remaining coverage debt; a future lifecycle can extend by
  appending to `case_groups[*].cases` without re-anchoring the existing
  literal contracts.
- Production runner sha drift introduced by any future task will require
  a refresh of the production_preservation block in the harness and may
  invalidate existing reason_code anchors; refresh is gated by a
  separate task.
- TASK-1030 NEG-002 / NEG-003 backward compat is anchored at the CLI
  boundary in addition to the in-process anchor from TASK-1035; future
  refactors must preserve both surfaces.
