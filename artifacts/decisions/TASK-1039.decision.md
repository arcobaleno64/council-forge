## Decision Class

governance-waiver-policy-registry-prototype

## Affected Gate

Waiver policy registry prototype (no active runtime gate;
documentation/index only).

## Scope

Design-only: a waiver policy registry prototype JSON plus a
companion design note plus inspection evidence over the existing
waiver semantics scattered across
`quality-gate-policy.v3.5.json#waiver_policy`,
`artifact-obligation-matrix.v3.5.json#waiver_policy`,
`evidence-ref-policy.v3.5.3.json#required_ref_contexts.RRC-5`, and
`golden-cli-coverage-matrix.v3.5.4.json#GCLI-QUALITY-SYNC`.

## Issue

Three committed governance artifacts each define waiver semantics
in their own surface:

- `quality-gate-policy.v3.5.json#waiver_policy` defines six
  required fields (`rule_id`, `scope`, `reason_code`, `owner`,
  `evidence_ref`, `expires_at`), expiration enforcement
  (`expired_is_blocking=true`,
  `missing_expires_at_is_blocking=true`,
  `missing_required_field_is_blocking=true`), and explicitly
  forbids a global registry in v3.5.0
  (`registry_forbidden=true`).
- `artifact-obligation-matrix.v3.5.json#waiver_policy` declares the
  mechanism is `decision_artifact_only`, with
  `no_standalone_registry_in_v3_5_0=true`,
  `narrative_only_waiver_invalid=true`, and the same six required
  fields.
- `evidence-ref-policy.v3.5.3.json#required_ref_contexts.RRC-5`
  governs the waiver_evidence_ref context (decision artifact
  `## Guard Exception` Scope Files must be echoed in verify
  artifact references).
- `golden-cli-coverage-matrix.v3.5.4.json#GCLI-QUALITY-SYNC`
  enumerates the runtime reason_code shapes
  (`waivered_until:<date>`, `waiver_invalid:expired:<date>`,
  `waiver_invalid:<reasons>`,
  `post_baseline_new_pair_waivered_until:<date>`,
  `post_baseline_new_pair_waiver_invalid:<reasons>`).

The v3.5.0 plan explicitly defers a standalone waiver registry
beyond v3.5.x; the closure index records it as a non-authorized
candidate (`TASK-1040 Waiver Policy Registry Prototype`). Without a
single readable contract source, any future task that introduces
waiver registry runtime risks silently disagreeing with one of the
four existing surfaces. TASK-1039 records the contract before any
runtime extraction is authorized.

## Options Considered

### Option A: Create a design-only waiver policy registry prototype and design note (chosen)

Author the prototype JSON under
`artifacts/governance/prototypes/`, the design note under
`artifacts/governance/`, and the inspection evidence under
`artifacts/verify/TASK-1039/`. No production change. No new test.
No runtime registry introduction. No prior task artifact mutation.
No TASK-1040+ creation.

### Option B: Bundle prototype with runtime extraction

Reject. Both
`quality-gate-policy.v3.5.json#waiver_policy.discovery.registry_forbidden=true`
and `artifact-obligation-matrix.v3.5.json#waiver_policy.no_standalone_registry_in_v3_5_0=true`
forbid runtime registry introduction without separate
authorization. The TASK-1038 closure index also records
`new_runtime_registry_extraction_authorized=false`. Bundling would
violate four separate non-authorization boundaries.

### Option C: Refresh `quality-gate-policy.v3.5.json#waiver_policy` directly with a richer schema

Reject. The TASK-1038 closure index records
`production_governance_policy_modification_authorized=false` and
`prior_task_artifact_modification_authorized=false`. The current
quality gate policy was introduced by TASK-1025 and is governed by
its own decision artifact; extending it requires a separate
lifecycle.

### Option D: Defer the prototype until the runtime extraction task is authorized

Reject. Without a design-time contract source, the runtime
extraction task would have to consolidate the four scattered
sources from scratch under runtime pressure. The prototype's
purpose is to make the contract readable before any runtime work
begins.

### Option E: Fold the waiver schema into the Evidence Ref policy registry

Reject. Evidence Ref policy
(`evidence-ref-policy.v3.5.3.json`) governs PCACC-002 only and does
not own quality gate waivers (QC-SYNC-001) or AOM waivers
(decision artifact `## Guard Exception`). Folding would conflate
two policy domains and break the
`prototype_changes_pcacc_active_count=false` invariant recorded in
the v3.5.x closure index.

## Chosen Option

create design-only waiver policy registry prototype

- Production runner modification is **NOT** authorized.
- Production validator/test modification is **NOT** authorized.

- TASK-1023..TASK-1038 lifecycle artifact modification is **NOT**
  authorized (including TASK-1037 repair evidence and TASK-1038
  closure evidence).
- PCACC-005 or any new active PCACC check introduction is **NOT**
  authorized.
- AC-to-verify coverage activation is **NOT** authorized.
- Bootstrap Prompt Skill modification is **NOT** authorized.
- v3.5 / v3.5.1 plan / manifest modification is **NOT** authorized.
- pytest / ruff / formatter / package manager invocation is **NOT**
  authorized.
- Modification of `.obsidian/`, `.omc/`, `.tmp/`,

- SRS / RTM / design spec / threat model / release note / migration
  note / user guide / runbook content generation is **NOT**
  authorized.
- The closure-index `new_runtime_registry_extraction_authorized=false`
  recorded by TASK-1038 still applies; this prototype does **NOT**
  lift that boundary.

Any future waiver runtime extraction (registry installation under
`artifacts/governance/`, runner attachment via a CLI flag, golden
CLI coverage of waiver paths beyond
GCLI-QUALITY-SYNC-005..GCLI-QUALITY-SYNC-006, validator split,
runtime registry expansion for the remaining RC slices) must be
separately authorized.

Claude Code commits only allowed TASK-1039 files after
self-verification passes (inspection JSON `overall_status=pass`
and no forbidden mutation). Codex performs post-commit PASS/FAIL
verification per `agent_roles.negative_tester`.

## Implications

- The prototype makes the four scattered waiver surfaces
  (quality gate / AOM / Evidence Ref / golden CLI matrix) readable
  at a single point, without altering any of them.
- Any future waiver runtime extraction task has an explicit
  contract source plus an explicit non-authorization surface; any
  future lifecycle that violates a recorded boundary becomes
  immediately visible by diff against the prototype JSON
  `non_authorization` block.
- The prototype lives under `artifacts/governance/prototypes/`
  (the same parent directory as the Evidence Ref prototype
  delivered by TASK-1033), keeping it out of the runner load path
  and consistent with the v3.5.x prototype convention.
- The prototype's `existing_waiver_semantics_inventory` field
  preserves byte-level references to the four committed sources;
  any future runtime extraction must rerun the inventory and
  confirm each source's value is still observable.

## Expiry

Prototype reflects state at HEAD `27a31ff` (TASK-1038 closure
snapshot commit). Prototype is not invalidated by future commits
but a future prototype task may produce a refined registry under a
later `schema_version`.
