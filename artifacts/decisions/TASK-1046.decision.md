## Scope

Two coupled decisions: (1) rename the project from `Consilium Fabri` / `consilium-fabri` to `Council Forge` / `council-forge` across forward-facing surfaces; (2) rename the source-template sentinel from `.consilium-source-repo` to `.council-forge-source-repo` (path α) with lockstep validator update.

## Issue

User decided to rename the project. The old name appears in 200+ files across active forward-facing surfaces, the source-template sentinel, and historical TASK-952..TASK-1045 lifecycle artifacts. A choice is required between α (rename sentinel for naming consistency, accepting validator code change risk) and β (keep sentinel as historical name, accept project name and sentinel filename divergence). User chose α. A second choice is required between updating every committed historical artifact (high churn, breaks immutability) and preserving them (clean immutability, accept that the old name remains in historical record). Implicit consensus: preserve historical artifacts.

## Options Considered

### Option α (chosen): rename sentinel + preserve historical artifacts

Rename `.consilium-source-repo` → `.council-forge-source-repo` and update every active reference (validator, orchestration doc, CLAUDE.md). Preserve every committed TASK-* artifact and historical governance plan filename byte-identically.

### Option β: keep sentinel `.consilium-source-repo`, only rewrite display surfaces

Reject. Sentinel stays as historical name divorced from the new project identity. Lower risk but creates a permanent naming inconsistency that confuses every future reader.

### Option γ: rename sentinel and rewrite historical artifacts

Reject. Rewriting committed governance evidence (TASK-952..TASK-1045 lifecycle and their `governance-*-closure-snapshot.v3.5.x.md` / `governance-repair-manifest.v3.x.json` deliverables) destroys the immutability principle that the artifact-first workflow depends on. Future audits would not be able to verify what was actually committed at HEAD `0a6fb6f` or earlier.

## Chosen Option

Option α — rename sentinel, preserve historical artifacts.

## Reasoning

- Preserving historical artifacts is a hard rule of the artifact-first workflow (see `docs/orchestration.md` §2.2: "以最新且合法狀態的 artifact 為準" — and historical artifacts at their commit time are exactly the latest legal state at that point).
- Sentinel rename is a small surface (1 file rename + ~3 reference updates in validator and 2 docs). Keeping the old sentinel name (β) trades 5 minutes of work for permanent confusion.
- Preserving the historical governance plan filenames at repo root (`consilium-fabri-governance-repair-plan-v3.4.md` and `-v3.5.md`) is consistent with treating those plans as snapshot-named at their authoring time. Future v3.6+ plans will use the new name.
- GitHub auto-redirect from old URL to new is durable as long as the new repo exists and the old slug stays unused, so all SHA-pinned permalinks in research artifacts continue to resolve.

## Implications

- Future downstream terminal repos that copy `template/` will inherit the new sentinel filename.
- Old downstream repos that have already been cloned will need to sync the renamed validator and sentinel when they next pull from the source template — document in improvement artifact as forward-compatibility note.
- Historical artifacts retain "Consilium Fabri" / "consilium-fabri" as historical record. New artifacts (TASK-1046+) use "Council Forge" / "council-forge".
