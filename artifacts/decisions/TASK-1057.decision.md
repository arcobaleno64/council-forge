## Options Considered

### Option A: 立即移除 -AutoRestore 於兩 wrapper（保守）

- **Pros**: 完全消除破壞性 baseline 誤判；後續 dispatch 之 sub-agent 越界寫入由 user 手動 `git status` + `git restore` 處理。
- **Cons**: TASK-1057 之 Layer A guard 本意（自動還原 sub-agent 越界）失效；user 須改為自行驗證。
- **Risk**: low（保留 detection，移除 enforcement）

### Option B: 修復 -AutoRestore 之 baseline 計算（推薦）

於 dispatch **前** snapshot 既有之「未 commit 之 working tree state」（含 M-marker tracked 檔 + untracked 檔），dispatch **後** 比對 detect 真正 sub-agent 寫入之 delta，僅 restore / delete 該 delta；既有 user state 完全保留。

具體 mechanism：
- Dispatch 前：`git stash push -u -m "TASK-1057 pre-dispatch <timestamp>"`（含 untracked），紀錄 stash ref
- Dispatch 中：sub-agent 在 clean working tree 上操作（dispatched edits 為 working tree only）
- Dispatch 後：`git diff HEAD --stat` 列出所有 sub-agent 之變動 → 與 `-AllowedPaths` 比對
- 違規時：`git checkout HEAD --` + `git clean -fd` 對 **僅違規 paths**
- 結束：`git stash pop` 恢復 user pre-dispatch state（合併 sub-agent 之合法輸出）

- **Pros**: 保留 Layer A guard 本意；user state 安全；deterministic baseline。
- **Cons**: stash pop 在 sub-agent 寫入 user M 檔之路徑時可能 conflict（須額外 conflict-resolution path）；複雜度上升。
- **Risk**: medium（stash + pop 流程於極端情境可能 fail；須 fallback 至「skip restore + 人工驗證」之降級路徑）

### Option C: TASK-1057 wrapper 全面 deprecate

開新 task 設計新一代 sandboxed dispatch（如 git worktree-based 隔離 / docker container），完全不在 user 之 working tree 操作。

- **Pros**: 根因消除；sandbox 隔離為產業標準。
- **Cons**: 工程量大；TASK-1057 全廢；現有所有 dispatch wrapper 須 migrate；user 已建之 alias / slash command / CI 全變動。
- **Risk**: high（scope 過大）

## Chosen Option

**Option B**，並追加保守降級層：

1. 立即（緊急）：對兩 wrapper 加 `-DisableAutoRestore` flag 或 default 改為 `-AutoRestore $false`，user 須顯式啟用；待 Option B 完整修復前，本對話與後續 session 不再以 `-AutoRestore` 模式 dispatch。
2. 中期：開立 **TASK-1059** 實作 Option B 之 stash-based baseline + 降級路徑。
3. 紀錄：本 decision + auto-memory 沉澱事故脈絡，供跨 session 追溯。
4. 不做：不立即重寫 TASK-1057 之 verify artifact 為 fail（屬歷史紀錄；本 decision 即為 follow-up 紀錄載體）。

## Reasoning

- **為何不選 A**：移除 enforcement 等於放棄 TASK-1057 之核心功能；user 已 invest TASK-1057 之 wrapper code + slash command 整合；保留 Layer A 但修正 baseline 為更小代價。
- **為何不選 C**：sandbox 隔離為長期目標但本 incident 之緊急性要求短期內可用之修復；TASK-1059 完成 Option B 後，C 仍可作為 TASK-10xx 長期 roadmap。
- **為何選 B**：根因為 baseline 計算錯誤（diff against HEAD 而非 dispatch-pre-state），最小修復範圍即可消除破壞性；stash 為 git 之原生機制，無需引入新工具。
- **為何加保守降級層**：在 Option B 落地前，wrapper 仍 unsafe；must default 改為 `-AutoRestore $false` 防止對話中誤觸；本對話不再以該 mode dispatch。
