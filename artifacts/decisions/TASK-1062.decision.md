## Issue

Plan §Risks §R2 之 mitigation 觸發。Coding first-edit micro-smoke 階段以 `gemini --help` 直接驗證 Gemini CLI 之 stdin 接收語意（per `artifacts/research/TASK-1062.research.md` §UNVERIFIED）：

```
Gemini CLI - Defaults to interactive mode. Use -p/--prompt for non-interactive (headless) mode.
  -p, --prompt   Run in non-interactive (headless) mode with the given prompt. Appended to input on stdin (if any).
```

關鍵語意：(a) 不給 `-p` flag 不進 non-interactive mode；(b) 給 `-p` 時 stdin 內容會被 appended 至 prompt。意思是：plan §Scope 假設之「Gemini wrapper 移除 `-p` 改 stdin pipe」**不成立** —— 移除 `-p` → gemini 進 interactive mode → wrapper sub-process 永遠 hang 等 user input。

**設計衝擊**：plan §Scope 之 Gemini wrapper Bug B fix 路徑（純 stdin pipe 取代 `-p`）不可行；本 task §AC-3 之 Gemini 半邊（`artifacts/scripts/Invoke-GeminiAgent.ps1` 之 stdin cutover）需要重新設計 — 但此重新設計屬上游 CLI 行為調適，超出本 task 之原始 scope（per task §Background §Bug B 起源即明示「Gemini wrapper 同邏輯但因 gemini.cmd 之解析路徑稍異，未必同樣失效」，task §AC-3 之假設前提即未經實測）。

## Options Considered

- **Option B — 在本 task 內實測 + 延伸**：當前 session 跑 Gemini wrapper 之 multiline `-p` 實測（`gemini -m gemini-3.1-flash-lite-preview --approval-mode=yolo -p "[ROLE]`nline2`nline3"`）；若不踩 Bug B → 不修 Gemini Bug B（task §AC-3 縮 scope）；若踩 → 本 task 內研究替代修法（如 temp file path、process arg escape）。代價：增加實測 + 設計時間，可能耗 Gemini quota + Bug-B1 fabrication 風險（per `memory/feedback_wrapper_known_bugs.md`），且若實測失敗仍需建 decision 延期。
