## Issue

FB-1 (from TASK-1087 CP-4 re-review of TASK-980): `repo_security_scan.py` was FAIL-OPEN — an
unreadable in-scope file silently left coverage (read_text returned None → callers `continue`)
and a nonexistent `--root` exited 0; both could present an incomplete scan as "clean". Make
scan-coverage failures fail-closed (TASK-1079 discipline) without breaking deliberate non-text
skips (oversize/binary).

## Options
- Option A: Only harden read_text (OSError → raise) + bad-root.
- Option B: Harden the WHOLE coverage path fail-closed (traversal, stat, read, root-resolve, all 3 commands), keep oversize/binary as deliberate-but-VISIBLE skips, and prove it with adversarial dual review.

## Chosen Option
**Option B**

## Reasoning

The plan + implementation dual reviews showed Option A leaves fail-open holes (pre-read
traversal/stat). A security scanner's "clean" must mean "fully covered", so every I/O failure
on an in-scope file fails closed; only deliberate non-text scope limits (oversize / NUL-binary)
remain skips, and even those are surfaced for auditability.
