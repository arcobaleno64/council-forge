## Issue

FB-2 (from TASK-1087 CP-4 re-review of TASK-963): publish-release.ps1 created a GitHub release
with NO release-integrity / release-signing verification — out of step with P8-D2 (release_gate /
snapshot_manifest) and P8-D3 (gpg detached-signature). Couple both to the preflight, fail-closed,
mirroring the CI release-integrity job's proven pattern, without breaking the operator-gated
bootstrap (signing is deliberately not provisioned in this repo per docs/security/release-signing.md).

## Options
- Option A: Add only the release_gate structural gate.
- Option B: Couple the FULL CI integrity (snapshot_manifest verify + release_gate) + the gpg signing-triad verification (armed-vs-unprovisioned, exact-fingerprint binding), fail-closed, with unprovisioned defaulting to fail-closed and an explicit `-AllowUnsigned` opt-in.

## Chosen Option
**Option B**

## Reasoning

The plan dual-review showed Option A under-mirrors CI (a stale-but-structurally-valid manifest
passes release_gate but fails snapshot_manifest verify) and leaves signing unverified. Option B
mirrors the CI release-integrity job (itself hardened by a prior codex impl-review), so a local
publish is held to the same bar as CI. Unprovisioned signing fails closed by default (no accidental
unsigned publish); `-AllowUnsigned` is the explicit, loudly-logged operator opt-in for the
documented operator-gated bootstrap; an ARMED-but-incomplete/invalid signature is never overridable.
