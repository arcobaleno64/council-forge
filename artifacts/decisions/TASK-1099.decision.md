## Issue

TASK-1001（Governance Lens Explicitization，v3.4 多階段任務）之實質 obligation 已全竣——canonical AC 經 **TASK-1011** reconcile、AC-5b 經 **TASK-1095** resolved，decision §Verified AC Summary 全 AC 有 evidence。然 TASK-1001 本身僅存 task/decision/status/verify、**無 plan/code**，致 docs-spec/mvp 之 `done` computed-required=[task,plan,verify,status] **機械上不可達**（缺 plan）。如何予其一**形式化、誠實之 terminal disposition**，而**不捏造**歷史 artifact、**不弱化** done-gate 對一般任務之完整性？

## Options Considered

- **A — guard 認可 reconciled-terminal done**：教 `guard_status_validator.py` 識別 `superseded_by`+`reconciliation_ref`+successor-done+全-AC-evidence，放寬 done-required 略去其從未擁有之 plan/code。research 揭：guard **全然不讀** superseded_by/reconciliation_ref（即此為**新增能力**非微調）；**blast radius N=1**（唯 TASK-1001）→ 為單例增通用 workflow-integrity 能力涉過度設計（[[avoid-over-layering]]）＋改 guard 碼風險（EXACT_SYNC、負向測、實作層雙審）。
- **B — 合法重建 TASK-1001 plan**：補一 plan artifact 以滿 plan-required。research 揭：**無獨立非捏造之源**——TASK-1001 之規劃實由 `TASK-1011.plan.md` 承載，重建獨立 v3.4 plan 即虛構歷史設計。**違「不捏造」紅線 → 否決**。
- **C — 明定 superseded-via-reconciliation terminal（route 2）**：於 `docs/workflow_state_machine.md` 明定此為 `blocked` sink 之一獲認可終態 disposition；不改 guard、不捏造、不 flip done。TASK-1001 維 `blocked`，語意由「卡住待解」校為「已 reconciled 之認可終態」。

## Chosen Option

**C（route 2）**——主公 2026-06-13 裁定。落實：`docs/workflow_state_machine.md` §5.1 明定 `blocked` 之二 disposition〔(a) stuck-awaiting-resolution〔Gate-E 出〕／(b) superseded-via-reconciliation terminal〔三條件識別之認可終態、無 exit/resume、Gate-E N/A〕〕；TASK-1001 decision/status/verify 校正為此終態。

## Reasoning

- **最輕且誠實**：C 零 guard 變更、零捏造；TASK-1001 形式上不偽稱 done（其本即被 supersede、非自身走完 lifecycle），以「superseded-terminal」誠實終結。
- **A 對 N=1 過度設計**：guard 從不讀 superseded/reconciliation 二鍵，為單一任務增通用 workflow-integrity 能力＋負向測＋實作層雙審，成本與風險不稱（[[avoid-over-layering]]）；其補既有 schema 盲視之論可成立，然宜俟 N>1 或主公另命時為之（列 Follow Up）。
- **B 觸紅線**：無真源、重建即捏造（[[machine-green-not-quality-met]] 之反面——不得為達機械 done 而造假）。
- **done-gate 不弱化**：C 之 (b) 別為**文件性、非 guard-enforced**（guard 仍以 blocked 驗、不讀二鍵）；識別三條件嚴格；明載一般 stuck 任務不得藉此繞 Gate-E。故未開實際逃逸口。
- **雙審佐證**：plan-gate codex r1/r2 累揪 AC-1（須本 decision）＋AC-5（TASK-1001 verify 一致性）缺漏，r3 APPROVE；唯餘 non-blocking（blocked 語意輕度 overload，已以嚴格識別＋documentary 界涵之）。

## Implications

- `docs/workflow_state_machine.md`（+template EXACT_SYNC）新增 §5.1，為長存之 workflow policy（非 TASK-1001 專屬）。
- TASK-1001 維 `state=blocked`，惟 decision/status/verify 皆校為「superseded-via-reconciliation terminal」；不需 Gate-E（無工作可 resume）。
- guard_status_validator.py **不變**——TASK-1001 續以 blocked 驗（guard-clean）；terminal 性為文件+review 認定。
- 今適用者唯 TASK-1001（N=1）；他歷史 blocked task 若擬套用須個案核三條件。
