2. **Dispatch 設定失誤**：Claude 於 dispatch 時未將 5 個 lifecycle artifact 路徑（`artifacts/{status,code,decisions,test,verify}/TASK-1110.*`）納入 `-AllowedPaths`，誤以為 CODEX.md 之 lifecycle 豁免會被 wrapper 自動套用。實際上 wrapper 之 post-dispatch write-scope guard（`-AutoRestore`）不具此豁免邏輯，將 Codex 已產出之 4 份草稿 artifact（`code.md`/`decision.md`/`test.md`/`verify.md`）判定為越界寫入並刪除；`status.json`（既有已 commit 檔案）亦被誤刪，但可用 `git checkout --` 復原且已復原。
3. **R5 裁決缺口**：plan R5 要求 `DISALLOWED_GEMINI_FRAGMENTS` 之去留須記錄理由於 decision artifact；Codex 之 diff 已實作移除該清單，但原本要記錄理由的 decision artifact 正是被誤刪的那 4 份之一，理由需要在此重建記錄。

## Options Considered

1. **等待 Codex credits 回充後重新 dispatch，交由 Codex 完成收尾 artifact 撰寫並 commit**：符合預設分工慣例（Coding 由 Codex 全責，含收尾）；缺點是實際程式碼已完成且已由 Claude 獨立驗證正確（validator + PR-case + pytest + 端對端真實呼叫），重新 dispatch 只是為了補寫已知內容的摘要文件，時間成本與 credits 成本皆不合理；且無法預期 credits 何時回充。
2. **由 Claude 直接撰寫 4 份收尾 artifact 並 commit**：程式碼本身完全未變動（不算 Claude 自行實作），Claude 僅記錄已完成且已獨立驗證之事實；缺點是 Execution Profile 之 provenance 需誠實記錄「執行者為 Codex、收尾撰寫者為 Claude」之混合情形，不能含糊帶過。
