## What Actually Happened

The audit's substantive work took ~5 seconds (two `python -c` invocations); the lifecycle artifact authoring took longer than the actual evidence collection. The audit findings cleanly bounded TASK-1045's scope to validator + schema-doc changes only.

## Steps That Felt Redundant

Authoring task / code / verify / status as four separate files for a 5-second audit is heavyweight. Future audit-only tasks could fold into a single combined artifact (or be subsumed into the requesting task's research artifact).

## Error-Prone Steps

The cp950 mojibake stdout from H2 grep on README.zh-TW.md / OBSIDIAN.md initially looked like file content corruption; the recovery (compare H2 list lengths and byte-equality directly in Python str space) is the correct approach but had to be discovered in-conversation rather than being a default audit instinct.

## Surprises / Mismatches

The validator's mojibake-rendered output was a Windows terminal codepage artefact, not a real file encoding issue. Always compare bytes/lengths in Python rather than trusting visual stdout when handling non-ASCII content.

## Template / Workflow Fix Candidates

- Document the "audit using Python in-place sha256 + H2 list equality, never trust mojibake stdout" rule in `docs/orchestration.md` or a new lightweight audit recipe under `docs/lightweight_mode_rules.md`.

## Next Time Default

For sync-contract audit questions, run the TASK-1044 two-line script before any other discovery work; trust Python str equality over terminal stdout for non-ASCII content.
