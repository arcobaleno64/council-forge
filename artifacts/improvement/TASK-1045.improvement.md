## 1. What Happened

User asked for "complete review and sync of all related MD files, especially README". Initial validator runs surfaced 30+ failures concentrated in TASK-1025 verify, TASK-1032..1036 verify (multi-paragraph evidence), and TASK-1037..1043 task + decision (v2 governance format). Workflow MD itself was already in sync. Path β (schema/validator evolution to absorb v2 practice) was selected over path α (artifact rewrites) and path γ (decision waivers). Implementation extended `MARKERS` to tuple-of-alternatives with line-anchored regex match (R1 mitigation), added `is_governance_decision_class` predicate with empty-subclass guard (R2 mitigation), rewrote `parse_verify_checklist_items` with AC-N item-start splitter and v1 fallback (R3 mitigation), and mirrored every Tier 1 change to `template/` byte-identically with SHA-256 verification (R4 mitigation).

## 2. Why It Was Not Prevented

The schema divergence between `docs/artifact_schema.md` v1 and the v2 governance practice that emerged across TASK-1037..TASK-1043 was an architectural drift that was not flagged by validators because each new v2 artifact passed local self-checks but failed the cross-task `guard_contract_validator.py` aggregate run. No prior gate forced a "v2 schema is being introduced — update artifact_schema.md and validators in lockstep" guardrail.

## 3. Failure Classification

Premortem failure (no risk had been pre-registered against schema drift between authored artifacts and the documented schema; the v2 evolution proceeded incrementally without a guardrail that required `artifact_schema.md` § extension whenever a new H2 / Decision Class / Expiry form was introduced).

## 4. Corrective Action (Immediate)

Implemented β path: validator now accepts v1 ∪ v2 markers additively; `governance-*` Decision Class family recognised; multi-paragraph evidence parser uses AC-N item-start boundary; docs-spec adapter releases `code` requirement; `docs/artifact_schema.md` §5.13 documents all v2 alternatives so future readers can trace which form is acceptable. All 14 historical failures cleared; 0 v1 regression.

## 5. Preventive Action (System Level)

- Workflow rule: any future task that introduces a new artifact heading, frontmatter key, Decision Class subclass, or checklist parser convention MUST update `docs/artifact_schema.md` (§5 family) in the same commit and mirror to `template/docs/artifact_schema.md`. Promote this from convention to a guard check by extending `guard_contract_validator.py` to detect new MARKERS / DECISION_CLASSES values introduced without a corresponding §5 documentation hit.
- Validator rule: marker checks MUST use line-anchored regex (`^MARKER(\s|$)` for colon-tail; `^MARKER\s*$` for pure heading). Substring `in` checks are reserved for non-heading markers. This is now enforced inside `_marker_present`; future edits to `MARKERS` should not regress to the simple `m in text` form.
- Adapter rule: when an adapter drops an artifact-type requirement (e.g. docs-spec dropping code), the rationale MUST be documented in `docs/artifact_schema.md` §5.1 Adapter section so downstream authors know what the relaxed surface accepts.

## What Actually Happened

The user posed an open-ended sync request; the conversation first ran validators to discover the actual drift (workflow MD intact; artifacts non-compliant). Path α/β/γ presentation forced a schema-evolution decision rather than an arbitrary repair. β was selected; implementation proceeded with self-test loops between every change, catching three layered issues (decision marker headlines, plan v2 format, AC-inline criterion + multi-field same-line packing) progressively rather than upfront.

## Steps That Felt Redundant

Two: (1) initial separate authoring of TASK-1044 lifecycle for an audit that was conceptually research-for-TASK-1045; could have folded the audit into TASK-1045's research artifact and saved one full set of lifecycle files. (2) Repeated source-line URL formatting iterations for TASK-1045.research.md (period-vs-no-period, URL pattern strictness) before the source pattern was matched.

## Error-Prone Steps

- Marker substring vs line-anchor distinction: `## Decision` vs `## Decision Class` was a near-miss false positive; line anchoring fixes this and now must remain.
- AC-inline-light verify items: `method` / `evidence` requirement relaxation is permissive; future schema audits should re-evaluate whether evidence anchoring should still be required at the criterion-text level.

## Surprises / Mismatches

- The v2 governance format had been live since TASK-1037 (5+ commits) without anyone updating `docs/artifact_schema.md`; the validator silently accumulated 30+ failures while local task-by-task self-checks all passed. Cross-task aggregate validation surfaced the divergence only when explicitly run.
- `docs-spec` adapter previously dropped only `test`; extending it to drop `code` aligns with the v2 governance attestation pattern but changes the contract surface for any pre-existing v1 docs-spec task. None regressed in the present sweep, but the broader downstream impact deserves attention.

## Template / Workflow Fix Candidates

- Add a guard validator check that verifies every `DECISION_CLASSES` constant or every `MARKERS` entry has a corresponding §5 documentation hit; flag drift at PR time rather than at lifecycle aggregate runs.
- Extend prompt regression cases to cover v2 governance Decision Class acceptance and v2 plan format detection so any future regression of `_is_v2_plan` or `is_governance_decision_class` is caught by a fixed case.

## Next Time Default

Whenever a v2-style heading, frontmatter, or subclass is first written into a governance artifact, also update `docs/artifact_schema.md` §5 in the same commit and run `guard_contract_validator.py` end-to-end before the commit lands. Don't let practice drift past schema by more than one task.
