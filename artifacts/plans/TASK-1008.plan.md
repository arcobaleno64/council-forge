## Proposed Changes

### 1. workflow_constants.py — 新增 strict/legacy 函數

在 `normalize_assurance_level` 之後插入：

**`validate_assurance_level_strict(value: str) -> str`**
- 若 value 為空 → raise `ValueError`（explicit schema error）
- 若 value 不在 `ASSURANCE_LEVELS` → raise `ValueError`（explicit schema error）
- 否則 → return normalized value

**`warn_and_default_assurance_level(value: str) -> tuple`**
- 若 value 已在 `ASSURANCE_LEVELS` → return `(value, {})`（empty warning dict）
- 否則 → return `(DEFAULT_ASSURANCE_LEVEL, {defaulted_from, selected_default, migration_debt})`
- 禁止在任何 silent fallback 路徑隱式呼叫此函數。

### 2. guard_status_validator.py — 三項變更

**Import**：將 `validate_assurance_level_strict`、`warn_and_default_assurance_level` 加入 workflow_constants import。

**validate_status_schema（assurance 欄位）**：
- 原：missing assurance_level → warning（warning + silent default）
- 新：missing assurance_level → **error**（explicit schema error，no silent default）
- 原：invalid value → error（已有）
- 新：error message 強化，明確說明 unknown assurance_level 為 schema error，並說明 legacy mode 路徑。

**validate_markdown_artifact（task type）**：
- 在 `elif artifact_type == "task":` 區塊加入 `_raw_task_assurance` 擷取。
- 原：missing `## Assurance Level` → warning
- 新：missing `## Assurance Level` → **error**（必須明確宣告）
- 原：`if assurance_level not in ASSURANCE_LEVELS` → dead check（normalize_assurance_level 永遠返回合法值）
- 新：`elif _raw_task_assurance` → 檢查原始值（在 normalize 之前）是否合法；例如 "high" → error。
- 新增：mismatch check — 若 task.md 的 assurance 與 status.json 的 assurance 不一致 → error。

### 3. docs/artifact_schema.md — 新增 §5.11
