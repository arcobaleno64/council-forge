## Proposed Changes

### 1. red-team-adversarial-cases.v3.4.json 設計

每個 case 包含以下結構化欄位：
- `case_id`（例：RT-PATH-001）
- `title`
- `category`（對應 v3.4 plan §4.2a case 類別）
- `attack_surface`
- `precondition`（前置條件，說明 case 在何種系統狀態下才有效）
- `attack_steps`（≥ 2 步，跨多個 artifacts 或控制層）
- `expected_detection`（應由哪個控制層偵測）
- `expected_detection_layer`（技術層級說明）
- `expected_result`（BLOCKED 或 ESCALATED）
- `expected_outcome`（BLOCKED 或 ESCALATED，與 expected_result 等值，供 Prompt 6e runner 使用）
- `target_control`（對應 guard 的哪個控制）
- `related_finding`（對應 v3.4 threat findings，例 FIND-18）
- `regression_candidate`（bool，Prompt 6e 是否應提升為 regression）
- `execution_phase`（Prompt 6e 執行時期）
- `not_a_unit_test_reason`（明確說明為何不是 unit test 的重複）

## Risks

- R1: Risk: case 設計與 Prompt 2 unit tests 語意重疊，無法通過 Prompt 6e 的去重檢查。
  Trigger: attack_steps 只有單一 artifact、單一 control layer。
  Detection: not_a_unit_test_reason 欄位明確說明；Prompt 6e 執行時 cross-check by case_id + attack_surface。
  Mitigation: 每個 case 要求 attack_steps >= 2 且跨 artifacts；在 not_a_unit_test_reason 明確列出 Prompt 2 unit test 的不同之處。
  Severity: non-blocking

- R2: Risk: case registry JSON 欄位缺漏，導致 Prompt 6e runner 解析失敗。
  Trigger: 欄位命名與 Prompt 6e 預期不一致。
  Detection: AC-2/3 驗收；json.loads 成功但 assertion error on required fields。
  Mitigation: 每個 case 包含兩套等值欄位（例：expected_result + expected_outcome）；schema_version 明確標注 v3.4。Prompt 6e 可調整 runner 而不需回改此 registry。
  Severity: non-blocking

- R3: Risk: 建立超出 TASK-1022 授權範圍的檔案（例如意外觸及 scripts 或 template）。
  Trigger: 操作失誤。
  Detection: AC-4（git diff --name-only HEAD 範圍檢查）。
  Mitigation: 明確在每個 artifact 建立前確認路徑；不執行任何修改 scripts 的命令。
  Severity: blocking

- R4: Risk: code artifact 不符合 validator 對 done state 的要求（需含 code artifact）。
  Trigger: validator 強制要求 code artifact 存在於 done state。
  Detection: guard_status_validator.py --task-id TASK-1022 fails with missing code artifact。
  Mitigation: 建立 design-only stub（TASK-1022.code.md），明確標注 no-runtime-code；符合 done state 的 STATE_REQUIRED_ARTIFACTS。
  Severity: blocking
