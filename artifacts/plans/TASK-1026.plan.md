## Risks

R1
- Risk: PCACC runner 對 TASK-1026 自身 self-check 失敗（如 PCACC-002 因 Evidence Refs 中含 `commit ` 字面或 HEAD 引用被誤判為 malformed），導致 self-check overall_status=fail，阻止 commit
- Trigger: parse_evidence_refs() 對非 repo-relative path 但合法的特殊 token（如「HEAD at TASK-1026 start: <sha>」、「commit a40f6bc」）之分類規則未涵蓋；或 verify artifact 之 Evidence Refs 含 markdown link `[label](path)` 未 strip 至純 path
- Detection: self-check 結果中 PCACC-002 之 status=`fail`、reason_code 含 `malformed_refs:` 或 `missing_paths:`
- Mitigation: parse_evidence_refs() 顯式處理 `[label](path)` link、HEAD / commit prefix；verify artifact 之 Evidence Refs 採純 repo-relative path 形式（不貼絕對路徑、不貼 URL、HEAD / commit hash 用獨立行 + 顯式 prefix `HEAD at task start:` 或 `commit `）；self-check fail 時立即修整 verify artifact 之 Evidence Refs 直至 PCACC-002 pass
- Severity: blocking

R2
- Risk: PCACC-004 因 review_timestamp 與 evidence_generated_at 比對誤判（如 verify last_updated 寫入時刻早於 self-check 執行時刻），致 self-check fail
- Trigger: 寫 verify artifact 時 timestamp 用先前 phase 之預估值；或 self-check 在 verify 寫入後才跑致 evidence ts > review ts；或時區轉換不一致
- Detection: PCACC-004 之 actual 顯示 `review_ts < evidence_ts` 或 equal，status=fail
- Mitigation: 嚴格依序 — Phase 4 先跑 self-check（產生 evidence file with generated_at=T1），Phase 5 verify last_updated 與 status last_updated 用 T2 > T1；status.last_updated 在 Phase 5 末更新一次，T2 取 self-check 完成後且 verify 寫入完成後之 wall-clock；若 fail，重寫 status.last_updated 至 self-check generated_at + ≥1 秒，並重跑 self-check 確認 review > evidence
- Severity: blocking

R3
- Risk: TASK-1026 lifecycle 過程中無意建立 TASK-1027 之任一 artifact，違反 non-authorization 條款
- Trigger: 撰寫 plan / decision 中關於 Artifact Obligation Matrix 章節時誤把段落內容存入 `artifacts/tasks/TASK-1027.task.md` / `TASK-1027.*.md`

R4

- Trigger: Windows git autocrlf 對新檔之處理在 root 與 template 差異；或 `cp` 命令未保留 mtime/permission；或編輯器在不同檔以不同 line ending 寫入
