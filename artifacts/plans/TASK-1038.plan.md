## Risks

### R1: Snapshot misrepresents prior closure status

The snapshot reads from committed status / verify artifacts and from
the human-provided closure state. If the snapshot fabricates a state
not present in committed artifacts, it pollutes the governance map.

- **Risk**: snapshot claims a status (e.g. `closed_verified_after_repair`) for a version where no committed evidence supports it
- **Trigger**: writing the snapshot from intuition rather than from `artifacts/status/TASK-103[5-7].status.json` and the TASK-1037 verify
- **Detection**: inspection evidence cross-checks `closure_status[*].status` and `task_groups[*].status` against committed artifacts; pre-commit `git status` shows no modification of prior task artifacts
- **Mitigation**: the snapshot uses only `closed_verified` and `closed_verified_after_repair`; only v3.5.5 is allowed `closed_verified_after_repair` because TASK-1037 status records `repair_result=pass`; everything else is `closed_verified`
- **Severity**: blocking

### R2: Snapshot accidentally authorizes future scope

A misworded snapshot could read as authorization for TASK-1039+,
runtime registry expansion, validator split, PCACC-005, or
AC-to-verify activation.

- **Risk**: snapshot lists candidate lifecycles without an explicit `authorized=false`, allowing readers to interpret the snapshot as license to start them
- **Trigger**: writing candidate lists in narrative form without the non-authorization gate
- **Detection**: inspection evidence checks every `next_candidate_lifecycles[*].authorized` field is literal `false`; snapshot markdown §8.8 explicitly states the non-authorization boundary; closure index `non_authorization` carries `false` for every required key
- **Mitigation**: snapshot §8.9 prefixes every candidate with `non-authorized candidate`; closure index `next_candidate_lifecycles[*].authorized=false`; closure index `non_authorization.*_authorized=false`
- **Severity**: blocking

### R3: TASK-1039+ artifact accidentally created

A typo or path slip could create
`artifacts/{tasks,plans,decisions,verify,status}/TASK-1039*` or a
candidate-numbered TASK-1040..TASK-1043 lifecycle artifact.

- **Risk**: candidate task lifecycle is unintentionally created during snapshot writing
- **Trigger**: copy/paste of candidate task IDs into a path
- **Detection**: pre-commit `git diff --cached --name-only` is checked against the TASK-1038 allowed list; `git status --short` is inspected for any TASK-103[9]* or TASK-104* path
- **Mitigation**: every candidate id appears in the snapshot only as a string under `next_candidate_lifecycles`; no path under `artifacts/{tasks,plans,decisions,verify,status}/` is created for candidate ids
- **Severity**: blocking

### R4: Unrelated working-tree noise leaks into commit

`.obsidian/`, `.omc/`, `.tmp/`, `.pytest-basetemp/`, and
`__pycache__/` are known non-blocking local noise. A wide `git add`
would stage them.

- **Risk**: unrelated state is committed alongside TASK-1038 artifacts
- **Trigger**: `git add -A` or `git add .`
- **Detection**: pre-commit `git diff --cached --name-only` is compared against the TASK-1038 allowed list
- **Mitigation**: stage files individually by path; verify `git diff --cached --name-only` matches exactly the TASK-1038 allowed list before commit
- **Severity**: non-blocking

Cause: writing closure status from memory or intuition rather than
from committed evidence.

Mitigation: every closure-status field is sourced from
`artifacts/status/TASK-103[5-7].status.json` (`state=done`,
`verify_result=pass`) or from the TASK-1037 status `repair_result=pass`

the source status artifact paths.

Cause: omitting the `authorized=false` gate on candidate lifecycles.

Mitigation: schema requires `authorized` field on every candidate;
inspection evidence asserts each is literal `false`.

Detection: inspection check `next-candidates-non-authorized` enumerates
the candidate list and reports `actual=false` per entry.

Mitigation: snapshot writes only into `artifacts/governance/`,
`artifacts/verify/TASK-1038/`, and the five TASK-1038 lifecycle paths;
no path under `artifacts/{tasks,plans,decisions,verify,status}/` for
TASK-1039+.

Detection: pre-commit `git diff --cached --name-only` and
`git status --short` are inspected for any TASK-103[9]* or TASK-104*
path.

### R4 (commit noise)

Cause: wide `git add`.

Mitigation: stage by exact path; never `git add -A` / `.`.

Detection: pre-commit staged-set inspection.
