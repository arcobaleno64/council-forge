## Risks

### R1: Prototype is misread as runtime authorization

A misworded prototype JSON or design note could read as
authorization for the PCACC runner / quality gate runner / a future
validator to consume the waiver registry directly.

- **Risk**: prototype field naming or design-note prose suggests the
  registry is already consumed by a runtime, leading downstream
  agents to wire it into runners under the same lifecycle
- **Trigger**: writing the JSON without `prototype_status=design_only`
  + `runtime_consumption_authorized=false` at the top, or omitting
  the explicit non_authorization block
- **Detection**: inspection evidence asserts
  `prototype_status=design_only`,
  `runtime_consumption_authorized=false`, and that
  `non_authorization.runtime_consumption_authorized=false`,
  `non_authorization.production_runner_modification_authorized=false`,
  `non_authorization.production_validator_modification_authorized=false`,
  `non_authorization.production_policy_modification_authorized=false`,
  `non_authorization.new_test_implementation_authorized=false`,
  `non_authorization.validator_split_authorized=false`,
  `non_authorization.task_1040_plus_authorized=false`
- **Mitigation**: every top-level field that touches runtime
  semantics is paired with an explicit `false` flag; the design
  note §1 / §16 repeats the non-authorization in prose; the
  prototype lives under `artifacts/governance/prototypes/`, not
  under `artifacts/governance/`
- **Severity**: blocking

### R2: Prototype contradicts existing waiver semantics

The prototype could disagree with
`quality-gate-policy.v3.5.json#waiver_policy.schema.required_fields`
(six fields) or with
`artifact-obligation-matrix.v3.5.json#waiver_policy.required_waiver_fields`
(six fields) or with the GCLI-QUALITY-SYNC reason_code surface
(`waivered_until:<date>`, `waiver_invalid:expired:<date>`).

- **Risk**: prototype declares `expires_at` optional or accepts a
  reason_code that the existing policies reject
- **Trigger**: drafting the schema from intuition rather than from
  the four committed source artifacts
- **Detection**: inspection evidence cross-checks each required
  field is present in `waiver_schema.required_fields`; design note
  §3 cites the four source paths; prototype JSON
  `existing_waiver_semantics_inventory` carries each source path
- **Mitigation**: the prototype's required field list is the union
  of the existing policies plus the necessary lifecycle metadata
  (`waiver_id`, `created_by_task`, `created_at`, `status`); the
  prototype's reason_code surface preserves the
  `waivered_until:<date>` and `waiver_invalid:expired:<date>` shapes
  observed in `golden-cli-coverage-matrix.v3.5.4.json` (informative,
  not authoritative)
- **Severity**: blocking

### R3: TASK-1040+ artifact accidentally created

A typo or path slip could create
`artifacts/{tasks,plans,decisions,verify,status}/TASK-1040*` (or
later) lifecycle artifacts.

- **Risk**: candidate task lifecycle is unintentionally created
  during prototype writing
- **Trigger**: copy/paste of candidate task IDs into a path
- **Detection**: pre-commit `git diff --cached --name-only` is
  checked against the TASK-1039 allowed list;
  `git status --short` is inspected for any TASK-104* path
- **Mitigation**: every candidate id appears in the prototype only
  as a string under
  `future_runtime_extraction_acceptance_criteria` or design note
  §14; no path under `artifacts/{tasks,plans,decisions,verify,status}/`
  is created for candidate ids
- **Severity**: blocking

### R4: Unrelated working-tree noise leaks into commit

`.obsidian/`, `.omc/`, `.tmp/`, `.pytest-basetemp/`, and
`__pycache__/` are known non-blocking local noise. A wide `git add`
would stage them.

- **Risk**: unrelated state is committed alongside TASK-1039
  artifacts
- **Trigger**: `git add -A` or `git add .`
- **Detection**: pre-commit `git diff --cached --name-only` is
  compared against the TASK-1039 allowed list
- **Mitigation**: stage files individually by path; verify
  `git diff --cached --name-only` matches exactly the TASK-1039
  allowed list before commit
- **Severity**: non-blocking

## Premortem

### R1 (silent runtime authorization)

Cause: omitting the `runtime_consumption_authorized=false` flag or
the `non_authorization` block.

Mitigation: schema requires `prototype_status` and
`runtime_consumption_authorized` at the top; schema requires the
seven mandatory false keys under `non_authorization`; inspection
evidence asserts each is literal `false`.

Detection: inspection check
`runtime-consumption-not-authorized` and
`non-authorization-block-complete` enumerate the values.

### R2 (semantic contradiction with existing policies)

Cause: drafting the schema from memory.

Mitigation: prototype JSON `existing_waiver_semantics_inventory`
records the source artifact path, the source field name, and the
observed value for each waiver semantic; design note §3 cites the
same source paths.

Detection: inspection check
`existing-waiver-semantics-inventoried` enumerates the four source
paths and confirms each is referenced.

### R3 (TASK-1040+ slippage)

Cause: typing a candidate id into an
`artifacts/...TASK-104?.*` path.

Mitigation: prototype writes only into
`artifacts/governance/prototypes/`,
`artifacts/governance/` (single design-note file only),
`artifacts/verify/TASK-1039/`, and the five TASK-1039 lifecycle
paths; no path under
`artifacts/{tasks,plans,decisions,verify,status}/` for TASK-1040+.

Detection: pre-commit `git diff --cached --name-only` and
`git status --short` are inspected for any TASK-104* path.

### R4 (commit noise)

Cause: wide `git add`.

Mitigation: stage by exact path; never `git add -A` / `.`.

Detection: pre-commit staged-set inspection.
