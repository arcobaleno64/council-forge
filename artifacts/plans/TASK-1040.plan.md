## Risks

### R1: Plan is misread as implementation authorization

A misworded plan JSON or markdown could read as authorization for
the quality gate runner / PCACC runner / a future validator to
consume the waiver registry directly under TASK-1040 itself, or as
authorization to execute TASK-1041.

- **Risk**: plan field naming or markdown prose suggests the
  runtime extraction is already authorized
- **Trigger**: writing the JSON without
  `plan_status=planning_only`, `implementation_authorized=false`,
  `runtime_consumption_authorized=false` at the top, or omitting
  the explicit non_authorization block; writing the markdown
  without §4 Non-authorization boundary or §17 Closure conclusion
- **Detection**: inspection evidence asserts the three top-level
  flags are all literal false and that `non_authorization` carries
  every required false key
- **Mitigation**: every top-level field that touches runtime
  semantics is paired with an explicit `false` flag; the markdown
  §4 / §17 repeat the non-authorization in prose; every
  fail-closed matrix row carries `implementation_authorized=false`;
  every golden CLI requirement carries `authorized_now=false`
- **Severity**: blocking

### R2: Plan contradicts the TASK-1039 prototype contract

The plan could disagree with the prototype's
`waiver_schema.required_fields` (10 fields), the prototype's
`waiver_lifecycle_states` (6 states), the prototype's
`expiration_policy`, or the prototype's `validation_semantics` /
`registry_load_failure_reason_codes` (9 codes).

- **Risk**: plan declares a different required-field list, a
  different lifecycle state set, or a different reason_code surface
- **Trigger**: drafting the plan from intuition rather than from
  the committed prototype JSON
- **Detection**: inspection evidence cross-checks each fail-closed
  row's reason_code against the prototype's
  `validation_semantics.registry_load_failure_reason_codes` and
  `reason_code_policy.qc_sync_001_runtime_reason_code_alignment`;
  source_refs lists the prototype JSON path
- **Mitigation**: the plan's fail-closed matrix preserves the
  prototype's reason_code shapes
  (`waiver_registry_missing:<path>`,
  `waiver_registry_malformed_json`,
  `waiver_registry_schema_version_mismatch:<actual>`, etc.); the
  plan's waiver selection model preserves the prototype's
  `select_only_valid_active_unexpired_waivers=true` and
  `wildcard_only_scope_rejected=true` invariants
- **Severity**: blocking

### R3: TASK-1041+ artifact accidentally created

A typo or path slip could create
`artifacts/{tasks,plans,decisions,verify,status}/TASK-1041*` (or
later) lifecycle artifacts.

- **Risk**: candidate task lifecycle is unintentionally created
  during plan writing
- **Trigger**: copy/paste of candidate task IDs into a path
- **Detection**: pre-commit `git diff --cached --name-only` is
  checked against the TASK-1040 allowed list; `git status --short`
  is inspected for any TASK-104{1..9}* path
- **Mitigation**: every candidate id appears in the plan only as a
  string under `future_task_acceptance_criteria` or markdown §15;
  no path under `artifacts/{tasks,plans,decisions,verify,status}/`
  is created for TASK-1041+
- **Severity**: blocking

### R4: Unrelated working-tree noise leaks into commit

`.obsidian/`, `.omc/`, `.tmp/`, `.pytest-basetemp/`, and
`__pycache__/` are known non-blocking local noise. A wide `git add`
would stage them.

- **Risk**: unrelated state is committed alongside TASK-1040
  artifacts
- **Trigger**: `git add -A` or `git add .`
- **Detection**: pre-commit `git diff --cached --name-only` is
  compared against the TASK-1040 allowed list
- **Mitigation**: stage files individually by path; verify
  `git diff --cached --name-only` matches exactly the TASK-1040
  allowed list before commit
- **Severity**: non-blocking
