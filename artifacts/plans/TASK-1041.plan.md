## Goal

Author a decision-only authorization readiness package for a
possible future waiver runtime implementation lifecycle. The
package assesses, against the TASK-1040 runtime extraction plan
(v3.5.8) and its FTC-1..FTC-15 future-task acceptance criteria,
whether the planning context is sufficient to permit a separately
authorized future implementation task. The package records a
single readiness decision plus a future-task implementation
allowlist, hard non-goals, and the seven gates that any future
implementation lifecycle must satisfy. The package does NOT
authorize implementation; even where the readiness decision selects
`ready_for_separate_human_authorization`, a future implementation
task must still be separately and explicitly authorized by the
human maintainer.

## Risks

### R1: Readiness decision is misread as implementation authorization

A misworded readiness decision markdown or matrix JSON could read
as authorization for the quality gate runner / PCACC runner / a
future validator to consume the waiver registry directly under
TASK-1041 itself, or as authorization to execute TASK-1042.

- **Risk**: matrix JSON field naming or markdown prose suggests the
  runtime extraction is already authorized
- **Trigger**: writing the JSON without
  `decision_status=decision_only`,
  `implementation_authorized=false`,
  `runtime_consumption_authorized=false` at the top, or omitting
  the explicit `non_authorization` block; writing the markdown
  without §4 Readiness decision or §16 Explicit non-authorization
- **Detection**: inspection evidence asserts the three top-level
  flags are all literal false and that `non_authorization` carries
  every required false key
- **Mitigation**: every top-level field that touches runtime
  semantics is paired with an explicit `false` flag; the markdown
  §4 / §16 / §17 repeat the non-authorization in prose; every
  allowlist entry carries `authorized_now=false`; every gate
  carries `authorized_now=false`
- **Severity**: blocking

### R2: Readiness decision contradicts the TASK-1040 plan contract

The readiness package could disagree with the TASK-1040 plan JSON's
24 fail-closed rows, 19 golden CLI requirements, or 15 future-task
acceptance criteria, or could mis-cite the TASK-1039 prototype
schema_version separation (waiver-policy-registry-prototype/v1 vs
waiver-policy-registry/v1).

- **Risk**: readiness matrix declares a different criteria set, a
  different gate set, or a different reason_code surface
- **Trigger**: drafting the readiness package from intuition rather
  than from the committed TASK-1040 plan JSON
- **Detection**: inspection evidence cross-checks each
  `readiness_criteria` entry against TASK-1040 plan JSON
  `future_task_acceptance_criteria`; `source_refs` lists the
  TASK-1040 plan JSON path
- **Mitigation**: the readiness package's `readiness_criteria` block
  carries one criterion per FTC-1..FTC-15 (mapped via `evidence_ref`
  to the TASK-1040 plan JSON entry); the gates surface the
  corresponding acceptance criteria from §7 fail-closed matrix and
  §11 golden CLI requirements
- **Severity**: blocking

### R3: TASK-1042+ artifact accidentally created

A typo or path slip could create
`artifacts/{tasks,plans,decisions,verify,status}/TASK-1042*` (or
later) lifecycle artifacts.

- **Risk**: candidate task lifecycle is unintentionally created
  during readiness writing
- **Trigger**: copy/paste of candidate task IDs into a path
- **Detection**: pre-commit `git diff --cached --name-only` is
  checked against the TASK-1041 allowed list; `git status --short`
  is inspected for any TASK-104{2..9}* path
- **Mitigation**: every candidate id appears in the readiness
  package only as a string under `future_implementation_allowlist`
  / markdown §5; no path under
  `artifacts/{tasks,plans,decisions,verify,status}/` is created for
  TASK-1042+
- **Severity**: blocking

### R4: Unrelated working-tree noise leaks into commit

`.obsidian/`, `.omc/`, `.tmp/`, `.pytest-basetemp/`, and
`__pycache__/` are known non-blocking local noise. A wide `git add`
would stage them.

- **Risk**: unrelated state is committed alongside TASK-1041
  artifacts
- **Trigger**: `git add -A` or `git add .`
- **Detection**: pre-commit `git diff --cached --name-only` is
  compared against the TASK-1041 allowed list
- **Mitigation**: stage files individually by path; verify
  `git diff --cached --name-only` matches exactly the TASK-1041
  allowed list before commit
- **Severity**: non-blocking
