## Goal

Implement the smallest safe runtime surface for waiver policy
consumption in the quality gate runner only. Add an explicit
`--waiver-policy <path>` CLI flag to `run_quality_gates.py` that
loads a `waiver-policy-registry/v1` registry, validates it under
the TASK-1040 fail-closed contract (FC-01..FC-24), and applies its
valid active unexpired waivers to QC-SYNC-001 findings only.
Default behavior without the flag must remain byte-identical
against the TASK-1029 / TASK-1037 fixtures. The root and template
runner pair must remain byte-identical after modification.

## Risks

### R1: Default-mode regression on TASK-1029 / TASK-1037 fixtures

A regression in `run_qc_sync_001` could change the reason_code
or pass/fail outcome for the existing TASK-1029 negative-test
fixtures or the TASK-1037 24 golden CLI cases.

- **Risk**: existing baseline-aware logic emits a different reason_code or status for unchanged fixture inputs.
- **Trigger**: rewriting the legacy waiver branch instead of inserting the runtime branch in front of it.
- **Detection**: post-modification self-check on the live repo emits identical reason_codes for the unchanged TASK-1029 / TASK-1037 surfaces; harness audit recomputes runner sha256 against the recorded baseline prefix and fails closed on mismatch.
- **Mitigation**: insert the runtime waiver branch BEFORE the legacy branch as an early-exit; do not alter the legacy `find_applicable_waivers` / `select_valid_waivers` helpers; runtime_waivers default to empty list when `--waiver-policy` is absent so the branch is a no-op in default mode.
- **Severity**: blocking

### R2: Runtime registry promoted from prototype path

A typo could cause the runner to default to the TASK-1039
prototype path under `artifacts/governance/prototypes/...` when
`--waiver-policy` is omitted, or to accept the prototype's
`waiver-policy-registry-prototype/v1` schema_version at runtime.

- **Risk**: the prototype is silently consumed at runtime, lifting the TASK-1039 `runtime_consumption_authorized=false` boundary.
- **Trigger**: defaulting `args.waiver_policy` to the prototype path; allowing prototype schema_version through schema validation.
- **Detection**: WAIVER-RT-006 case asserts that a registry with the prototype schema_version is rejected with `waiver_registry_schema_version_mismatch:waiver-policy-registry-prototype/v1`; no production waiver registry exists under `artifacts/governance/`.
- **Mitigation**: `RUNTIME_WAIVER_REGISTRY_SCHEMA_VERSION = "waiver-policy-registry/v1"` is a literal string check; `args.waiver_policy` defaults to None; activation is exclusively via the explicit CLI flag.
- **Severity**: blocking

### R3: Suppression leaks beyond QC-SYNC-001

A waiver could accidentally suppress non-QC-SYNC-001 findings
(QC-SCHEMA-001, QC-IMPORT-001, QC-GOLDEN-001, QC-RUFF-001
advisory) or PCACC / Evidence Ref / validator findings.

- **Risk**: a runtime waiver entry with `rule_id=QC-SCHEMA-001` (or any non-QC-SYNC-001 value) is loaded and silently applied; or the matching function ignores `rule_id` and matches by target alone.
- **Trigger**: not enforcing `rule_id in RUNTIME_WAIVER_SUPPORTED_RULE_IDS` at registry load; not gating `find_runtime_waiver_for_target` by rule_id.
- **Detection**: WAIVER-RT-025 asserts that a valid waiver does NOT affect QC-SCHEMA-001 surfaces; `RUNTIME_WAIVER_SUPPORTED_RULE_IDS = ("QC-SYNC-001",)` is enforced at registry load with reason_code `waiver_registry_unknown_enum_value:rule_id=<value>`; matching helper accepts only `rule_id="QC-SYNC-001"` callers.
- **Mitigation**: rule_id is enforced at both load time (registry-level) and matching time (suppression-level); the waiver application sites are exclusively inside `run_qc_sync_001` Pass 1 and Pass 2; non-QC-SYNC gates do not consult `runtime_waivers`.
- **Severity**: blocking

### R4: Commit noise leaks unrelated working-tree state

`.obsidian/`, `.omc/`, `.tmp/`, `.pytest-basetemp/`,
`__pycache__/` are known non-blocking local noise. A wide
`git add` would stage them.

- **Risk**: unrelated state is committed alongside TASK-1042 artifacts.
- **Trigger**: `git add -A` or `git add .`.
- **Detection**: pre-commit `git diff --cached --name-only` is compared against the TASK-1042 allowed list; staging is performed by exact path.
- **Mitigation**: stage by exact paths; final pre-commit check enumerates the staged set.
- **Severity**: non-blocking
