## Proposed Changes

### 1. workflow_constants.py

1.1 Add helper predicate `is_governance_decision_class(value: str) -> bool` returning `True` iff `value.lower().startswith("governance-")` and `len(value) > len("governance-")`.

1.2 Keep `DECISION_CLASSES` tuple unchanged (canonical 5). Export `is_governance_decision_class` from the module.

### 2. guard_status_validator.py

2.1 Replace the flat `MARKERS` tuples for `task` and `decision` with tuples that may contain nested tuples representing alternatives:
- task: `("# Task:", "## Metadata", "Task ID:", "Artifact Type: task", ("## Objective", "## Description"), ("## Constraints", "## Non Goals", "## Authorized Production Surface"), "## Acceptance Criteria")`
- decision: `(("# Decision Log:", "# Decision:"), "## Metadata", "Artifact Type: decision", ("## Issue", "## Context"), ("## Chosen Option", "## Decision"), ("## Reasoning", "## Consequences"))`
- All other artifact-type entries unchanged.

2.2 Add helper `_marker_present(text: str, marker: str) -> bool`:
- For markers starting with `#` and ending with `:` — line-anchored regex `^MARKER(\s|$)` (allows trailing content).
- For markers starting with `#` and NOT ending with `:` — line-anchored regex `^MARKER\s*$` (heading must stand alone on its line).
- For other markers (e.g. `Task ID:`, `Artifact Type: task`) — fall back to substring `in` containment, matching the existing v1 behaviour.

2.3 Replace the `[m for m in required_markers if m not in text]` list comprehension at the marker check call site with a loop that:
- For each marker in `MARKERS[artifact_type]`:
  - If it is a tuple, the marker is satisfied iff `any(_marker_present(text, alt) for alt in marker)`; if not, append `" / ".join(marker)` to missing.
  - Otherwise, the marker is satisfied iff `_marker_present(text, marker)`; if not, append `marker` to missing.

2.4 In `validate_decision_artifact`:
- Import `is_governance_decision_class` from `workflow_constants`.
- Decision Class check: pass if `decision_class.lower() in DECISION_CLASSES` OR `is_governance_decision_class(decision_class)`. Otherwise error as before.
- Affected Gate check: only enforce `DECISION_GATE_PATTERN` when the Decision Class is one of the canonical 5. For `governance-*` classes, allow any non-empty value (including `None`, `N/A`, or governance-specific text). Missing Affected Gate remains a warning.
- Expiry check: only enforce ISO 8601 `validate_taipei_timestamp` when the Decision Class is one of the canonical 5 AND the value is not in `{none, n/a}`. For `governance-*` classes, require non-empty Expiry but allow free-form prose; empty Expiry on a governance-class becomes a warning, not error.

2.5 Replace `parse_verify_checklist_items` with a splitter that prefers AC-item-start boundaries:
- Pattern: `^- \[[ x]\]\s+\S+:` (line-anchored, multiline). Match either `- [ ] ID:` or `- [x] ID:` style.
- If the section yields ≥1 such start, split the section at those start positions; merge text between consecutive starts as one block.
- If no such start is found, fall back to the original `re.split(r"\n\s*\n", section_text)` behaviour (preserves v1 verify-artifact compatibility for any artifact that doesn't use the `- [x] AC-N:` convention).
- For each block, parse fields via the existing `parse_structured_checklist_fields`; keep an item iff it has any of `criterion / method / reviewer / timestamp`.

### 3. docs/artifact_schema.md

3.1 Append §5.13 "v2 Governance Extension" documenting:
- v2 task allowed alternates: `## Description` for `## Objective`; `## Non Goals` and `## Authorized Production Surface` for `## Constraints`. v1 markers remain canonical and recommended for new tasks.
- v2 decision allowed alternates: `# Decision:` for `# Decision Log:`; `## Context` for `## Issue`; `## Decision` (h2) for `## Chosen Option`; `## Consequences` for `## Reasoning`. YAML frontmatter `schema_version: decision/v2` is permitted but optional.
- v2 Decision Class: any value starting with `governance-` plus a non-empty subclass token (e.g. `governance-attestation`, `governance-snapshot`, `governance-implementation`). The canonical 5 v1 classes remain the default for non-governance decisions.
- v2 Affected Gate: free-form (including `None`) when Decision Class is `governance-*`; canonical `Gate_A..Gate_E` enforced for the v1 five classes.
- v2 Expiry: free-form prose (commit anchor or plan version anchor) allowed when Decision Class is `governance-*`; ISO 8601 +08:00 required for the v1 five classes.
- Verify multi-paragraph evidence: `## Acceptance Criteria Checklist` items now split on `- [x] AC-N:` (or `- [ ] AC-N:`) item-start markers, allowing multi-paragraph evidence values without breaking the parser.

## Risks

- R1: Risk: Marker check regex relaxation accidentally matches `## Decision Class` when looking for `## Decision`, causing false positives that suppress real schema violations.
  Trigger: Substring containment in the existing simple `m in text` check for any new alternate marker that is a prefix of an existing valid heading.
  Detection: Build a synthetic v1 fixture where `## Decision Class:` appears but `## Decision` (the v2 chosen-option alternate) does not, and run the validator; expect missing-marker error to fire on `## Chosen Option / ## Decision` alternative.
  Mitigation: Implement `_marker_present` as line-anchored with end-of-line / whitespace boundary. For markers without trailing colon, require the marker line to consist of the marker only (allow trailing whitespace). For markers with trailing colon, allow any content after the colon.
  Severity: blocking

- R2: Risk: Decision Class governance prefix accidentally matches a misspelled or empty subclass like `governance-` (just the prefix) or `governance- ` (prefix + space).
  Trigger: User pastes incomplete governance-class string into a new decision artifact.
  Detection: Add a non-empty subclass length check; refuse `governance-` with no following non-whitespace token.
  Mitigation: `is_governance_decision_class` requires `len(value) > len("governance-")` AND the suffix after the prefix must contain at least one non-whitespace character. Test with a fixture artifact whose Decision Class is `governance-` (empty suffix).
  Severity: non-blocking

- R3: Risk: New `parse_verify_checklist_items` AC-N splitter regresses on a v1 verify artifact that did not use the `- [x] AC-N:` convention (e.g. an early-life verify artifact using `### AC-N` heading or plain `1. AC-N:` numbering).
  Trigger: A pre-1037 verify artifact (e.g. TASK-985, TASK-999) uses a different checklist convention.
  Detection: Run `guard_status_validator.py` against a representative pre-1037 verify artifact; observe any new "missing field" error.
  Mitigation: Splitter falls back to the legacy blank-line split when no AC-N start pattern is found. Keep the legacy code path intact.
  Severity: blocking

- R4: Risk: SHA-256 mirror to `template/` drifts because the editor inserts a different line ending or BOM for the same logical content (CRLF vs LF; UTF-8 with BOM).
  Trigger: Default Windows editor or a script's automatic newline conversion writes CRLF on root and LF on template (or vice versa).
  Detection: Post-write SHA-256 comparison shows mismatch despite identical visible content.
  Mitigation: Use `pathlib.Path.read_bytes()` + `Path.write_bytes()` (binary copy) when mirroring to `template/`. Compare SHA-256 prefixes immediately after each mirror.
  Severity: blocking

- R5: Risk: Prompt regression suite hard-codes v1 phrasing for `# Decision Log:` and breaks because the validator now also accepts `# Decision:`.
  Trigger: A regression case asserts that exactly the string `# Decision Log:` must appear in a decision artifact.
  Detection: Run `prompt_regression_validator.py --root .`; observe new failure.
  Mitigation: If new failures appear, update the affected drill case in `prompt_regression_cases.json` to accept either `# Decision Log:` or `# Decision:`. Mirror the case to `template/`.
  Severity: non-blocking

- R6: Risk: Validator change inadvertently breaks an unrelated artifact type (e.g. `improvement` or `code`) by sharing the new marker check helper.
  Trigger: `_marker_present` line-anchoring is too strict for an existing non-header marker like `Source Task:` (which appears mid-line in `## Metadata`).
  Detection: Run `guard_status_validator.py` for a recent improvement artifact (e.g. TASK-1043 has none, TASK-1031 has improvement) and observe.
  Mitigation: `_marker_present` only line-anchors when the marker starts with `#`. Other markers (`Source Task:`, `Task ID:`, `Artifact Type: improvement`) keep substring `in` semantics.
  Severity: non-blocking
