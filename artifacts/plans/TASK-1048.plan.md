## Risks

R1
- Risk: cross-reference 漏改導致下游 agent 載入時找不到對應節碼，靜默失敗或載入錯誤章節
- Trigger: 全 repo 引用點分布廣（CLAUDE.md / GEMINI.md / CODEX.md / AGENTS.md / .github/memory-bank/ / .github/prompts/ / artifact 範本 / scripts），人工或單次 Codex pass 易遺漏角落引用
- Detection: 6.6 之三條 `git grep` 命令；若仍有舊路徑出現於非「索引／回鏈」段落，即視為漏改
- Mitigation: 在 coding 階段最後一輪以 `git grep -nE` 全 repo 掃描三個關鍵字串；漏改處逐一補修；補修後重跑 prompt_regression_validator 確認 corpus 不退化
- Severity: blocking

R2
- Risk: 拆出之 spec 檔內容與原 §5.X 字面不符（拆分時誤刪／意改 schema literal），導致 validator 解析破口
- Trigger: Codex 在大量重組時可能將同義詞替換或重排欄位順序，破壞精確字串契約（如 `## Metadata`、`Last Updated`、副檔名命名）
- Detection: `python artifacts/scripts/guard_contract_validator.py` 與 `prompt_regression_validator.py` 兩條命令任一回 `[ERROR]`；或 `git diff --stat` 顯示原檔行數變化遠大於「索引化」之預期
- Mitigation: dispatch Codex prompt 明列「字面不可變」之 literal 清單；coding 完成後對拆出之每個 spec 檔，與原 §5.X 段落做 line-by-line `diff`，差異應僅限「節碼移除」「H1 標題新增」「回鏈新增」三類；若有額外差異，回退並重跑
- Severity: blocking

R3
- Risk: template/ 同步遺漏，sync contract 漂移，使 source template repo 鏡像失效
- Trigger: 新增 11 個檔案於 root 後忘記在 template/ 建立對應；或 template/ 鏡像檔內容與 root 不一致
- Detection: `python artifacts/scripts/guard_contract_validator.py` 之 sync contract 檢查；SHA-256 比對腳本（手動或加入 CI）
- Mitigation: coding 階段以「root + template」成對寫入為原則；最後一步以 `find docs/schemas template/docs/schemas -name '*.md' | sort` 比對兩側檔名集合；如有缺檔即補
- Severity: blocking

R4
- Risk: validator 之 hardcoded 檔案清單未擴充至新增之 spec 檔，導致新檔不被檢查或新檔被誤判為非法
- Trigger: `guard_contract_validator.py` / `prompt_regression_validator.py` 內若有 `EXPECTED_DOCS = ['artifact_schema.md', ...]` 之白名單，新增檔不在內
- Detection: validator 回 `[OK]` 但拆出之 spec 檔有錯誤未被偵測；或回 `[ERROR]: unexpected file in docs/schemas/`
- Mitigation: dispatch 階段先 `Grep` 兩條 validator 內所有 hardcoded path / docs 檔案清單；若有，於 plan 6.x 新增「擴充 validator path list」步驟；coding 階段同步擴充
- Severity: non-blocking
