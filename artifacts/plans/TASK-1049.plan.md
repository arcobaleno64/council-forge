## Risks

R1
- Risk: 拆分後 `from guard_status_validator import X` 形式呼叫無法解析，導致 test_guard_units.py 200+ 處 import 全部破，CI 紅
- Trigger: Codex 將 helper 移至 submodule 後忘記在主檔做 re-export；或 helper 名稱被改寫
- Detection: pytest collection 階段即拋 ImportError；`pytest --collect-only` 立即可見
- Mitigation: dispatch prompt 明列「主檔須以 `from .guard_helpers.X import *` re-export 所有移走之名」之硬規則；coding 完成後立刻 `python -c "from guard_status_validator import *"` 與 `pytest --collect-only` 雙重檢查；任何破口立即回退 commit
- Severity: blocking

R2
- Risk: cases registry 外部化破壞 phase 過濾邏輯，某些 case 遺漏或被誤分類
- Trigger: JSON metadata 之 `phase` 欄與原 source code 之 `case.phase` 不一致；或 `build_cases()` 之輸出順序改變
- Detection: `python run_red_team_suite.py --phase static` 之 case 數對照拆分前；`run_red_team_suite.py --phase all` 同樣對照
- Mitigation: dispatch prompt 明列「cases_metadata.json 之 phase / case_id / title 必須與原 source 逐字對齊」；coding 完成後 `diff <(git show HEAD:run_red_team_suite.py | grep -oP 'case_id="[^"]+", phase="[^"]+"' | sort) <(jq -r '.[] | "\(.case_id) \(.phase)"' red_team/cases_metadata.json | sort)` 比對等同
- Severity: blocking

R3
- Risk: template/ 鏡像漂移，sync contract 失效
- Trigger: 新增 8+ 檔於 root 後忘記在 template/ 建立對應；或 root 與 template 內容不一致
- Detection: `guard_contract_validator.py` 報 sync drift；`find artifacts/scripts/red_team artifacts/scripts/guard_helpers template/artifacts/scripts/red_team template/artifacts/scripts/guard_helpers -name '*.py' -o -name '*.json' | sort` 兩側檔案集合不對等
- Mitigation: dispatch prompt 明列「root + template 成對寫入」；coding 完成後 SHA-256 比對 8 個受影響檔；缺檔即補
- Severity: blocking

R4
- Risk: pytest 通過數下降（即使無 ImportError，個別 test 因 fixture inter-dependency 破而失敗）
- Trigger: 拆出之 submodule 中之 helper 簽章被微調（Codex 自動「修正」型別 hint 或順序），test fixture 互依鏈破
- Detection: pytest 結果 < 1166 passed
- Mitigation: dispatch prompt 明列「禁改任何函式簽章、參數順序、預設值、回傳結構；拆分 = 移檔 + import，不改內容」；coding 完成後立即 pytest 全跑；任何 fail 即 STOP 並回報 blocked
- Severity: blocking

R5
- Risk: Codex 越界刪除函式 / class / case（重演 TASK-1048 之 §5.9-§5.13 事故）
- Trigger: Codex 在「結構重組」過程中誤判某段為 dead code 或 redundant；或為「簡化」而刪除
