## Proposed Changes

### Step 1：七類範本檔案內容

每範本需有：
- 統一 frontmatter（除 GitHub UI 三類外）：`name / description / version / applicable_agents / applicable_stages / applicable_scale / prerequisites`
- Section 結構依下表（從 research §Confirmed Facts 與 RQ-4 overlap 結論摘出 minimum viable subset；full scale 之欄位以 H3 標記為 optional）
- 內容用 `{{PLACEHOLDER}}` 形式（依 CI-6）

| 範本 | 路徑 | 規模 | 必填段落 |
|---|---|---|---|
| PR description | `.github/PULL_REQUEST_TEMPLATE.md` | all | Summary / Linked Task / Files Changed / Verification Evidence / Risk |
| Bug report | `.github/ISSUE_TEMPLATE/bug_report.yml` | all | Reproduction / Expected vs Actual / Environment / Logs |
| Feature request | `.github/ISSUE_TEMPLATE/feature_request.yml` | all | Problem / Proposed Solution / Alternatives / Acceptance Criteria |
| SRS | `docs/templates/srs/TEMPLATE.md` | full（lightweight 用 User Story 簡化版） | Purpose / Scope / Functional Req / Non-Functional Req / Constraints / Acceptance Criteria |
| RTM | `docs/templates/rtm/TEMPLATE.md` | full | Requirement ID / Description / Source / Linked TASK / Linked Plan / Linked Code / Linked Verify / Status |
| Debug runbook | `docs/templates/debug/TEMPLATE.md` | both（lightweight=symptom+fix；full=完整段） | Symptom / Reproduction / Hypothesis / Evidence / Fix / Regression Test |
| ADR | `docs/templates/adr/TEMPLATE.md` | standard+ | Status / Context / Decision / Consequences / Alternatives |

每範本檔頭明示「與 council-forge 既有 artifact spec 之 overlap / delta」一句，避免使用者重複工作（依 CI-5）。例：ADR 範本檔頭加註「短期 task-local 決策改用 `artifacts/decisions/TASK-XXX.decision.md`；本範本適用跨多 task 之長期架構決策」。

### Step 2：`docs/lightweight_mode_rules.md` §「規模適用矩陣」

新增段（位於 §3 與 §4 之間，命名為「§3.5 範本規模適用矩陣」）：

| 工作型態 | lightweight 必填 | standard 加增 | full 加增 |
|---|---|---|---|
| Bug fix | task + code + verify + Bug report | + Debug runbook | + RTM（影響範圍 ≥3 模組時） |
| Feature | task + plan + code + verify + Feature request + PR description | + SRS（lightweight subset）+ ADR（若架構變動） | + SRS（full）+ RTM |
| PR (對外) | task + code + verify + PR description | + decision（若架構變動） | + ADR |
| Refactor | task + plan + code + verify | + ADR（若架構變動） | + RTM（影響範圍重新計算） |

註：本表為 lightweight_mode_rules.md 之 docs convention，不擴 `guard_status_validator.py` 之 required_artifacts policy。

### Step 3：`discover_templates.py` 擴充

新增：
- `TemplateInfo` dataclass 加 `applicable_scale: list[str]` 欄位（list 以兼容 frontmatter 寫 `[lightweight, standard]`）

- 對 frontmatter 缺 `applicable_scale` 鍵者：視為 `["all"]`，永遠過 filter

## Risks

R1
- Risk: 新範本與既有 9 類 artifact spec 欄位衝突，產生 schema fragmentation。ADR ↔ decision、Debug runbook ↔ improvement、SRS / RTM ↔ task / plan 多重來源不一致時，agent 在 plan/code 階段難以判斷 single source of truth。
- Trigger: ADR 與 decision artifact 對同一決策同時存在；Debug runbook 在事件結束後未轉為 improvement artifact，導致 post-mortem 紀錄缺失；SRS 之 Acceptance Criteria 段沿用 task §AC-N 編號規則但格式 drift。
- Detection: `guard_status_validator.py` 對單一 task 同時引用 ADR + decision 時 [WARN]（本批暫不擴 validator，但 plan 階段已預留 hook 檢查點）；人工 audit 範本檔頭之「overlap / delta 一句聲明」是否存在。
- Mitigation: 每個有 overlap 之新範本（SRS / RTM / Debug / ADR）檔頭強制加註「與既有 artifact spec 之關係」一句聲明（指向 `decision` / `improvement` / `task` 之適用條件）；plan 階段已產出 RQ-4 overlap/delta 表，coding 階段對照此表為單一來源；若範本內容仍與既有 spec 衝突，立 decision artifact 說明 split-source rationale。
- Severity: blocking

R2
- Risk: `discover_templates.py --scale` 過濾邏輯誤改 `discover()` 函式，破壞既有 `--agent` / `--stage` filter 行為。
- Trigger: 改寫 `discover()` 時誤觸 None-default 邏輯（如把 `if agent:` 改為 `if agent is None:` 反邏輯）；frontmatter `applicable_scale` 鍵不存在時拋例外而非 fallback `["all"]`。
- Detection: `python -m pytest artifacts/scripts/test_guard_units.py artifacts/scripts/test_security_scans.py` 通過數退步於 baseline 1166；既有 `python artifacts/scripts/discover_templates.py --agent "Codex CLI"` 命令列輸出改變。
- Mitigation: `--scale` 為 additive-only 參數（預設 `None` 不過濾）；frontmatter 缺鍵時 fallback `["all"]`；coding 結束前跑既有 pytest baseline 比對；4 條 `--scale <level>` CLI 樣板手動執行驗證並記入 verify Build Guarantee（AC-10）。
- Severity: non-blocking

R3
- Risk: `bug_report.yml` / `feature_request.yml` 之 GitHub Issue Forms YAML 格式錯誤，致 GitHub UI 無法解析、退回預設 markdown issue 形式。
- Trigger: yaml `body[].type` 用 GitHub 不支援值（如拼錯 `markdwon`）；required 欄位（如 `name`、`description`、`body`）缺失；attributes / validations 結構違反 schema。
- Detection: 推送後 GitHub repo Issues → New Issue 頁面手動檢查；GitHub 對 .github/ISSUE_TEMPLATE/*.yml 有後台 schema validation（issue 建立失敗時前台會退回）；本批 verify 階段於 push 後 5 分鐘內手動檢查。
- Mitigation: 直接採用 GitHub 官方範例（https://docs.github.com/en/communities/using-templates-to-encourage-useful-issues-and-pull-requests/syntax-for-githubs-form-schema）逐欄位對照；本批僅列基本必要欄位（type / id / attributes / validations）；推送後立即手動檢查 Issues 頁面；若解析失敗，於 verify 標 deferred 並補修。
- Severity: non-blocking

R4
- Risk: 9 個 root 變更檔對應之 template/ 鏡像漏同步，guard_contract_validator.py 報 [FAIL]。
- Trigger: coding 階段未逐檔複製；template/.github/ISSUE_TEMPLATE/ 子目錄須 mkdir 而被忽略；換行符號 (CRLF vs LF) 差異致 SHA-256 mismatch。
- Detection: `python artifacts/scripts/guard_contract_validator.py` 列出 root↔template SHA-256 mismatch；`Get-FileHash -Algorithm SHA256` 逐檔比對。
- Mitigation: coding 之 implementer 完成 root 變更後立即逐檔 `Copy-Item -Force` 至 template/；statements 完成後以 PowerShell `Compare-Object` 對 9 對檔之 hash 集合驗證；若 .github/ISSUE_TEMPLATE/ 在 template/ 下不存在須先 mkdir；強制 UTF-8 LF（與既有 docs/* 一致）。
- Severity: blocking

R5
- Risk: `applicable_scale` frontmatter 值未對齊 lightweight_mode_rules.md §「規模適用矩陣」之 scale 命名（lightweight / standard / full）。
- Trigger: 範本作者填 `applicable_scale: minimal` 或 `enterprise` 等枚舉外之值；多範本不一致（一份用 `lightweight` 另一份用 `lite`）。
- Detection: `discover_templates.py --scale lightweight` 過濾結果與預期不符；手動 audit 7 個範本之 frontmatter。
- Mitigation: 在 `docs/lightweight_mode_rules.md` §3.5 明列允許值（`lightweight | standard | full | both | all`）；本批 7 範本之 frontmatter 由 Claude 一次寫入後人工 audit；不擴 validator 檢查（屬 follow-up）。
- Severity: non-blocking
