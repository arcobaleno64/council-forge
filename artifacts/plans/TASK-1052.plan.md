## Proposed Changes

### Step 1：`Invoke-CodexReview.ps1` orchestrator

PS 7+ script，依研究 §CI-1~CI-6 撰寫。Param block：

```
[CmdletBinding()]
param(
    [ValidateSet('staged','unstaged','all','HEAD')]
    [string]$DiffSource = 'all',
    [string]$OutputDir = 'artifacts/reviews/',
    [string[]]$CouncilModels = @('gpt-5.4-mini','gpt-5.4','gpt-5.5'),
    [string]$ReasoningEffort = 'high',
    [switch]$DryRun = $false,
    [string[]]$AllowedPaths = @(),
    [switch]$AutoRestore = $false,
    [switch]$ShowHelp = $false
)
```

行為流：

1. 若無參（`$PSBoundParameters.Count -eq 0`）或 `-ShowHelp` → 印 usage 表 + exit 1。
2. 解析 `-DiffSource` 對應之 `git diff` 命令；取 diff 文字。
3. 若 diff 為空 → 印「No diff to review」+ exit 0。
4. 構建 review prompt（短 instruction + diff 連接；instruction 含 severity rubric / output format / Council member context）。
5. For each model in `$CouncilModels`：
   - 若 `-DryRun` → 印「[DRY-RUN] dispatch: model=X effort=Y prompt_size=N」+ 跳過實際呼叫；
   - 否則 → 呼叫 `& "$PSScriptRoot\Invoke-CodexAgent.ps1" -Model $m -ModelPolicy fixed -ReasoningEffort $ReasoningEffort -TaskScale standard -ApprovalMode never -Prompt $prompt`；
   - 將 stdout 寫入 `$OutputDir/<timestamp>-<model>.md`（含 frontmatter：model / effort / diff_source / commit_anchor）。
6. 印 summary 表：3 review 檔路徑 + 字數 + exit 0。

注意事項：

- `-AllowedPaths` 若給定，僅 `artifacts/reviews/` 為合法寫檔範圍——本 orchestrator 自身不寫其他檔。
- `-AutoRestore` 透傳至 `Invoke-CodexAgent.ps1`（caller 不額外處理）。
- 不引入新 import（純內建 cmdlet）。

### Step 2：`.claude/commands/codex-review.md` slash command

Frontmatter：

```yaml
---
description: Run a Codex Council-of-models review on the current diff and produce a triaged summary
argument-hint: "[--diff-source staged|unstaged|all|HEAD] [--dry-run]"
allowed-tools: Bash(pwsh*), Bash(git diff*), Read, Write
---
```

主體（自然語言指引）：

1. **Step 1: Parse args** — 從 user 命令解析 `--diff-source`（預設 `all`）與 `--dry-run`（預設 false）。
2. **Step 2: Invoke orchestrator** — 透過 Bash tool 跑 `pwsh -File artifacts/scripts/Invoke-CodexReview.ps1 -DiffSource <X> [-DryRun]`。
3. **Step 3: Read 3 review outputs** — 讀 `artifacts/reviews/<timestamp>-{mini,5.4,5.5}.md` 三檔。
4. **Step 4: Triage** — 依 quality-playbook §Council of Three protocol 之三層裁示：
   - **Agreement**：3 model 皆指出之 finding → severity 自動升至 `high`。
   - **Majority**：2/3 model 指出之 finding → 保留 model 自評 severity。
   - **Dissent**：僅 1 model 指出 → 標 `dissent`，附 model 名稱供 user 判斷。
5. **Step 5: Output** — 以 markdown table 列出 triaged findings：`severity | source_models | location | issue | suggested_fix`。
6. **Step 6: Recommend next** — 列 user 可能下一步動作（接受 / 駁回 / 補測試 / 補 ADR）。

主體並含：

- Triggers 段：「Run a Codex Council review」「codex council」「multi-model review」等
- Limitations 段：明示「single-machine Codex dispatch（非真正 multi-vendor），cmd 8191 字限制屬 TASK-1053 follow-up」「對大 diff 建議 commit-by-commit 拆分」
- Output Format 段：明示 Council triage table 之欄位 schema

## Risks

R1
- Risk: `Invoke-CodexReview.ps1` 之 dispatch loop 直接 invoke `Invoke-CodexAgent.ps1`，若 prompt + diff 累計長度超 cmd 8191 字（TASK-1053 未修），下游 wrapper 將靜默失敗或拒收，user 看到 3 個空 review 卻無錯誤訊息。
- Trigger: `-DiffSource all` 對於累計 staged + unstaged 變更超 ~6000 字之 batch（如本 TASK-1052 自身之 SKILL/PS 雙檔加 lifecycle 7 artifacts），加上 review prompt header ~500 字，超 8191 上限。
- Detection: 個別 review 檔 size < 100 bytes，或 stdout 含「Intercepted API/Execution Error」但 file 已建立；commit 前以 `Get-Item artifacts/reviews/*.md | Select Name,Length` 抽檢。
- Mitigation: orchestrator 預先計算 prompt + diff 字數，超 6000 字時印 warning + 建議 user 改 `-DiffSource HEAD`（單 commit）或 commit-by-commit 拆分；本批 `-DryRun` mode 已會印 prompt_size，可預檢；e2e 修復屬 TASK-1053。
- Severity: blocking

R2
- Risk: `.claude/commands/codex-review.md` 之 frontmatter `allowed-tools` 鍵之語法或值不符 Claude Code 官方規範，致 slash command 無法被 IDE 識別或無法呼叫 Bash tool 跑 PS。
- Trigger: 寫 frontmatter 時憑記憶寫 `allowed-tools: Bash(pwsh*), Bash(git diff*), Read, Write`，但 Claude Code 之 allowed-tools 語法可能要求不同格式（如 list 而非 comma-separated）。
- Detection: user 在 IDE 鍵入 `/codex-review` 後 Claude 回「unknown command」或「tool not allowed」；Bash tool 呼叫 `pwsh -File ...` 被拒。
- Mitigation: 採最寬鬆 frontmatter——`allowed-tools` 僅列必要 tool 之 family（`Bash`, `Read`, `Write`），不限制 sub-command；若仍出問題，主體段落明示 user 可手動執行 `pwsh -File artifacts/scripts/Invoke-CodexReview.ps1` 並貼回結果，slash command 退化為「教學文件」而非「自動執行 wrapper」；本批不做 e2e IDE 驗證（屬 user runbook）。
- Severity: non-blocking

R3
- Risk: `template/` 鏡像漏同步致 SHA-256 mismatch、`guard_contract_validator.py` 雖未把新檔列入 `EXACT_SYNC_FILES` 但 `template/` 之 `.claude/commands/` 子目錄不存在會破壞「root↔template 結構同形」之非正式契約，未來 downstream 複製 `template/` 開新 repo 時缺檔。
- Trigger: 寫 root `.claude/commands/codex-review.md` 後忘了立即 PowerShell `Copy-Item -Force`；或 `template/.claude/commands/` 子目錄不存在須 mkdir 而忽略。
- Detection: PowerShell `Get-FileHash -Algorithm SHA256` 比對 4 對檔案（2 內容檔 + 2 .gitkeep），任一 mismatch 或 root-only 存在；`Test-Path template/.claude/commands/codex-review.md` 回 False。
- Mitigation: 寫 root 後立即 `New-Item -ItemType Directory -Force template/.claude/commands/` + `Copy-Item -Force`；coding 結束前 SHA-256 全綠驗證（4 對 0 mismatch）；強制 UTF-8 LF（與既有 `Invoke-CodexAgent.ps1` 一致）。
- Severity: blocking

R4
- Risk: `Invoke-CodexReview.ps1` 之 `-DryRun` 路徑邏輯有 bug，致 `-DryRun $true` 仍真實呼叫 `Invoke-CodexAgent.ps1`，意外消耗 Codex tokens（user 跑 dry-run 預期免費卻被計費）。
- Trigger: `if ($DryRun) { ... }` 之 branching 寫成 `if (-not $DryRun) { ... }` 或忘了 `else { ... }` 之 fall-through；switch 參數未正確以 `[switch]` 宣告致 `-DryRun` 被當 string。
- Detection: 跑 `pwsh -File ... -DryRun` 後 `git status` 顯示 `artifacts/reviews/*.md` 已建立（dry-run 不該寫檔）；或 stdout 不含「[DRY-RUN]」標記；或 process 耗時 > 5 秒（dry-run 不該對外呼叫）。
- Mitigation: param 宣告 `[switch]$DryRun = $false`；dispatch loop 內以 `if ($DryRun) { Write-Host "[DRY-RUN] ..."; continue }` 為 early continue，不再 fall-through 到實際呼叫；coding 階段三 smoke 之 (i) DryRun 必驗證「不寫檔 + 含 [DRY-RUN] tag + < 5 秒」三條件；任一不符則回 plan。
- Severity: blocking
