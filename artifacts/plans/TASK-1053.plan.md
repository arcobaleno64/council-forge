## Risks

R1
- Risk: `codex exec` 在 stdin pipe 模式下對於空 stdin 或 stdin 中斷（pipe close 太早）行為不可預期，致 long-prompt path dispatch 失敗或 hang。
- Trigger: `$Prompt | & codex.cmd exec ...` 之 PowerShell pipeline 在 prompt 構建後立即 close pipe；codex 在解析 stdin 為「instruction text」之前 pipe 已關，codex 收到 0-byte stdin 視為「無 prompt」並走 default 互動路徑或拋 ParseError。
- Detection: e2e 試跑時 review 檔 frontmatter `exit_code` 非 0 或 stdout 為空；mock smoke (ii) 印「__STDIN_PIPE__」但「stdin 收到內容」為空；本機快速 probe 已驗證 `echo "test" | codex exec ...` 可正確讀 stdin 並印「Reading prompt from stdin...」。
- Mitigation: 採 PowerShell native pipeline `$Prompt | & $Executable $processArgs`，PS 自動處理 stdin 之 buffering 與 EOF；不採 `Out-String | & ...`（會多一層轉換）；e2e 試跑前先以 mock smoke (ii) 端到端確認 stdin 確實 carry 內容；若 e2e 失敗，回 plan 改採 `--input-file <tempfile>` 替代方案（屬 follow-up，本批不切方案）。
- Severity: blocking

R2
- Risk: `-a never -s workspace-write` 之 flag 順序敏感——置於 `exec` 子命令之前 vs 之後行為差異致 codex 拒收 args 或 sandbox 設定無效。
- Trigger: 既有 wrapper 之 `$processArgs` 為 `@("exec", "-m", ...)` 順序，新版本須改為 `@("-a", "never", "-s", "workspace-write", "exec", "-m", ...)`；若仍維持 exec 在前，codex 將 `-a` / `-s` 視為 exec subcommand 之 unknown flag。
- Detection: mock smoke (iii) 之 args 紀錄；本機 probe `codex --help` 顯示 `-a` / `-s` 為 top-level flag，必須置於 subcommand 之前；e2e 試跑若 codex stderr 含 `unrecognized argument` 或 `unexpected option`，視為 R2 觸發。
- Mitigation: dispatch args 構建順序固定為 `[-a, never, -s, workspace-write, exec, -m, <model>, -c, <effort>, [PROMPT|--]]`；mock smoke (iii) 強制 assert args 之 `[0]==-a`、`[1]==never`、`[2]==-s`、`[3]==workspace-write`、`[4]==exec`；e2e 失敗時回退至 plan §1.2 之精確順序檢查。
- Severity: blocking

R3
- Risk: real Codex e2e Council 試跑（AC-14）token cost 失控或某 model 試跑失敗，導致 verify 卡住。
- Trigger: `-DiffSource HEAD` 對 TASK-1052 commit `1ee12ff` 之單 commit diff（13 檔 1547 行 insertion）之 prompt_size ≈ 64686 字；mini ~ $0.01-0.02 / 5.4 ~ $0.05-0.10 / 5.5 ~ $0.10-0.30；user 帳號可能對某 tier 未授權或 quota 耗盡。
- Detection: e2e 開始 8 分鐘後仍未產出 3 review 檔；任一 review 檔之 `exit_code` ≠ 0 + stdout 全空；token cost 之 user-side 監控（屬 user runbook）。
- Mitigation: AC-14 設「至少 2/3 review 之 exit_code=0 + stdout ≥ 100 字」之最低門檻——允許其中 1 model fail 不阻 verify；整體執行時間 ≤ 8 分鐘為 cost ceiling 之 proxy；e2e 試跑前先 `pwsh ... -DryRun -DiffSource HEAD` 確認 prompt_size 在預期範圍；若三 model 全 fail，回 plan 標 blocked + dump 各 review 檔 frontmatter 之 exit_code 與 combined stderr 至 verify §Known Debts。
- Severity: blocking

R4
- Risk: PR-010 / PR-023 之 modify 操作誤觸 doc-side assertion（subagent_roles.md / CODEX.md），致 PR validator 對未動之 doc file 仍報 fail。
- Trigger: JSON edit 操作不夠精準，意外刪除或 reorder doc-file 之 must_contain_all 列表。
- Detection: `python artifacts/scripts/prompt_regression_validator.py --root .` 對 PR-010 / PR-023 之 doc-file row 報 fail；diff 比對 prompt_regression_cases.json 之 doc-file 段未動。
- Mitigation: 採 PowerShell `[regex]::Replace` 或精準 line-range Edit，僅修 PR-010 / PR-023 之 wrapper file 段（可由 file path string 區分）；coding 後 grep 比對 `docs/subagent_roles.md` / `CODEX.md` 在 prompt_regression_cases.json 之命中行未變動。
- Severity: non-blocking

- Trigger: 修 root .ps1 後忘了立即 `Copy-Item -Force`；或 PR JSON 之 mirror 漏同步致 PR test 在 downstream 走舊 PR 規則。
- Detection: PowerShell `Get-FileHash -Algorithm SHA256` 比對三對檔（兩 wrapper + 一 PR JSON），任一 mismatch；`Test-Path template/artifacts/scripts/<file>` 回 False。
- Mitigation: 修 root 後立即 `Copy-Item -Force`；coding 結束前 SHA-256 全綠驗證（3 對 0 mismatch）；強制 UTF-8 LF（與既有兩 wrapper 一致）；prompt_regression_cases.json 為 `EXACT_SYNC_FILES` 之 17 檔之一，validator 自動偵測 drift。
- Severity: blocking
