## Proposed Changes

### Step 1：Invoke-CodexAgent.ps1 修改

新增 param block 末尾 2 個 optional 參數：
```
[string[]]$AllowedPaths = @(),
[switch]$AutoRestore = $false
```

主 loop（行 100-172）後、wrap-up（行 174）前插入新段：
- 若 `$AllowedPaths.Count -eq 0`：印「[GUARD] skipped (no AllowedPaths configured)」並跳過 guard
- 否則：跑 `git status --porcelain` 收集變更檔；對每行 trim status prefix + trim 雙引號 + normalize forward slash；對 rename 形式 `R old -> new` 取 `new` 部分
- 違規檢測：path 對 AllowedPaths 做匹配（trailing `/` = 目錄前綴；否則 exact）；不在 allowed 即記入 `$violations`
- 違規處置：印 `[GUARD] Post-dispatch detected unexpected file changes:` + 違規檔；若 `$AutoRestore` 設定，對每條跑 `git ls-files --error-unmatch` 判 tracked，tracked 用 `git checkout HEAD --`、untracked 用 `Remove-Item -Force -ErrorAction SilentlyContinue`；最後 `exit 2`
- 無違規：印「[GUARD] Post-dispatch check OK; all changes within allowed paths.」

## Risks

R1
- Risk: Guard 邏輯 bug 致 false positive 自動還原合法檔案；AllowedPaths 比對誤判將 plan 合法允許之檔誤識為越界，啟動 `-AutoRestore` 後刪使用者本批之合法工作。
- Trigger: AllowedPaths 元素 path separator 不一致（Windows `\` vs `/`）；rename 形式 `R old -> new` parse 失誤；目錄前綴匹配誤判（如 `artifacts/research/` 誤匹 `artifacts/research-temp.md`，缺 trailing `/` 之精確判定）。
- Detection: Step 6 手動測試三情境含 (i) 既有不傳 (ii) 合法 (iii) 模擬違規；guard 預設 `-AutoRestore=$false`，須顯式 opt-in 才還原。
- Mitigation: `-AutoRestore` 預設 `$false`；path normalize 統一 forward slash；目錄前綴比對嚴格 trailing `/`（不容隱式）；rename split by ` -> ` 取後半；本批 plan §Files Likely Affected 之 path 完整列出（含 trailing `/` for 目錄）；Step 6 三情境 smoke 在 commit 前完成。
- Severity: blocking

R2
- Risk: Wrapper 修改破壞既有 dispatch 流程致後續 task 之 dispatch 全失敗。
- Trigger: PowerShell param block 之 `[string[]]` / `[switch]` 語法錯誤；變數作用域漂移（如 `$IsSuccess` 被誤覆蓋）；exit code path 漂移（既有 success exit 0 / API fail exit 1 之路徑被切斷）。
- Detection: 修改後 `pwsh -File <wrapper> -Prompt "test"` smoke run（無 AllowedPaths）→ wrap-up 印「success」與 exit 0；既有 `gh run list` 之 Workflow Guards 通過；本批 commit 後 push 之 CI 綠燈。
- Mitigation: 新段落限「主 loop 之後 wrap-up 之前」插入，**不改既有 loop 邏輯**；param block append 新 optional 參數於既有 5/8 個之後；變數命名空間獨立（用 `$_guard*` prefix）；guard violation exit 2 與既有 0/1 不衝突；Step 6 三情境 smoke 涵蓋。
- Severity: blocking

R3
- Risk: CODEX.md / GEMINI.md 新增段落與 TASK-1056 之 §Model Policy 更新衝突。
- Trigger: TASK-1056 啟動時以 absolute line number patch 形式 apply（而非 section-based search-replace）。
- Detection: 本批完成後 grep 兩 .md 檔之段落順序，確認新段不影響 §Model Policy 之段標題行匹配。
- Mitigation: 本批新段以 `## Write Scope Discipline` 為唯一新 section header，位於 §禁止事項 後；TASK-1056 啟動時須 reload .md 不可用 cached line number；本批 verify §Recommendation 提醒此事項。
- Severity: non-blocking

R4
- Risk: Path matching 對中文 / 空格 / 特殊字元路徑之邊界條件處理失誤。
- Trigger: sub-agent 寫入檔名含空格 / 中文 / 特殊字元 之檔；`git status --porcelain` 對含空格路徑以 `"<path>"` 雙引號包裹。
- Detection: Step 6 (iii) 模擬違規時故意以含空格檔名測試。
- Mitigation: wrapper parse 時對 git output 之每行先 trim 兩端 `"`；path normalize 統一 forward slash；council-forge 既有路徑慣例為純 ASCII + forward slash，實際邊界情境機率低，mitigation 保留 robust 處理。
- Severity: non-blocking

R5
- Risk: template/ 4 對檔之 SHA-256 不一致致 contract validator [FAIL]。
- Trigger: 修 root 之 4 檔（2 wrapper + 2 .md）後忘鏡像 template/；換行 CRLF/LF 差異。
- Detection: PowerShell `Get-FileHash -Algorithm SHA256` 4-pair 比對；guard_contract_validator 重跑。
- Mitigation: 4 檔修完後一次 PowerShell loop 鏡像 + 即時 SHA-256 比對 4 行 [OK]；CRLF 由 .gitattributes 自動處理（與 TASK-1050 / 1051 同流程）。
- Severity: non-blocking
