## Risks

R1
- Risk: routine 之 saved prompt（user 端 claude.ai 帳號內）與 repo 內 `.github/prompts/weekly-claude-audit.prompt.md` 飄離；user 修改 repo prompt 後忘記同步 saved prompt（或反之），致 routine 行為與 repo 文檔不一致，產生 governance drift。
- Trigger: 任何修改 `.github/prompts/weekly-claude-audit.prompt.md` 之 PR 合併後，user 未同步至 `/schedule update` 之 saved prompt。
- Detection: weekly routine 跑出之 review PR 內容與 repo prompt 之 Output Format 不符；或 review file 路徑與 cadence doc 之 Artifact Destination 不一致；可由 PR reviewer 直接觀察。
- Mitigation: prompt 設計採「thin pointer」模式 — saved prompt 僅一句「Read and execute `.github/prompts/weekly-claude-audit.prompt.md`」，所有實質內容存於 repo 檔；任何 review behavior 變更僅須改 repo file，無須改 saved prompt；於 cadence doc setup steps 明列此原則。
- Severity: blocking

R2
- Risk: GitHub Actions scheduled workflow 於 high load 時段被延遲或跳過；quarterly issue 未如期建立；user 未察覺致該季 threat model exercise 漏跑。
- Trigger: 季首日 UTC 05:30 之 cron 觸發時 GitHub Actions 高負載（per 官方文檔「The schedule event can be delayed during periods of high loads」）；或 repo 60 天無活動致 scheduled workflow 自動 disable。
- Detection: 季首日 +1 日 user 檢查 issue tracker 無 `[Quarterly Threat Model]` issue；或 `Settings → Actions → General` 顯示 workflow 為 disabled。
- Mitigation: workflow 同時設 `workflow_dispatch:` 為 manual trigger 備援；cadence doc 之 Cadence Drift Recovery 段列出 user 季首日 +1 日檢查清單與手動 trigger 命令；公開 repo 60 天 disable 之風險於本 repo 不適用（持續 push 活動）。
- Severity: non-blocking

R3
- Risk: routine 之 commits / PR 顯示為 user 個人 GitHub identity（per Anthropic 文檔「commits and pull requests carry your GitHub user」）；audit log 上看似 user 親手提交，但實為 routine 自動產出，blame 不準。
- Trigger: routine 跑完 weekly review 後 push 至 `claude/weekly-audit-<date>` branch + 開 PR。
- Detection: PR author 為 user 個人帳號而非 bot；commit message 與 PR title 之 routine 屬性僅以 prompt-side disclaimer 顯示。
- Mitigation: prompt 模板要求 routine 於 commit message 開頭加 `[claude-routine]` prefix；於 PR body 開頭明列「Generated by Claude Cloud Routine: weekly-claude-audit」+ routine ID；cadence doc setup steps 明列此 attribution requirement；不依賴 GitHub identity 區分 routine vs human。
- Severity: non-blocking

R4
- Risk: `docs/security_cadence.md` 之 cadence 描述與 `.github/workflows/security-scan.yml` / `quarterly-threat-model.yml` / weekly prompt 檔之實際行為不一致（doc drift）；user 依 doc 期待但實際 cadence 不同。
- Trigger: 任何修改 workflow yml 或 prompt 檔之 PR 未同步更新 cadence doc；或 cadence doc 修改未對齊 yml。
- Detection: 可以人工 cross-check 或 future task 寫 lint script 比對 doc 與 yml cron / workflow_dispatch 之 字面值；本 task 無自動 lint。
- Mitigation: cadence doc 之每段 cadence 引用對應 yml / prompt 之 relative path（如 `.github/workflows/quarterly-threat-model.yml`），便於 reviewer 一鍵 cross-check；future task TASK-10xx 可加 lint script 比對；本 task 採 manual reviewer responsibility 為 first-line defense。
- Severity: non-blocking

R5
- Risk: template/ 鏡像 SHA-256 mismatch；source repo 之 root 與 template/ 對應檔字面不同；guard_contract_validator 雖不對非 EXACT_SYNC_FILES 強制 SHA check，但 broader sync contract（CLAUDE.md §「Template Sync」）要求一致；downstream terminal repo 由 template/ 複製出之版本將失新增 cadence governance。
- Trigger: 編寫 root 檔後遺漏 template/ 鏡像，或 template/ 鏡像時間差導致版本不一致。
- Detection: 本 task 之 verify 階段執行 `Get-FileHash` SHA-256 比對 root + template/ 之 4 對檔；mismatch 則 `[FAIL]`。
- Mitigation: 採 single-write-then-mirror pattern：每寫一 root 檔即立即用 `Copy-Item` 鏡像至 template/，並於 verify 階段以 PowerShell SHA-256 比對輸出 `MATCH/MISMATCH`；mismatch 時 task state 不得進 done。
- Severity: blocking
