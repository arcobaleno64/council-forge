## Proposed Changes

### Stage 1：兩 wrapper（並行修改）

- 1.1 **Param block**：兩 wrapper 各加 `[switch]$AutoRestoreLegacy = $false`；既有 `-AutoRestore`、`-AllowedPaths` 不動。
- 1.2 **Helper functions**（插入 param block 之後 / main loop 之前；以 `region` 註解標）：
  - `Save-PreDispatchState`：`git stash push -u -m "TASK-1057 pre-dispatch <yyyyMMddHHmmss>"`；以 `git stash list --max-count=1` 之第一段 `stash@{N}` 取 ref；返回 ref 字串或 `$null`（無 modifications 時 / stash 失敗時）。
  - `Restore-PostDispatchDelta`：對 `$violations` 集合中每 path 執行 targeted restore——tracked 跑 `git checkout HEAD -- $v`；untracked 跑 `Remove-Item -Force -ErrorAction SilentlyContinue`；既有判斷邏輯（`git ls-files --error-unmatch`）保留。
  - `Pop-PreDispatchState`：對非 null ref 跑 `git stash pop $ref`；exit 0 → return 0；exit 1（conflict）→ Write-Host stash@{N} ref + 不 drop + return 3；ref 為 null → 直接 return 0。
- 1.3 **Main flow 整合**：
  - param block 解析完成後，若 `$AutoRestoreLegacy.IsPresent`：印 DarkYellow `[DEPRECATED] -AutoRestoreLegacy maps to -AutoRestore for backward-compat; expect removal in TASK-10xx (date TBD)`；若 `$AutoRestore.IsPresent` 同時設則 `[DEPRECATED] flags coexist; -AutoRestore wins` warning；無同時設則 `$AutoRestore = $true`（forward）。
  - 若 `$AllowedPaths.Count -gt 0`：在 model loop 之前 invoke `Save-PreDispatchState`，紀錄 stash ref 至 `$preDispatchStashRef` 區域變數。
  - Model loop 不變。
  - Model loop 結束後、wrap-up 之前：重構 guard 段為 (a) `git status --porcelain` 解析（既有邏輯保留）；(b) violation list 為 stash 後之 disk delta（純 sub-agent 寫入）；(c) violation 印 `[GUARD] Post-dispatch detected sub-agent writes outside AllowedPaths:` + paths；(d) `$AutoRestore` 設則 invoke `Restore-PostDispatchDelta`；(e) invoke `Pop-PreDispatchState`，若 return 3 則 exit 3；(f) `$violations` 非空且 `$AutoRestore` 設則 Write-Error `__GUARD_VIOLATION:[TASK-1057] Sub-agent wrote files outside AllowedPaths.__` + exit 2；(g) `$violations` 非空且 `$AutoRestore` 未設則印 detect-only warning，繼續至 wrap-up（exit 0/1 由 dispatch 結果決定，不被 guard 改寫）。
  - wrap-up 區段不變（既有 IsSuccess / BestEffortOutput 等邏輯）。

## Risks

### R1: stash pop conflict 之 wrapper exit 3 處理失誤導致 user state 遺失

- Risk: `Pop-PreDispatchState` 對 conflict 情境之 detection 不可靠（`$LASTEXITCODE` 在 PowerShell → cmd → git.exe chain 之 mask 風險，per UI-2），導致 wrapper 誤判 pop 成功而 silent drop stash entry，user pre-dispatch state 永久遺失（含 untracked `.obsidian/graph.json` 類檔）。
- Trigger: smoke (iv) 之 conflict 情境發生於真實 dispatch；exit code 在 PowerShell pipeline 被吞或被 reset。
- Detection: smoke (iv) 必跑且驗證：(a) wrapper exit 3；(b) `git stash list` 仍含 `TASK-1057 pre-dispatch` 字串之 ref；(c) stdout 印 stash@{N} 之具體 ref 字面值。
- Mitigation: `Pop-PreDispatchState` 在 invoke `git stash pop` 後立即 capture `$LASTEXITCODE` 至區域變數（不延後）；額外 parse stash pop stdout 之 conflict marker（如 `CONFLICT (`）作 secondary check；若 secondary 偵測 conflict 但 exit code 為 0，視為 mask 觸發並仍 exit 3（fail-safe）；smoke (iv) 為 acceptance criterion，不過即阻塞 commit。
- Severity: blocking

### R2: param block 介面變動誤破既有 caller

- Risk: 新增 `-AutoRestoreLegacy` 之 PowerShell ValidateSet 處理或 default 值若有誤，可能造成既有 caller invoke 時 param binding 失敗（exit 1 / `Cannot bind argument`），影響 TASK-1052 之 `Invoke-CodexReview.ps1` Council orchestrator 與 user slash command。
- Trigger: 既有 caller 在不傳 `-AutoRestoreLegacy` 之情境下 invoke wrapper（為 90%+ 之常見呼叫）。
- Detection: 在 coding 階段以既有 `Invoke-CodexReview.ps1 -DryRun -DiffSource HEAD` 試跑驗證 param binding 不破；smoke (i) 之 PreservesUserPreDispatchModified 之 `-AllowedPaths` 已含完整 param block 之 invocation。
- Mitigation: `-AutoRestoreLegacy` 採 `[switch]` 型別 + `= $false` default（與既有 `-AutoRestore` 一致）；不採 ValidateSet 約束；param 順序 append 至 block 尾（不重排既有）；coding 後立即跑 `pwsh -File artifacts/scripts/Invoke-CodexReview.ps1 -DryRun -DiffSource HEAD` smoke 確認 forward 正常。
- Severity: non-blocking

### R3: helper function scope 與 invocation 順序錯誤導致 wrapper script execution 失敗

- Risk: PowerShell 之 function 必須在 invocation 之前 define；3 helper 若放錯位置（如放於 main loop 之後）即 script 執行時 `Save-PreDispatchState : The term ... is not recognized` 致 wrapper exit 1 + 全 dispatch flow 破壞。
- Trigger: ps1 file 之 function 定義位置不對（在 `Save-PreDispatchState` 之 invoke point 之後）；或 function 名 typo（`Save-PreDispatchState` vs `Save-PrePreDispatchState`）。
- Detection: smoke (i)~(iv) 任一執行時 wrapper console 印 `not recognized` 或 unhandled exception；coding 階段以 `pwsh -NoProfile -File <wrapper> -Prompt "test"` 之 quick smoke 在 first edit 後立即 verify。
- Mitigation: 3 helper 以 `# region TASK-1059 helpers` 註解區塊集中於 param block 之後 / main loop 之前；以 `Get-Command Save-PreDispatchState` 在 ps1 中（debug-only 段）斷言 function 已定義；coding 採 first edit + immediate smoke 之 incremental pattern 而非全改後再驗。
- Severity: non-blocking

### R4: template/ 鏡像 SHA-256 不一致觸發 guard_contract_validator failure

- Risk: 5 對檔之 byte-identical 鏡像在 PowerShell loop 中誤遺漏，致 `guard_contract_validator.py` 報 SHA mismatch 致 exit 1 致 AC-12 fail。
- Trigger: PowerShell loop 之 path mapping 錯誤（如 root path 直接 prepend `template/`，但 EXACT_SYNC_FILES 之 entry 含 root-relative 路徑）。
- Detection: 鏡像後立即跑 `python artifacts/scripts/guard_contract_validator.py`；mismatch 立即 `Get-FileHash` 雙端輸出對照定位。
- Mitigation: 鏡像 loop 之 path mapping 採 EXACT_SYNC_FILES 名單之每 entry 直接 `Join-Path 'template' $entry`；loop 結束後必執行 `Get-FileHash` 雙端比對輸出 0 mismatches 之 console 確認；不 trust loop 之內部行為，以最終 hash 為驗收。
- Severity: non-blocking
