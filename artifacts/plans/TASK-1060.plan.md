## Risks

R1
- Risk: PowerShell quoting 對 `:(exclude)<dir>/` pathspec 字面值之解讀偏離預期，致 git.exe 收到 mangled 字串、stash 行為錯誤（如 `:` 被視為 scope operator、`(` `)` 被視為 grouping）。
- Trigger: wrapper 在 PowerShell 中以 double-quoted 或 unquoted 方式傳 pathspec；或 `$stashArgs` array 在 `& git` invocation 時被 PowerShell 自動 join 而觸發 re-parse。
- Detection: pytest 之 C-1 case `tmp_repo` 中 `artifacts/tasks/TASK-fake.task.md` 在 dispatch 期間消失（被 stash），即 exclusion 未生效；或 wrapper console 印 `git: 'unknown pathspec' / 'pathspec '..' did not match any file'`；或 `git stash list` 之 entry 顯示「stash includes lifecycle」。
- Mitigation: pathspec 字面值一律以 single-quoted PowerShell string（如 `'`+`':(exclude)artifacts/tasks/'`+`'`）構建並 append 至 `$stashArgs` array；以 splatting `& git $stashArgs` invoke 而非字串 concat；coding 階段以 `pwsh -NoProfile -c "& git stash ... | Out-Host"` 之 first-edit smoke 立即驗證；若實機 quote 仍失敗，改用 `--pathspec-from-file=<file>` + temp file 方式（per `git stash push --help` 之 `--pathspec-from-file` 選項，已在本機 usage line 確認支援）。
- Severity: blocking

R2
- Risk: `Save-PreDispatchState` 經 exclude 後若 working tree 為空集（per smoke-B），既有 fallback 路徑（`git stash list --max-count=1 | Select-Object -First 1` 之第一行）會誤拾 user 既有 stash entry（pre-existing stash@{0}），致 wrapper 後續 `Pop-PreDispatchState` 對非本次 dispatch 之 stash 執行 pop，破壞 user 之 stash stack。
- Trigger: dispatch 啟動前 user repo 已有 `git stash list` 非空；本次 dispatch 之 working tree changes 全為 lifecycle（被 exclude 後 stash 不建立）；wrapper 既有「`git stash list --max-count=1` 取 first line」邏輯讀回 user 既有 stash 之 ref。
- Detection: pytest 之 C-3 case 在 baseline commit 前以 `git stash push -m "user pre-existing"` 建一 stash → 跑 wrapper（lifecycle-only changes）→ assert (a) wrapper 不誤拾 user stash；(b) user stash list 仍含原 entry；或 wrapper 印 `[GUARD] Pre-dispatch: working tree clean; no stash needed.` 而非 stash ref。
- Mitigation: `Save-PreDispatchState` 在 stash invoke 後改以 stash msg 字面值（`TASK-1057 pre-dispatch <ts>`）對 `git stash list` 之全 list 做 string match；僅當第一行 `On <branch>: TASK-1057 pre-dispatch <ts>` 完全匹配時才 return ref，否則 return `$null`（per research C-6 之既有 fallback 路徑強化版）；coding 階段以新增 pytest C-3 case 立即驗證 user-pre-existing-stash 不被誤拾。
- Severity: blocking

R3
- Risk: pytest 新增之 wrapper case 在 cross-platform CI（Linux / macOS）跑時，`tmp_repo` 之 `wiki/README.md` 修改 + `git stash push` 之 line ending 警告（`LF will be replaced by CRLF`）觸發 stderr 雜訊使 assertion 失敗；或 fake exe 之 `.cmd` shim 在 POSIX 不可執行致 wrapper 拋 `git: command not found`-style error。
- Trigger: pytest 在無 `pwsh` 之 POSIX 環境跑 → `_powershell_exe()` 已 skip（per conftest.py）；但若 POSIX 有 `pwsh` 安裝（如 Linux pwsh），fake exe 之 shim 路徑分歧（POSIX `#!/usr/bin/env sh`，Windows `.cmd`）可能與 Git for Windows 之 line ending normalization 衝突。
- Detection: CI log 顯示 fake exe shim 找不到 / wrapper exit 非 0 / stderr 之 line ending warning 觸發 case assertion 失敗；或 pytest skip 訊息為 `PowerShell unavailable`（per existing conftest.py）已生效。
- Mitigation: 新增 case 採既有 `tmp_repo` fixture（baseline 已含 `wiki/README.md` 之 600 行 `Changed for review.`，line ending 早已存在）；assertion 不依賴 stash msg 之 console output，改檢 disk file existence + exit code + fake exe call log（per existing pattern）；POSIX `pwsh` 環境之 git.exe 不存在時 case 直接 skip（既有 conftest.py 已處理）；coding 階段以 Windows + bash 雙環境跑 pytest 確認 baseline 不退步。
- Severity: non-blocking

R4
- Risk: PR-029 之 `must_contain_all` 追加 `IncludeLifecycleInBaseline` 字面值後，`prompt_regression_validator.py` 對既有兩 wrapper 之 ps1 內容 grep 該字串失敗，致 PR-029 fail 阻塞 closure。
- Trigger: ps1 修改未真正寫入 `IncludeLifecycleInBaseline` 字面值（如 `-Include` typo、或被 PowerShell parser 自動 alias 改寫）；或 `template/` 鏡像未同步致 `--root .` 模式對 template path 也驗時 fail。
- Detection: `python artifacts/scripts/prompt_regression_validator.py --root .` 報 `PR-029 FAIL: file artifacts/scripts/Invoke-CodexAgent.ps1 missing required substring 'IncludeLifecycleInBaseline'`。
- Mitigation: ps1 之 param block append 採 `[switch]$IncludeLifecycleInBaseline = $false` 之完整字面值（無 alias / 無縮寫）；coding 階段以 `Select-String 'IncludeLifecycleInBaseline' artifacts/scripts/Invoke-CodexAgent.ps1` 雙端驗證；template/ 鏡像 step 5.1 完成後再跑 prompt_regression_validator。
- Severity: non-blocking
