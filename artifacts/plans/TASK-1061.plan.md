## Proposed Changes

### CP-1: `CITATION_PATTERN` 放寬（雙副本同步）

兩處 `CITATION_PATTERN` 改為以下 alternative-branch 結構（per research §C1-C4）：

```python
CITATION_PATTERN = re.compile(
    r"(?:"
    r"https?://\S+"
    r"|`gh api [^`]+`"
    r"|`[^`\n]+\.(?:md|json|txt|py|ps1|csproj|ini|toml|yml|yaml|cfg|sh)[^`\n]*`"
    r"|[（(](?:[Ss]ource:\s*)?[^)）\n]*?[A-Za-z0-9_./\\-]+\.(?:md|json|txt|py|ps1|csproj|ini|toml|yml|yaml|cfg|sh)(?::\d+)?[^)）\n]*[)）]"
    r"|\b[A-Za-z0-9_./\\-]+\.(?:md|json|txt|py|ps1|csproj|ini|toml|yml|yaml|cfg|sh)(?::\d+)?\b"
    r")",
    re.IGNORECASE,
)
```

設計要點：
1. **既有 3 條 branch（URL / `gh api` / backtick-wrap）字面保留**：放寬為 superset，不破壞 backwards compat（per research §C1）。
2. **擴 ext list 至 `md|json|txt|py|ps1|csproj|ini|toml|yml|yaml|cfg|sh`**：6 ext 補白名單（per research §C2）。
3. **新增 ASCII / 中文括號 wrap branch**：`[（(]...[)）]` 對稱 char-class；內可含可選 `Source:` 前綴（case-insensitive）；強制至少含 1 個 `path.ext` token；非貪婪 `[^)）\n]*?` 防跨行（per research §C3）。
4. **新增裸 `path:line` branch**：`\b...\b` word boundary 防 prose 偽匹配；ext 限白名單；可選 `:digit+` 行號（per research §C4）。
5. **alternative branch 順序**：specific（含明確定界符）→ general（裸路徑），避免歧義；per research §C3 第 3 原則。

- Severity: blocking

R2
- Risk: 既有 PASS research / task / status artifacts（含 8 條歷史 task fixture + RT-001/003/004 sample fixture）在新 superset regex 下因「裸 path:line」branch 之 `\b...\b` 邊界偽匹配 prose 文字（如數字版本號 `3.14`、日期 `2026.05.08` 之 ext 字尾被誤判為 path token），導致原本應失敗之 case 變 PASS（false negative）或無關案例之 trigger 被誤啟
- Trigger: prose 中出現符合 `\b\w+\.\w{1,10}\b` 但非實際路徑之文字（如 `Python 3.14`、`v1.2.3`、`section 5.7`）
- Detection: 新增 `test_citation_pattern_rejects_prose_period`（CP-4 第 5 條）assert prose period 不匹配；8 條歷史 task `guard_status_validator.py --task-id <id>` 仍 [OK]（regression smoke）；RT-001/003/004 之 fixture 結果與 baseline 一致
- Mitigation: 裸路徑 branch 強制 ext 限白名單（不接 `2.3` / `3.14` 因 ext 為 `3` / `14` 不在 list）；若仍有偽匹配，於 ext list 末加更嚴格約束（如限 `[A-Za-z]{1,10}` 而非 `[A-Za-z0-9]{1,10}`）；blocking 升級若回歸測試失敗 ≥ 2 條
- Severity: non-blocking

R3
- Risk: 新 `CITATION_PATTERN` 之裸路徑 branch `\b[A-Za-z0-9_./\\-]+\.(?:ext-list)(?::\d+)?\b` 在長輸入（如 200+ char list item 含多 path-like token）發生 catastrophic backtracking，使 validator 於大型 research artifact 上掛起或超時
- Trigger: research artifact 有單條 Confirmed Facts item 含 5+ 路徑 token 且後綴非 ext list（如 `path/to/x.notavalidext path/to/y.alsoinvalid`），引擎於 ext list mismatch 之 fallback 觸發 O(N²) 或更嚴重複雜度
- Detection: validator 對 2KB+ test artifact 跑時 wallclock > 1 秒（CP-4 之 unit test 加 timeout=0.5s subTest）；OWASP ReDoS guidance（research §C3）；CI runner 之 timeout
- Mitigation: 採 `[A-Za-z0-9_./\\-]+` 而非巢狀量詞（per research §C3 原則 1）；ext list 為 alternation（O(K)）非 nested quantifier；於 CP-4 加 stress test：500 char input 含 10 偽路徑 token assert match time < 0.1s；若 perf 不達，回退至 atomic group `(?>...)` 或縮 ext list
- Severity: non-blocking
