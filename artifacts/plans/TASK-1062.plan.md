- 1.1 **新增 `Get-LifecycleUntrackedSnapshot` helper**：列舉 7 lifecycle dirs 內既存 untracked 檔（`git ls-files --others --exclude-standard -- artifacts/tasks/ artifacts/research/ artifacts/plans/ artifacts/code/ artifacts/test/ artifacts/verify/ artifacts/status/`）；逐 path 跑 `git hash-object -w <path>` 取 SHA-1 並寫入 .git/objects（`-w` flag 之關鍵：使 restore 階段可用 `git cat-file blob <hash>` 取回原內容）；return hashtable `@{ path1 = sha1_hex; path2 = sha1_hex; ... }`。

- 1.5 **`Restore-PostDispatchDelta` 擴充**：簽名追加 `[hashtable]$LifecycleSnapshot = @{}` 參數；對每 violation P，若 `$LifecycleSnapshot.ContainsKey($P)` → 從 git blob 取回原內容（`git cat-file blob $LifecycleSnapshot[$P] | Out-File -FilePath $P -Encoding utf8`）；否則採既有 `git ls-files --error-unmatch` 分支（tracked → checkout HEAD；untracked → Remove-Item）。
- 1.6 **Pop-PreDispatchState 不變**。雙 wrapper 字面同步；helper 命名 / 順序 / log 字串對齊。

## Risks

R1
- Risk: PowerShell function 之 `return @{...}` 與 helper 內部 `Write-Host` / git CLI 之 implicit output 混合，致 caller 拿到 `Object[]` 而非 hashtable，`.StashRef` / `.LifecycleUntrackedSnapshot` 為 `$null`。整個 Bug A fix 失效於 dispatch entry。
- Trigger: `Save-PreDispatchState` return 之 hashtable 與 helper 內部 `& git stash push ... 2>&1 | Out-Null` 之 stdout 殘留 / `Write-Host` 之 console output 共構為 PowerShell function 之多元 output stream；caller 之 `$preDispatchState = Save-PreDispatchState ...` 接到 array。
- Detection: Coding 階段 first-edit 之 `pwsh -NoProfile -c '. <wrapper>; (Save-PreDispatchState).GetType().Name'` 不等於 `PSCustomObject`；或新增 pytest C-1 case 印 `wrapper console output` 含 `LifecycleUntrackedSnapshot is null` 字串（assertion 失敗）；或 `stash 後印 .StashRef` 為 `$null`。
- Mitigation: helper return 改用 `[PSCustomObject]@{...}`（避免 hashtable 之 implicit array 行為）；helper 內 git CLI 之 stdout 一律 `2>&1 | Out-Null` 屏蔽；helper 內 `Write-Host` 顯式輸出 console（`Write-Host` 走 host stream 不污染 function output）；first-edit 跑 `pwsh -NoProfile -c` 之 .GetType().Name 確認 + 新增 micro-smoke 寫至 code artifact。
- Severity: blocking

R2
- Risk: gemini CLI 之 stdin 接收行為與 codex 不同：(a) 不支援 stdin（需 `-p`）；(b) 支援但需顯式 `-p -`；(c) 支援且 unconditional 讀 stdin。case (a) 致 sub-agent 收空 prompt + 9 retry × tier 全 deterministic 失敗；case (b) 致 wrapper 完全不工作。
- Trigger: gemini.cmd 之 batch wrapper / node argv 對 stdin pipe 不支援；本機 `gemini --help` 未在 research 階段直接驗證之 UNVERIFIED-1 風險。
- Detection: coding 階段 first-edit 之 `'test prompt`nwith newline' | gemini -m gemini-3.1-flash-lite-preview --approval-mode=yolo` PowerShell smoke 之 stdout 為 「No prompt provided」/「stdin not supported」/「awaiting input」；或 sub-agent response 不對應 prompt 內容（如回 `請提供任務`）。
- Mitigation: first-edit 必須先跑 micro-smoke；smoke 未通過即停手升級 decision artifact，記錄 gemini stdin 不可用 + 回退方向（如維持 Gemini wrapper line 225 `-p $Prompt` 但加防截斷檢查 / 或 escalate 至 task §OOS 之上游修復路徑）；wrapper 不在本 task 引入 dual-path 分支（per task §OOS minimal-change 原則 + R2 此 risk 即 fail-safe 之觸發點）。
- Severity: blocking

R3
