## Proposed Changes

### CP-1: `artifacts/scripts/scaffold_downstream.py`（greenfield generator）

CLI（argparse）：
- 必：`--target`（新 repo root）、`--project-name`、`--repo-name`、`--project-summary`
- 選：`--owner`（GitHub owner，供 `{{ORG}}`；預設 = `--upstream-org`）、`--upstream-org`（供 `{{UPSTREAM_ORG}}`；預設 = `--owner`）、`--author`（供 `{{AUTHOR}}`；預設 = `--owner` 或 `--project-name`）、`--year`（供 `{{YEAR}}`；預設 = `datetime.now().year`）、`--topics`、`--git-init`、`--dry-run`、`--force`、`--template-root`（預設 = 本 repo template/）

替換 map（**只含實例化鍵**）：
```
{{PROJECT_NAME}} ← project_name
{{REPO_NAME}}    ← repo_name
{{REPO}}         ← repo_name
{{ORG}}          ← owner（或 upstream_org）
{{UPSTREAM_ORG}} ← upstream_org（或 owner）
{{AUTHOR}}       ← author（或 owner / project_name）
{{YEAR}}         ← year
```
per-task 鍵（`{{TASK_ID}}`/`{{NNNN}}`/`{{TITLE}}`/`{{N}}`/`{{INCIDENT_ID}}`）**不入 map**，自動倖存。

流程（greenfield）：
1. 驗 `--target` 不存在或空（非空且無 `--force` → exit 2）。
2. `shutil.copytree(template_root, target)`（含 .github/.obsidian/.claude 等 dotdirs）。
3. **scoped substitution**：遍 target 之文字檔，逐檔讀；**排除** basename 匹配 `test_*.py` 之檔（fixture 保護）與二進位檔；其餘檔以 map 之 7 鍵逐一字面替換後寫回（僅當有變動）。
4. **post-substitution check**：再遍非排除檔，以 regex `\{\{(PROJECT_NAME|REPO_NAME|REPO|ORG|UPSTREAM_ORG|AUTHOR|YEAR)\}\}` 掃殘留；若有 → 印各檔殘留鍵並 exit 3。
5. 斷言 target 無 `.council-forge-source-repo`（template 本無；防呆）。
6. 呼 `update_repository_profile.py --project-name ... --project-summary ... [--topics ...] --profile-path <target>/.github/repository-profile.json`（subprocess）。
7. `--git-init` 時於 target `git init`（部分 guard 需 git）。
8. 跑 downstream guards（subprocess，cwd/--root = target）：`guard_contract_validator.py --root <target>`、`prompt_regression_validator.py --root <target>`；蒐 exit code。
9. 印結構化報告（copied file count、substituted file count、guard 結果）；任一 guard fail → 整體 exit≠0（但檔留存供檢）。
`--dry-run`：行 1-5 之模擬（印將 copy/substitute 者），不寫、不跑 guard。

實作守則：`def main()`、argparse、`if __name__` 皆 `.coveragerc` `[report] exclude_lines` 所免；filesystem 操作以 `pathlib` + `shutil`；UTF-8 讀寫；二進位偵測以嘗試 decode 或副檔名白名單。

### CP-2: Coverage——逼近 100%（**不** omit），並納入 CI cov 跑列

依主公「coverage 盡可能 100%」之諭：`scaffold_downstream.py` **不入 `.coveragerc` omit**（與既有 CLI-runner omit 之權宜不同），而以可測設計 + in-process 單元測試達近 100%。為使 CI 之 `--cov-fail-under=90` 真實計入其覆蓋，於 `.github/workflows/workflow-guards.yml` 之 Unit Tests step（line 40）pytest 跑列**加** `artifacts/scripts/test_scaffold_downstream.py`（該檔不可入 `test_guard_units.py`，因後者在 EXACT_SYNC 且會把 scaffold 測試引散播至無此 script 之下游）。`workflow-guards.yml` 不在 EXACT_SYNC（root-only）。`.coveragerc` 之 `[report] exclude_lines` 已免 `def main(`/argparse/`if __name__`，故 CLI glue 不計；其餘邏輯行須由測試覆蓋。**目標**：scaffold_downstream.py line coverage ≥ 95%（趨近 100%），整體 cov gate ≥ 90 維持綠。凡真正不可測之 I/O 行（如極端 OS 例外）以 `# pragma: no cover` 並附一句理由。

### CP-3: `artifacts/scripts/test_scaffold_downstream.py`（**in-process** 單元測試，趨近 100%）

為取真實 coverage credit，測試**import** `scaffold_downstream` 並**直呼其函式**（in-process，非 subprocess 子程序——子程序之行不計 cov）。以 `tmp_path` + 合成 mini-template fixture（數檔含實例化鍵、per-task 鍵、與一 `test_*.py` fixture 檔）為主，避免每測 copy 龐大真 template/。

純函式單元（全分支）：
- `build_substitution_map`：含/缺各選 arg 之預設鏈（owner→upstream_org→author、year 預設）；斷言 7 鍵齊備。
- `should_substitute`：`test_*.py`→False、二進位→False、一般 .md/.json/.py→True。
- `substitute_text`：替實例化鍵、保 per-task 鍵不動。
- `find_leftover_instantiation_keys`：有/無殘留二態。
編排層（in-process，tmp）：
- `copy_template` + `apply_substitutions`：對合成 mini-template 跑 → 斷言實值落、`{{TASK_ID}}` 倖存、`test_*.py` fixture 之 `{{PROJECT_NAME}}` 未被替。
- `run(argv)` happy path（mini-template，`--template-root` 指 fixture，guard step 以 `monkeypatch` 替 `subprocess.run`/`run_downstream_guards` 為 stub 回 0）→ exit 0、target 結構正確、無 `.council-forge-source-repo`。
- `run(argv)` 負向：`test_post_check_catches_leftover`（缺鍵 → exit 3 列殘留）、`test_refuses_nonempty_target`（非空無 `--force` → exit 2）、`test_dry_run_writes_nothing`（`--dry-run` → 未寫）。
- `run_downstream_guards` 之呼叫點：以 monkeypatch `subprocess.run` 記錄被呼叫之 argv（覆蓋該行），不實跑真 guard（真 guard 之 end-to-end 留 P3 dry-run）。
此檔加入 CI cov 跑列（CP-2），與 `test_guard_units.py`/`test_security_scans.py` 同步計 cov。

## Risks

R1
- Risk: over-substitution——誤替 per-task 鍵或 test fixture，致下游 `docs/templates/` 或 test_*.py 損壞
- Trigger: 替換 map 含 per-task 鍵，或未排除 test_*.py
- Detection: test_greenfield_happy_path 斷言 `{{TASK_ID}}` 與 test fixture `{{PROJECT_NAME}}` 倖存；人工抽查
- Mitigation: map **只含 7 實例化鍵**；basename `test_*.py` 排除；per-task 鍵永不入 map
- Severity: blocking

R2
- Risk: 實例化鍵殘留（user 漏供 arg）→ 下游有字面 `{{ORG}}` 致 repo 無效
- Trigger: 某實例化鍵存於 template 而未供對應 arg/預設
- Detection: post-substitution regex 掃描
- Mitigation: step 4 post-check 殘留即 exit 3 列出；arg 預設鏈（owner→upstream_org→author）減漏
- Severity: blocking

R3
- Risk: coverage 未達近-100%（主公明諭之目標），或 cov gate `--cov-fail-under=90` 破
- Trigger: scaffold_downstream.py 入 source 而 in-process 測試覆蓋不全（含 subprocess 呼叫點、例外分支），或 test 未納入 CI cov 跑列
- Detection: `pytest test_guard_units.py test_security_scans.py test_scaffold_downstream.py --cov --cov-report=term-missing --cov-fail-under=90`；檢 scaffold_downstream.py 之 missing lines
- Mitigation: 可測設計（純函式分離、`run(argv)` 回 exit code、guard-run 為可 monkeypatch 之函式）；in-process 測試覆全分支；CP-2 將 test 納 cov 跑列；term-missing 檢殘漏補測；真不可測之 OS 例外行以 `# pragma: no cover` + 理由（即「明確不可為」之例外）
- Severity: blocking

R4
- Risk: contract guard 破——新增 source-only 檔觸 EXACT_SYNC 或 root-strictness
- Trigger: 誤以為須鏡像 template/，或 contract 有「全 script 須同步」檢查
- Detection: `guard_contract_validator.py --root .`（母本 source mode）
- Mitigation: 已查 EXACT_SYNC 為明列清單（不要求 root 全檔入 template）；scaffold/test 不列入、不入 template/；新增後即驗 contract [OK]
- Severity: blocking

R5
- Risk: 下游 guard 於 scaffolded target 失敗（git 依賴、seed task、Windows 路徑/編碼）
- Trigger: guard_contract/prompt_regression 於 copy 後之 target 報錯（如 git-backed 檢查、CRLF、dotdir copy）
- Detection: P3 throwaway dry-run 實跑 downstream guards
- Mitigation: `--git-init` 供 git 依賴；UTF-8 顯式；`shutil.copytree` 處理 dotdirs；P3 為實證關卡，失敗則據訊息修 generator（非擴 scope）
- Severity: non-blocking
