## Proposed Changes

### CP-1: docs/ssdf-mapping.md（單一事實源，machine-parseable）
固定 6 欄表：`| Practice | Title | Status | Mechanism | Evidence | Gap/Waiver |`，每列一 practice，19 列（SSDF v1.1，無 PW.3）。
- Status 詞彙：`covered`（有實機制 + 可 resolve mechanism&evidence）｜`partial`（機制存在但繫於實作者或不全）｜`gap`（無機制）。
- covered/partial：**Mechanism 與 Evidence 皆**為 repo-relative ref（`path`/`path#anchor`/`path:line`），指既有檔/錨。
- gap：Gap/Waiver 為 `docs/ssdf-roadmap.md#<階-anchor>` 或 `decision:TASK-NNNN`；**對應之 waiver 目標須含結構化 marker `SSDF-Gap-Waiver: <practice_id>`**。故 P8-A 於 `docs/ssdf-roadmap.md` 各 owns-gap 之階 section（P8-B 之 PW.4/RV.1、P8-C 之 PW.7/PS.2…）**補該 marker**，令 roadmap 成結構化 waiver registry（小幅 additive）。
- **標頭聲明**（誠實侷限）：① status 詞彙；② canonical 出處 NIST SP 800-218 v1.1 + 核實日 2026-06-07；③「**本檔校 mapping 完整性、非 SSDLC 認證**；validator 只機器校 ref resolvability，**質性適足由雙對抗審查 + human-review ack 把關**」。

### CP-2: ssdf_mapping_validator.py（source-only, read-only）
- `CANONICAL_PRACTICES`（19 frozenset；docstring 引 NIST SP 800-218 v1.1 + 核實日 2026-06-07 + 註 PW.3 v1.1 移除）。
- `parse_mapping(path)`：解析表為 {practice: row}（容錯略過分隔/空列；畸形列具名報錯）。
- `resolve_ref(ref, repo_root)`（**統一 repo-bound resolver**，mechanism 與 evidence 共用）：
  - 拒 `cmd:`/非-path/absolute/含 `..` → unresolved；
  - split `path[#anchor][:line]`；path 須存在於 repo_root 下（normalize 後仍在 root 內，防 traversal）；
  - `#anchor`：**僅**匹配檔內 markdown **標題之 slug**，以 `slugify()` 計（見下），**不接受寬鬆字面/子字串/regex 比對**（免誤匹配 body 文本致假 resolve；gemini v5 [high]），否則 unresolved；
  - `:line`：須正整數且 ≤ 檔行數，否則 unresolved。
- `slugify(heading)`（**明定確切演算法，不託「GitHub 式」之模糊；gemini v6 [high]**）：① strip 前後空白；② ASCII case-fold 為小寫（Unicode/CJK 字符原樣保留，不轉換）；③ 移除非 word-char/非空白/非連字號之字符（剝 ASCII 標點；保留 Unicode 字母含 CJK）；④ 連續空白→單一連字號；⑤ 連續連字號→單一。**重複標題消歧**：同檔內計全標題 slug 集時，依文件序對重複者加數字後綴 `-1`、`-2`…（與 GitHub 同序）。validator 自目標檔之**實際標題**建 slug 集，author 之 anchor 須與之相符。算法 + 消歧落 docstring。
- `resolve_waiver(ref, repo_root, practice_id)`（**全對稱結構化 marker：二形式皆須明示宣告 `SSDF-Gap-Waiver: <practice_id>`，棄非結構化 mention 啟發式；codex v7/v8 [high]、gemini v6 [medium]**）：
  - `docs/ssdf-roadmap.md#anchor`：檔存在 + anchor 為真標題 slug（走 slugify 檢）+ **該 anchor 之 section 內**（自該標題至下一**同級或更高級**標題之區段；section-scoped）**含結構化 marker `SSDF-Gap-Waiver: <practice_id>`**（非僅 practice_id 偶現之 incidental 文本）；
  - `decision:TASK-NNNN`：`artifacts/decisions/TASK-NNNN.decision.md` 存在 + 含結構化 marker **`SSDF-Gap-Waiver: <practice_id>`**；
  - 二者 unresolved（無 marker / practice_id 不符 / draft 無關）→ violation。
- `validate(rows, repo_root)`：(A) canonical 完整性（== CANONICAL_PRACTICES）；(B) status 合法；(C) covered/partial 之 **Mechanism 與 Evidence 皆 resolve_ref**（任一 unresolved→violation）；(D) gap 之 Waiver `resolve_waiver(..., practice_id=該列 practice)`（unresolved→violation）。
- 報告：恆計 covered 數 + 列 partial IDs 與 gap IDs（markdown+json）。
- **exit 語意**：`0`=結構有效**且全 19 covered**；`3`=結構有效**但有 open items**（>=1 partial 或 gap）；`2`=完整性違規；`1`=usage/IO。輸出文案 valid-with-open-items 明曰「open items — N partial: [...], M gaps: [...]」；**絕不**裸「conformant」/「full coverage」當有 open items。
- CLI：`--mapping`（預設 docs/ssdf-mapping.md）、`--json`。`main` `# pragma: no cover`。

### CP-3: tests
`test_ssdf_mapping_validator.py` fixture（全-covered→exit 0、有 partial 零 gap→exit 3、有 gap→exit 3、各式違規），涵：
- 完整性（缺/冗/未知）、status 非法；
- **resolver 正**：covered 之 mechanism+evidence 解析 `path`/`path#真anchor`/`path:在範圍line`；waiver 二形式皆解析含 `SSDF-Gap-Waiver: <practice_id>` marker 者——roadmap#（marker 於 anchor section 內）與 decision:（marker 於檔內）；
- **slugify edge-case 測**（gemini v6 [high]）：標題含 ASCII 標點、Unicode/CJK 字符、多/前後空白、**重複標題需後綴 `-1`/`-2`** → slug 計算正確且 anchor 相符/不符各驗；

- exit 0/2/3/1 各路徑、parse 畸形列、報告計數（covered 數 + partial IDs + gap IDs）、CLI（json/bad path）。
