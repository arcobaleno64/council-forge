4. **註 417-419 更新**：明「分類掃 STDERR（transient 於 exit-0 漏時現於 stderr），**不掃 STDOUT 答案**，杜 review 內容誤觸；exit-code 為 source-of-truth」。

## Risks

> 事前驗屍（Premortem）：Risk / Trigger / Detection / Mitigation / Severity。

R1
- Risk: stderr-only 漏真 transient——若 codex CLI 偶將 transient 錯印於 STDOUT 並 exit 0（須 codex 違其 exit-code 契約），stderr-only 匹配漏之、誤判 success，掩真錯。
- Trigger: codex CLI 非標準地將 API/transport 錯寫 stdout 而非 stderr，且 exit 0。
- Detection: 實作層雙審審此取捨；CP-3 (ii) 測 exit0+stderr-pattern 仍 retry（次級網）。**誠實界（D2）**：本 repo **無** codex CLI 各版 transient 串流行為之可復現證據（本機實為 codex-cli 0.137.0，非假設之 0.128）——故**不宣稱「transient 必走 stderr」為已驗證**，唯列為下方 accepted residual。**已驗證者僅一**：codex 親跑實證 PowerShell `2>&1` 於 exit 0 與 exit 1 皆保 native stderr 為 `System.Management.Automation.ErrorRecord`（故 `$outText`/`$errText` 分流技術可行）。
- Mitigation: **exit-code 為 source-of-truth**（exit≠0 一律 retry，涵絕大多數真錯）；**stdout-scan 根本歧義**——codex review 合法引/論「429」與 codex 真吐「429」**文本同形不可辨**，故掃 stdout 必致觀測到之 false-positive，stderr 為唯一可靠之次級網；**「exit-0-stdout-only-transient」列 explicitly ACCEPTED RESIDUAL**（須 codex 違 exit-code 契約 + 任何 string-scan 皆不能辨之，非本修可解；較現況之 false-positive 嚴重性低且未觀測）。
- Severity: blocking
