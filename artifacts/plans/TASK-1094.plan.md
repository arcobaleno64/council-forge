## Scope

修 release-integrity manifest 跨平台不可復現：令 `snapshot_manifest.py` 之 content-address 對**文字檔整檔讀入、正規化行尾（CRLF/CR→LF）後雜湊**（**整檔讀**杜 chunk-boundary 誤拆〔gemini〕；**強判別** text⇔UTF-8-decodable 且無 NUL、否則 binary 原始 bytes〔codex〕），使 manifest 與 working-tree 行尾組態無關；**canonicalization acquirer-可見**——manifest 加 `digest_canonicalization` 欄（schema `@2`）、verify fail-closed、三 acquirer 文載規約、`release_gate.py`（＋EXACT_SYNC 對偶）結構核欄〔codex R9〕；輔 root `.gitattributes`（`* text=auto eol=lf`）淨化；重生 manifest；補測鎖不變量。`snapshot_manifest.py` source-only；不動四下游。

## Decision Points（雙審已裁）

> **round-1 裁定（2026-06-12）：codex ＋ gemini 皆裁 A+B 為正解**——A（content-address 正規化）為跨平台/acquirer 復現之正源修，B（`.gitattributes`）為衛生；R7 行尾正規化**不弱化** tamper 偵測（文字治理 SSOT 之語義 payload 為內容非行尾）；NUL-sniff 妥（然見下 R10 強化）；下游 follow-up、coverage、blast-radius 皆 approved。下列三案陳述保留為決策記錄。

- **A — 於 content-address 正規化行尾（採為主）**：改 `sha256_file`（或新 `digest_file`）對文字檔 CRLF/CR→LF 後雜湊。**正本清源**——直修 snapshot_manifest 自誓「byte-reproducible」之偽（其只正規化路徑未正規化行尾）；manifest 遂於任何平台/working-tree 組態生成皆同。代價：須辨文字/二進位（NUL-sniff）、須 acquirer 同法復現（docstring 載明）、改動安全閘碼（故加實作層雙審）。
- **B — `.gitattributes eol=lf`（採為輔）**：釘 working tree 為 LF。**衛生**——淨化未來 diff、令 Windows working tree 亦 LF。然**單靠 B**則 snapshot_manifest 仍雜湊原始 bytes、其 reproducibility 仍倚 working-tree 組態（someone bypass eol=lf 即復裂），未修「theater」本病。
- **採 A+B 之由**：A 為正源修（必要）、B 為衛生（互補、低風險）；A 使 manifest 真跨平台、B 使 repo 行尾一致。**反對意見預期**：(i) 「A 弱化 tamper 偵測（CRLF-flip 不察）」——答：文字治理 SSOT 之行尾無語義/安全 payload，content-address 之旨在 acquirer 跨平台復現，原始-byte 雜湊正違此旨，故正規化乃**正確語義非弱化**（R7、docstring 載）；(ii) 「B 已足、A 過度」——答：B 倚組態、未修自誓之偽，且 A 之增量小（一函式＋NUL-sniff）。**若二審裁 B-only 足**，則去 A、僅 `.gitattributes`＋renormalize＋重生 manifest（snapshot_manifest 不改）——亦可解 CI，惟保留 working-tree 依賴。**懇二審明裁。**

## Proposed Changes

1. **digest 行尾正規化（A）**：`snapshot_manifest.py` 之 file-digest——**整檔讀入 bytes**（`path.read_bytes()`，非逐 65536-chunk）杜跨界 `\r\n` 被裸-CR 規則誤拆為 `\n\n`（gemini blocking：chunk-boundary CRLF split 破決定性）；template 治理檔小而有界，整檔讀安全。**強判別（codex blocking）**：text ⇔ 整檔 **UTF-8 可 decode 且無 `\x00`**；否則 binary（雜湊原始 bytes、不正規化，fail-closed——含無早-NUL 之二進位）。文字檔 `b"\r\n"→b"\n"`、`b"\r"→b"\n"`（裸 CR）後雜湊；二進位原始 bytes。generate/verify 共用單一 digest 函式。
1b. **canonicalization acquirer-可見（codex blocking）**：published manifest 加宣告欄位 `digest_canonicalization: "text-eol-lf-v1"`（schema bump `@1`→`@2`、向後容舊）；`verify` 重算時讀此欄、缺/不符即 fail-closed；更新 acquirer 文（`SECURITY.md`、`docs/security/release-signing.md`、`docs/templates/security/README.md` 之「acquirer 可重算 sha256」段）載明「文字檔行尾正規化為 LF 後雜湊、二進位原始 bytes」之復現規約。`release_gate.py` 結構驗證加容/核此欄（結構層、不重算 bytes）——**具體（gemini r2 nb）**：`SUPPORTED_SCHEMA_VERSIONS`（release_gate.py:49）由 `{"…@1"}` 增為 `{"…@1","…@2"}`（line 122 之 schema 檢續過）；`digest_canonicalization` 欄**僅對 @2 條件強制**（@1 不要求），杜下游拉新 template gate 而其 manifest 仍 @1 即破之相容性裂。
2. **`.gitattributes`（B）**：root 新增 `* text=auto eol=lf`；`git add --renormalize .`（object 已 LF，預期僅 `.gitattributes` 入 staged，無文字檔 churn；若有非預期 churn 先究）。
3. **重生 manifest**：碼改後 `python artifacts/scripts/snapshot_manifest.py generate --output .well-known/release-manifest.json`；驗本機（CRLF working tree）`verify` `[OK]`，且模擬 LF（temp LF 副本或 CI）算得同 root。
4. **補測**：`test_snapshot_manifest.py` 加 — (a) 同內容之 CRLF fixture 與 LF fixture 經 `compute_manifest` 得**位元相同** manifest；(b) **chunk-boundary `\r\n`（跨 65536 界）** 得同 digest；(c) **UTF-8-fail bytes → binary 原始-byte**（不正規化）、含 `\x00` → binary；(d) 裸 CR 正規化；(e) **canonicalization 欄缺/誤 → verify fail-closed**；維 snapshot_manifest 100% cov。`test_release_gate.py` 加 — `@1` 無欄過／`@2` 正欄過／`@2` 缺·誤欄 fail-closed（既有 @1 fixture 不破）。
5. **docstring**：Determinism 段增「文字檔（UTF-8-decodable 且無 NUL）行尾正規化為 LF 後雜湊（acquirer 須以同法復現、見 manifest `digest_canonicalization`）；二進位雜湊原始 bytes」。

## Risks

R1
- Risk: 行尾正規化誤施於二進位檔，將其內偶見之 `\r\n`／`\r` bytes 改寫，致 digest 失真、二進位完整性偽報。
- Trigger: 日後 template/ 加入二進位檔（圖片/字型/壓縮）；正規化無條件套於所有檔。
- Detection: 以含 `\x00` 且含 `\r\n` bytes 之二進位 fixture 測，比對其 digest 須等於原始-byte sha256（非正規化後）。
- Mitigation: digest 前**強判別**（text ⇔ 整檔 UTF-8 可 decode 且無 `\x00`；否則 binary）→二進位雜湊原始 bytes、僅文字檔正規化；今 repo 無追蹤二進位（`git ls-files` 證、text-only 不變量），強判別為未來 fail-closed 防（見 R10）。
- Severity: blocking

R2
- Risk: generate 正規化、verify 未（或反之），致 manifest 恆不符、verify 永紅。
- Trigger: 正規化只加於部分雜湊路徑。
- Detection: round-trip 測——`generate` 後即 `verify` 同 tree，於 CRLF 與 LF working tree 二者皆須 exit 0。
- Mitigation: 正規化置於**單一** `sha256_file`/digest 函式，`compute_manifest`（generate 與 verify 皆呼之）共用；無第二雜湊路徑。
- Severity: blocking

R3
- Risk: manifest 未重生、或於碼改前重生、或於未正規化之 CRLF tree 重生 → CI 仍紅。
- Trigger: 漏重生步、或次序顛倒。
- Detection: 本機 `verify` `[OK]` 且 LF 模擬（temp LF 副本/CI re-run）算得同 root；PR #14 CI release-integrity/validate 轉綠。
- Mitigation: 次序固定（先碼改→後 generate）；commit 前本機驗 CRLF working tree verify [OK]＋手算一文字檔之 LF-normalized sha256 與 manifest 該 entry 相符；push 後待 CI 綠方視竣。
- Severity: blocking

R4
- Risk: `.gitattributes` `* text=auto eol=lf` ＋ `git add --renormalize` 產非預期大量文字檔 churn（混入 commit），或誤改某檔行尾語義。
- Trigger: 套 .gitattributes 後 renormalize。
- Detection: `git diff --cached --stat` 核 staged——object 已 LF（`ls-files --eol` i/lf 證），renormalize 應為 object-level no-op，僅 `.gitattributes` 入 staged。
- Mitigation: renormalize 後 `git status`/`--cached --stat` 核；若除 `.gitattributes`＋manifest 外有文字檔變，先究（恐某檔 object 實非 LF）再決；commit 顯式路徑、不 `git add -A`。
- Severity: blocking

R5
- Risk: `snapshot_manifest.py`（現 100% cov、128 stmts）新增 branch（正規化/強判別/canonicalization）未測涵 → `validate` cov gate 紅（per-file 100% 期待）。
- Trigger: 加碼未補對應測。
- Detection: `pytest --cov` 之 snapshot_manifest per-file cov < 100%；CI validate 紅。
- Mitigation: 補測涵文字-正規化、二進位-原始、裸-CR 三 branch；本機 `pytest artifacts/scripts/test_snapshot_manifest.py --cov` 證 100% 方 commit。
- Severity: blocking

R6
- Risk: 四下游之 `.council-forge/release-snapshot.json` 同有 CRLF/LF 患（其亦 git repo、無 .gitattributes），本 task 不及 → 下游 release-integrity 將來同裂。
- Trigger: 下游 CI 啟 release-integrity 或 acquirer 跨平台驗。
- Detection: 下游同 recon（ls-files --eol / verify 跨平台）。
- Mitigation: 本 task 限解 council-forge 自身 CI 阻（避免疊床架屋、避免動四下游 push 面）；template/.gitattributes ＋下傳列**決策點/follow-up**（獨立 governed task，承 git-flow 最慎一級）；decision 誠實記此 known-residual。
- Severity: non-blocking

R7
- Risk: 行尾正規化「弱化」原始-byte tamper 偵測（純 CRLF-flip 之改動不為 manifest 所察），被視為削安全。
- Trigger: 審視 content-address 之 tamper-detection 完備性。
- Detection: 概念審——manifest 用途（PS.2.1 acquirer 跨平台完整性復現）vs 原始-byte 嚴格性之取捨。
- Mitigation: 文字治理 SSOT 之行尾無語義/安全 payload；content-address 之旨在 acquirer **跨平台可復現**，原始-byte 雜湊正使其不可復現（即此 bug）；故正規化為**正確語義**，於 docstring/decision **及 published manifest 之 `digest_canonicalization` 欄**明載取捨（非默削，見 R9）；二進位仍嚴格原始-byte。
- Severity: non-blocking

R8
- Risk: 行尾正規化若逐 65536-byte chunk 施 `replace(b"\r\n",b"\n")`，跨界 `\r\n`（`\r` 在 chunk N 末、`\n` 在 N+1 首）被裸-CR 規則誤拆為 `\n\n`，digest 隨檔長/CRLF byte 偏移**隨機**失敗，破壞決定性（gemini blocking）。
- Trigger: 文字檔長 > 65536 且某 `\r\n` 恰跨 chunk 邊界。
- Detection: 以「`\r\n` 置於 65536 邊界」之 fixture 測 digest 等於整檔正規化之 digest；現 `sha256_file` 之 chunk loop（snapshot_manifest.py 讀 65536）。
- Mitigation: **整檔讀入後正規化再雜湊**（`path.read_bytes()`，非逐 chunk replace）；template 治理檔小有界、整檔讀安全；測涵跨界 case。
- Severity: blocking

R9
- Risk: 正規化僅改 docstring、未現於 published 驗證面——manifest 露 `algorithm:"sha256"`，而 `SECURITY.md`／`docs/security/release-signing.md`／`docs/templates/security/README.md` 告 acquirer「可重算 sha256」；acquirer 依原文以 raw bytes 重算必敗（codex blocking）。
- Trigger: acquirer 跨平台以原始-byte sha256 重算比對。
- Detection: 核 manifest 有無宣 canonicalization；核 acquirer 文是否載正規化規約；`verify` 對缺/誤 canonicalization 欄是否 fail-closed。
- Mitigation: manifest 加 `digest_canonicalization:"text-eol-lf-v1"`（schema `@2`、向後容）；`verify` 讀並核（缺/不符 fail-closed）；更新三 acquirer 文載復現規約；`release_gate.py` 結構層容/核此欄；測證 verify 對缺/誤欄 fail-closed。
- Severity: blocking

R10
- Risk: NUL-sniff 非健全二進位判別——無早-NUL 之二進位格式漏網被當文字正規化、digest 失真（codex blocking）。
- Trigger: 日後 template/ 加無早-NUL 之二進位檔。
- Detection: 以無早-NUL 但非 UTF-8 之 bytes fixture 測，須走原始-byte 路徑（非正規化）。
- Mitigation: **強判別 fail-closed**——text ⇔ 整檔 UTF-8 可 decode **且**無 `\x00`；二者任一不成即 binary（原始-byte）；docstring/decision 宣**現 release surface 為 text-only 不變量**（`git ls-files` 證零二進位），未來二進位走 fail-closed binary 路徑；測涵「UTF-8-decode 失敗→binary」「含 NUL→binary」二 case。
- Severity: blocking
