## Proposed Changes

1. **marker 修（二腳本各一行）**：`detect_repo_root()` 之 `if (parent / "council-forge-governance-repair-plan-v3.5.md").is_file()` → `if (parent / ".council-forge-source-repo").is_file()`。理據：① 該死 marker 自始不存在（git 無史）；② `.council-forge-source-repo` 為既存、git-tracked、源 repo 之 canonical sentinel（`guard_contract_validator.py:14 SOURCE_REPO_SENTINEL`），二腳本本源-root 偵測器（既有 `template/` 條件即源-only 證），故源 sentinel 語意正確；③ 餘二條件不動，`matches[-1]` 取最外層，三條件 AND 僅真源 root 命中、不誤判祖先。
2. **twin 鏡改**：二 `template/artifacts/scripts/run_*.py` 施同一行改（root 與 twin 現 IDENTICAL，改後仍 IDENTICAL）。
3. **manifest regen（一次）**：`python artifacts/scripts/snapshot_manifest.py generate --output .well-known/release-manifest.json`；核 diff 僅二 twin entries＋root digest（integrity caveat：勿以 regen 掩非預期變動）。
4. **補測（root-only）**：`test_run_quality_gates.py` — (a) `from run_quality_gates import detect_repo_root` → 斷言 `== Path(__file__).resolve().parents[2]`（孿生 conftest REPO_ROOT）；(b) run_precommit_check 同；(c) **負測**：monkeypatch SCRIPT_PATH 至無 marker 之路徑 → `pytest.raises(RuntimeError)`（detector 契約不破）；(d) subprocess `run_quality_gates.py --self-check` → 斷言 stderr/stdout 無 `repo_root_detection_failed`。二腳本 `detect_repo_root` 僅於 main() 呼、非 import-time，import 安全、不觸 QC-IMPORT-001。
5. **動工序**：plan-gate(codex+gemini APPROVE) → 施 1-4 → 跑測+全 pytest → impl-gate(codex+gemini APPROVE) → verify → done。

## Risks

R1
- Risk: 新 marker `.council-forge-source-repo` 之 check 法（`is_file()`）與其實狀不符，或三條件組合於某祖先誤命中，致 `detect_repo_root` 回錯目錄或仍 raise。
- Trigger: `.council-forge-source-repo` 實為 dir、或被某祖先目錄亦具（連同 quality-baseline+template）。
- Detection: pre-flight 已證 `.council-forge-source-repo` 為 file（`test -f` IS_FILE）；新 test 斷言 `detect_repo_root() == parents[2]`（真源 root）；裸 CLI `--self-check` 不再 detection-fail。
- Mitigation: 沿用 `detect_repo_mode` 之 `.is_file()` 慣例（SOURCE_REPO_SENTINEL）；保留 quality-baseline+template 二條件（已唯一定位源 root）；test 正/負雙證。
- Severity: blocking

R2
- Risk: 僅改 root 而漏 twin（或改 twin 而漏 manifest regen）→ root-vs-twin 漂移（machine-green：非 EXACT_SYNC 故 guard_contract 不擋）下游散壞版；或 template/ 觸而未 regen → release-integrity 二測 fail-closed。
- Trigger: 漏 twin 同步步、或漏/錯序 manifest regen。
- Detection: `cmp` root vs twin 二腳本皆 IDENTICAL；`snapshot_manifest verify --manifest` exit 0；release-integrity pytest（`test_council_forge_release_manifest_matches_template_snapshot` 等）綠；`git status` 核變動檔集。
- Mitigation: root 與 twin 同改（單發 Edit、grep 回核 IDENTICAL）；**先碼改→後一次 regen**；驗 manifest diff 僅二 twin entries＋root digest。
- Severity: blocking

R3
- Risk: 修後 `run_quality_gates.py --self-check` 能跑、遂露**既存** QC findings（exit 3），被誤認為本修引入之 regression。
- Trigger: repo 有 broken-detector 所掩之潛在 QC 議題。
- Detection: 跑 `--self-check` 觀 exit code 與 findings；對照 pytest（其以 fixture 跑 QC 邏輯、現 1931 綠）判 QC 邏輯本健。
- Mitigation: AC-2 限「不再 repo_root_detection_failed」（detect 成）、非「exit 0」；若露真 QC findings＝gate 正常運作之發現，據實另稟、非本修 regression；本 task 不改 QC 邏輯。
- Severity: non-blocking

R4
- Risk: 新 test `import run_quality_gates`/`run_precommit_check` 觸發 import-time 副作用，破 QC-IMPORT-001 或污染測試。
- Trigger: 二模組於 import 時即呼 detect_repo_root 或他副作用。

- Severity: non-blocking
