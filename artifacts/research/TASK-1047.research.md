## Research Questions

- RQ-1: What are the exact failure categories of the 36 pre-existing pytest failures, and what is the minimal repair pattern for each?
- RQ-2: Why does `validate_context_stack.main()` produce empty stdout under pytest's capsys?
- RQ-3: Why do the UTF-8 wrap tests assume `importlib.reload(vcs)` triggers stream wrapping when the wrap is now a CLI helper called only from `main()`?
- RQ-4: What's the minimum coverage configuration that brings the CI gate from a hard 100% requirement to a green outcome without hiding meaningful test debt?

## Confirmed Facts

- CF-1: All 36 failures fall into four repair patterns identified by inspecting `artifacts/scripts/test_guard_units.py`. (a) `def fake(args, cwd=None)` mock signatures don't accept the `timeout` kwarg added to production `run_command` — affects `TestRrtsCaseRT001to010 / 011to020 / 021to023 / 024to029` and `TestRrtsRunCommand` (~15 tests; fixed by adding `timeout=None, **kwargs`). (b) Status fixtures don't declare `assurance_level` since TASK-1008 strict mode — central helpers `_make_full_status` (line 4021) and the three local `_modern_status` helpers (lines 1944, 2812, 2879) all need the field added. (c) Task-side fixtures don't include `## Assurance Level` / `## Project Adapter` sections — central builders `_setup_valid_done_tree` (line 7449) and `_build_task_artifact` (line 4114) need the sections added. (d) UTF-8 wrap tests assume `importlib.reload(vcs)` triggers wrap, but `init_streams` is now an explicit CLI helper. Inline citation: https://github.com/arcobaleno64/consilium-fabri/actions/runs/25384059516
- CF-2: `validate_context_stack.main()` calls `init_streams()` first thing, and `init_streams` may replace `sys.stdout` with a fresh `io.TextIOWrapper`, breaking pytest's capsys capture chain. Inline citation: `artifacts/scripts/validate_context_stack.py` lines 21-32 (`init_streams` definition with `sys.stdout = io.TextIOWrapper(...)`).
- CF-3: `test_validate_markdown_artifact_task_with_invalid_profile` writes `## Assurance Level\npoc` and monkeypatches `resolve_assurance_level` to return `alien-level`, but the validator's strict-mode check at `guard_status_validator.py` line 1556 reads `_raw_task_assurance` from text via `extract_single_line_section` — the monkeypatch on the resolver does not affect the strict-mode raw-text path, so the test never triggers the assurance error. The Project Adapter check at line 1751 uses the resolved value (`project_adapter`), so the corresponding monkeypatch does fire correctly.
- CF-4: CI's `--cov-fail-under=100` is currently impossible to satisfy because `run_quality_gates.py` and `run_precommit_check.py` have 0% unit-test coverage (they are CLI runners exercised via subprocess in red-team / fixture flows, not unit-tested). Adding both to `.coveragerc` `[run] omit` removes 874 statements from the denominator and brings local coverage to 95.14%.
- CF-5: The `--cov-fail-under=100` CI gate has been red on master since TASK-1005 (commit `24956035299`, 2026-04-26); 9 days of accumulated test-debt silence. Inline citation: https://github.com/arcobaleno64/consilium-fabri/actions/runs/24956035299 and `.github/workflows/workflow-guards.yml` (the gate definition).
- CF-6: TASK-1045 push (commit `f086552`, run `25384059516`) reproduced exactly the same 36 failures plus the coverage gate fail; net new failures introduced by TASK-1045 = 0. Inline citation: https://github.com/arcobaleno64/consilium-fabri/actions/runs/25384059516 and pytest baseline comparison preserved in `artifacts/improvement/TASK-1045.improvement.md` (36 fail / 1102 pass on master before TASK-1045; 36 fail / 1102 pass after TASK-1045).

## Uncertain Items

- UNVERIFIED: Whether CI on Linux runners produces a different `init_streams()` outcome than Windows local — the UTF-8 wrap tests depend on stream encoding behaviour which may differ. Mitigated by switching the test from `importlib.reload(vcs)` to a direct `vcs.init_streams()` call so the wrap is exercised deterministically regardless of platform.
- UNVERIFIED: Whether lowering the gate from 100% to 90% is acceptable to project stakeholders long-term. Documented as forward-compatibility note in TASK-1047.improvement.md.

## Constraints For Implementation

- CI-1: Mock fakes must use `**kwargs` for forward-compatibility with future production signature changes; don't enumerate every kwarg the fake might receive.
- CI-2: Central status / task fixtures (in `_make_full_status`, `_modern_status` × 3, `_setup_valid_done_tree`, `_build_task_artifact`) must declare `assurance_level` / `## Assurance Level` directly so all tests using them pass strict mode. Tests intentionally exercising the missing-field path can pop or override.
- CI-3: UTF-8 wrap tests must call `vcs.init_streams()` directly rather than relying on `importlib.reload(vcs)`.
- CI-4: ContextStack `test_main_passes_on_valid_repo` must monkeypatch `vcs.init_streams` to no-op so capsys capture is preserved.
- CI-5: `.coveragerc` omits the two CLI runners with rationale comments; CI gate threshold drops from 100% to 90% per `## Constraints` allowance.
- CI-6: All test-side changes mirror to `template/` per source-template alignment (Tier 4/5 manual but desirable).
