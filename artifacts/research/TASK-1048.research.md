- CF-4: 三檔基線行數：`artifact_schema.md` 1150、`orchestration.md` 642、`subagent_roles.md` 572；總計 2364 行。`wc -l` 已驗證。
- CF-5: `consilium-fabri-governance-repair-plan-v3.5.md` 含 `docs/artifact_schema.md §5.X` 引用，但此檔依使用者裁定屬版本固化 artifact，不在本批處置範圍。引用更新建議透過「新增回鏈索引段於 artifact_schema.md §5」之被動方式涵蓋（讀者讀 §5 索引即可導航至 spec 檔）。
- CF-6: `artifacts/scripts/workflow_constants.py`、`guard_status_validator.py`、`test_guard_units.py` 三檔之引用為註解或 docstring 內之文件指引（非 hardcoded path 載入）。`Grep` 確認無 `Path("docs/artifact_schema.md")` 或同類 import-style 引用。因此拆分新檔不會破壞 validator 行為，只需更新註解／docstring 中之路徑回鏈。
- CF-7: `artifacts/scripts/guard_contract_validator.py` 之 sync contract 檢查不維護「期望檔案白名單」，而是依「root↔template SHA-256 比對」與「Tier 規則」運作。新增 `docs/schemas/`、`docs/orchestration-workflow.md`、`docs/raci-matrix.md` 之檔，只要 root 與 template 同步，contract 自動通過；無須修改 validator 程式碼。
- CF-8: source template repo 之 sync contract（見 `docs/orchestration.md §9`）對新子目錄之要求為「新增於 root 之 workflow 文件，必須在 template/ 對應路徑建立位元等同鏡像」。`docs/schemas/` 為新子目錄，必須同時在 `template/docs/schemas/` 下建立。
