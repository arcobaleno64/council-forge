## Research Questions

- RQ-3: PowerShell 之 `$prompt | & native.exe args` pipeline 是否正確 redirect stdin 給 native 執行檔？

## Confirmed Facts

- CF-1: Codex CLI 0.128 之 `exec` 子命令明確支援 stdin 為 prompt——`codex exec --help` 文字：「If not provided as an argument (or if `-` is used), instructions are read from stdin. If stdin is piped and a prompt is also provided, stdin is appended as a `<stdin>` block」。本機實測：`echo "test" | codex exec -m gpt-5.4 -c model_reasoning_effort="low" --sandbox workspace-write --skip-git-repo-check --` 印「Reading prompt from stdin...」並啟動 dispatch（5 秒後 kill 終止）。Inline citation: [1] codex CLI 0.128 `codex exec --help` output (https://github.com/openai/codex/tree/v0.128.0).
- CF-2: Codex 0.128 之 sandbox / approval 旗標：`-s, --sandbox <SANDBOX_MODE>` 取值 `read-only|workspace-write|danger-full-access`；`-a, --ask-for-approval <APPROVAL_POLICY>` 取值 `untrusted|on-failure (deprecated)|on-request|never`，其中 `never` 為非互動執行之 default。`--full-auto` 雖未列於 0.128 help，仍接受但發 deprecation warning（per memory `project_followup_codex_wrapper_gpt55.md` §A.3）。本機實測：純跑 `codex exec ... --sandbox workspace-write` 之 banner 印「approval: never」即 default。Inline citation: [2] `codex --help` + `codex exec --help` output (https://github.com/openai/codex/tree/v0.128.0).
- CF-3: PowerShell 之 `$prompt | & native.exe args` pipeline 將 PowerShell-side 字串透過 stdin redirect 給 native 執行檔。既有 `Invoke-CodexAgent.ps1` 行 131 用 `$null | & $Executable $processArgs 2>&1` 之 `$null` 作為 closed stdin；改為 `$Prompt | & $Executable ...` 即將 prompt 內容當 stdin 餵入。Inline citation: [3] PowerShell about_Pipelines + `Invoke-CodexAgent.ps1` 行 131 之既有 pattern。
- CF-4: Windows cmd.exe 之命令列 args 總長度上限為 8191 字（含 `cmd.exe /c <command line>` 之 fully qualified 字串）；該限制為 cmd.exe shell 啟動前之拒絕，與 PowerShell 自身無關。stdin pipe 完全繞過此限制，因 stdin 經由 OS 之 pipe（無命令列長度約束）。Inline citation: [4] Microsoft Docs "Command prompt (Cmd. exe) command-line string limitation" KB 830473 (https://learn.microsoft.com/en-us/troubleshoot/windows-client/shell-experience/command-line-string-limitation).
- CF-5: 既有 caller 對 `-TaskScale` 之使用：grep 顯示僅 `Invoke-CodexReview.ps1` 行 166 與 `Invoke-CodexAgent.ps1` 行 22（default）使用，且皆指定 `'standard'`。8 個 ValidateSet 值（`tiny / docs-only / standard / high-risk / cross-module / critical / security / architecture`）中，僅 `standard` 之實際 caller 存在；其餘 7 值為「保留 backward compat」之未來擴充點。v2 ladder 之 mapping 對既有 caller 行為僅影響 `'standard'` → 中（5.4）即可。Inline citation: [5] grep `-TaskScale\s+\w+|TaskScale\s*=\s*['\x22]` 結果（2026-05-06 retrieved locally）。
- CF-6: `prompt_regression_cases.json` 之 PR-010（行 271-313）對 `docs/subagent_roles.md` 與 `Invoke-GeminiAgent.ps1` 兩 file pin 住「3 gemini models including pro」之 must_contain_all。PR-023（行 603-633）對 `CODEX.md` 與 `Invoke-CodexAgent.ps1` 兩 file pin 住「`gpt-5.4-mini` / `gpt-5.3-codex` / `gpt-5.4`」之 must_contain_all（PS1 file 含 `gpt-5.3-codex`）。本批移除 wrapper 之這些 model 後，PR-010（PS1 部分）+ PR-023（PS1 部分）會 fail；需修 PR assertion，但 doc 部分（subagent_roles.md / CODEX.md）保留——doc 修屬 TASK-1056。`--full-auto` 字面值無 PR pin（grep 0 hit），Layer 3 修無風險。Inline citation: [6] `artifacts/scripts/drills/prompt_regression_cases.json` 行 271-313, 603-633（HEAD `1ee12ff`）。

## Uncertain Items

- UNVERIFIED: codex 0.128 在「stdin 同時提供 prompt 為 positional arg」之雙存情境下，stdin 為何種優先。help 文字「If stdin is piped and a prompt is also provided, stdin is appended as a `<stdin>` block」暗示混合接收，但本批 long-prompt path 採「stdin only, 不傳 positional prompt」之乾淨切換，避免雙存歧義。
- UNVERIFIED: 真實 Council e2e 試跑（AC-14）對單 commit diff（`-DiffSource HEAD` 之 1ee12ff TASK-1052 commit）之 token cost 之精確值（mini ~ $0.01-0.02 / 5.4 ~ $0.05-0.10 / 5.5 ~ $0.10-0.30）；本批以「整體執行時間 ≤ 8 分鐘」作為 cost ceiling 之 proxy。
- UNVERIFIED: codex 0.128 之 `--ask-for-approval never` 是否 default 即 `never`——`codex exec` 之 banner 印「approval: never」可能是 default，也可能是 inherited from `~/.codex/config.toml` 之 user-side 設定。本批 wrapper 為了 explicit，仍會在 dispatch 中傳 `-a never`（top-level flag，置於 exec 子命令之前）。

## Constraints For Implementation

- CI-1: Layer 1 之 stdin pipe 切換閾值取 7000 字（保留 ~1000 字 buffer 給 PowerShell 端 args 構建之 model name / sandbox flag / `-c` config 等）；prompt > 7000 → stdin pipe；≤ 7000 → 既有 positional path。
