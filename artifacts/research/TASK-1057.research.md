- CF-6: PowerShell 對 `git checkout HEAD -- <file>` 之行為：tracked file → restore 到 HEAD 版本；untracked → exit 1 with stderr「did not match any file(s) known to git」。對 untracked 應改用 `Remove-Item -Force -ErrorAction SilentlyContinue`。判斷 tracked: `git ls-files --error-unmatch <path>` exit 0 即 tracked，非 0 即 untracked。Inline citation: https://git-scm.com/docs/git-ls-files
- CF-7: PowerShell 路徑特殊字元（含中文 / 空格 / `[` / `]`）於 `git status --porcelain` 之輸出會以 quoted form 包裹（含 `"` 雙引號），如 `?? "artifacts/foo bar.md"`。本批設計：path 含空格時 wrapper 須先 trim 雙引號；以 raw byte 比對為原則（避免 PowerShell 自動解 escape 之風險）。Inline citation: https://git-scm.com/docs/git-status#_porcelain_format_version_1（"In the absence of `-z`, the file paths are quoted as explained for the configuration variable `core.quotePath` (see git-config[1])"）。

## Uncertain Items

- UNVERIFIED: `git status --porcelain` 對 deeply-nested untracked 目錄之行為（如 sub-agent 新建 `artifacts/research/foo/bar/stray.md` 之三層深度）是否輸出單一 `?? artifacts/research/foo/` 或逐檔列出。本批保守設計：guard 對任一條 `git status` 輸出做 path normalize 後比對；若必要再用 `--untracked-files=all` 強制逐檔列出。
- UNVERIFIED: AllowedPaths 之路徑分隔符在 Windows / Unix 跨平台差異。本批 wrapper 為 PowerShell + Windows 主場；路徑統一用 `/` 形式（git 慣例），匹配時 normalize 為 forward slash。

## Constraints For Implementation

- CI-1: post-dispatch guard 注入點 — Codex wrapper 行 173（主 loop 結束、wrap-up 之前）；Gemini wrapper 行 123 處。
- CI-2: `git status --porcelain` 之輸出 parse — 取每行 [3..] 子串為 path（去掉前 2 字 status code + 1 字空格）；rename 形式 `R  old -> new` 取 `new` 部分（split by ` -> ` 取後半）。
- CI-3: AllowedPaths 匹配規則 — 元素以 `/` 結尾視為目錄前綴匹配（path startsWith allowed）；否則精確匹配（path -eq allowed）。路徑統一用 forward slash（git 慣例）。
- CI-4: 違規處置 — `-AutoRestore` 不設定時純報告 + exit 2；設定時對 tracked file 跑 `git checkout HEAD -- <file>`，對 untracked file 跑 `Remove-Item -Force -ErrorAction SilentlyContinue`，再 exit 2。判斷 tracked: `git ls-files --error-unmatch <path> 2>$null; $LASTEXITCODE -eq 0`。
- CI-5: AllowedPaths 為空（既有呼叫者）— skip guard，印「[GUARD] skipped (no AllowedPaths)」一行，wrap-up 行為不變。後向相容硬要求。
- CI-6: exit code 區分 — 既有 API failure 用 exit 1；guard violation 新增 exit 2；wrap-up 之 success 不變 exit 0。
- CI-7: CODEX.md / GEMINI.md 之新「Write Scope Discipline」段須引用 wrapper 之 `-AllowedPaths` / `-AutoRestore` 參數，但不複製 wrapper 之 PowerShell 程式碼字面值（避免文件 / code 漂移）。
- CI-8: `template/` 之 4 對 root↔template 鏡像須 byte-identical。
