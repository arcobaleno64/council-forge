## Confirmed Facts

- Cloud Routines 為 Anthropic 雲端排程之 Claude Code session，於 Pro / Max / Team / Enterprise plan 啟用 Claude Code on the web 後可用，於 [claude.ai/code/routines](https://claude.ai/code/routines) 或 CLI `/schedule` 建立（cf. Claude Code Docs "Automate work with routines" — https://code.claude.com/docs/en/routines）。
- routine 之 prompt 與 repository 設定屬於 saved configuration，存於 user-side claude.ai 帳號；prompt 為 routine 屬性，**非從 repo 載入**，但 prompt 內可指示 Claude 讀 repo 之檔案執行（cf. "The prompt is the most important part: the routine runs autonomously, so the prompt must be self-contained" — https://code.claude.com/docs/en/routines）。
- routine 每次執行於 cloud session 中 fresh clone repo（從 default branch 起），預設僅可 push 至 `claude/`-prefixed branches；`Allow unrestricted branch pushes` 開關可解此限制（cf. "Each repository you add is cloned on every run... By default, Claude can only push to branches prefixed with `claude/`" — https://code.claude.com/docs/en/routines）。
- Cloud Routines 之 minimum interval 為 1 hour；expressions 較頻繁者於 saved configuration 階段被拒（cf. "The minimum interval is one hour; expressions that run more frequently are rejected." — https://code.claude.com/docs/en/routines）。
- daily routine run cap 依 plan tier；超出日 cap 後若啟用 extra usage 計 metered overage，否則 reject 至 window 重置；one-off runs 不計入 daily cap 但仍計 subscription usage（cf. "Routines draw down subscription usage... routines have a daily cap on how many runs can start per account... One-off runs do not count against the daily routine cap" — https://code.claude.com/docs/en/routines）。
- Claude Code 之三層 scheduling 比較：Cloud Routines（雲端、無需 machine on、fresh clone 無 local files）、Desktop scheduled tasks（local machine、access local files、macOS / Windows only）、`/loop`（session-scoped、需 session 開、access local files）（cf. comparison table — https://code.claude.com/docs/en/scheduled-tasks）。
- `/loop` 與 `/schedule` 為不同 skill：`/loop` 為 session-scoped 之 in-session 排程，下層 tools 為 `CronCreate / CronList / CronDelete`，須 Claude Code v2.1.72+；`/schedule` 為 Cloud Routines 之 CLI 入口，會話式建 routine 或 `/schedule list/update/run` 管理（cf. "Run `/schedule` in any session to create a scheduled routine conversationally" — https://code.claude.com/docs/en/routines；"Scheduled tasks require Claude Code v2.1.72 or later" — https://code.claude.com/docs/en/scheduled-tasks）。
- routine 之 GitHub clone access 由 `/web-setup` CLI command 授權（屬 read/clone 權）；GitHub event triggers（PR / Release）須額外裝 Claude GitHub App；本 task 採 schedule trigger 故僅需 `/web-setup` 之 clone 授權（cf. "Running `/web-setup` in the CLI grants repository access for cloning, but it does not install the Claude GitHub App" — https://code.claude.com/docs/en/routines）。
- routine 之 commits / PR 顯示為 user 之 GitHub identity（個人帳號）；非 bot account（cf. "commits and pull requests carry your GitHub user" — https://code.claude.com/docs/en/routines）。
- GitHub Actions schedule trigger 使用 5-field cron 表達式於 `on.schedule.cron` key path；支援 `*` wildcards、`,` lists、`-` ranges、`/` steps（cf. GitHub Docs "Events that trigger workflows" — https://docs.github.com/en/actions/writing-workflows/choosing-when-your-workflow-runs/events-that-trigger-workflows）。
- GitHub Actions scheduled workflows 於高負載時段可能延遲（"The schedule event can be delayed during periods of high loads of GitHub Actions workflow runs. High load times include the start of every hour."），公開 repo 60 天無活動則自動停用排程（cf. https://docs.github.com/en/actions/writing-workflows/choosing-when-your-workflow-runs/events-that-trigger-workflows）。
- GitHub Actions scheduled workflow 之最短間隔為每 5 分鐘一次（cf. "The shortest interval you can run scheduled workflows is once every 5 minutes." — https://docs.github.com/en/actions/writing-workflows/choosing-when-your-workflow-runs/events-that-trigger-workflows）。
- quarterly schedule（每季首日）之 cron 字面值寫成 `'30 5 1 1,4,7,10 *'`（即每年 1/4/7/10 月 1 日 UTC 5:30 觸發；non-`:00` minute 規避高負載延遲）（cf. https://docs.github.com/en/actions/writing-workflows/choosing-when-your-workflow-runs/events-that-trigger-workflows）。
- `actions/github-script@v7` 採 Node 20，最新 stable version；於 hardened workflow 採 SHA pinning convention（cf. GitHub repo `actions/github-script` README — https://github.com/actions/github-script）。
- `actions/github-script@v7` 建 issue 之 API 為 `github.rest.issues.create({owner, repo, title, body})`，於 step 之 `with.script` 內以 multiline JS template literal 撰寫；最低 permissions 為 `issues: write`（cf. https://github.com/actions/github-script）。
- `actions/github-script` 文檔強調 dynamic value 應透過 `process.env` 而非 `${{ ... }}` 直接 expression injection，以防 script injection vulnerabilities（cf. https://github.com/actions/github-script）。
- 既有 `.github/workflows/security-scan.yml` 已含 pip-audit job（行 18-41），於 PR / push to master / workflow_dispatch 觸發（cf. `artifacts/scripts/guard_contract_validator.py` line 18 之 EXACT_SYNC_FILES 列表確認 yml 不在 strict sync 範圍；security-scan.yml 內容由本 session 直讀證實）。
- 既有 `.github/workflows/workflow-guards.yml` 含 unit tests / contract guard / prompt regression / status guard / red team static / context stack / repo health 七 step（cf. 本 session 之 file read 結果；validator 路徑於 `artifacts/scripts/guard_contract_validator.py` 與 `artifacts/scripts/guard_status_validator.py`）。

## Constraints For Implementation

- weekly Claude routine 之 prompt source：repo 內 `.github/prompts/weekly-claude-audit.prompt.md` 為 single source of truth，routine 之 saved prompt 僅為 thin pointer（如「Read and execute the workflow described in `.github/prompts/weekly-claude-audit.prompt.md`」），便於版本控管。
- weekly Claude routine 之 commit pattern：採 `claude/weekly-audit-<YYYY-MM-DD>` branch + PR 至 master；review artifact 寫至 `artifacts/reviews/weekly-<YYYY-MM-DD>/<commit-range>.md`；prompt 須明列此 destination 與 branch convention，以利 user review。
- weekly Claude routine 之 minimum interval 受 Cloud Routines 1-hour limit；weekly 為合法（604800s ≫ 3600s），不觸限。
- weekly Claude routine 之 daily run cap：weekly cadence 每週僅 1 run，遠低於任何 plan 之 daily cap，無 quota 風險。
- quarterly threat model workflow 之 cron：`'30 5 1 1,4,7,10 *'`（避 `:00` 高負載）；台灣時間每年 1/4/7/10 月 1 日 13:30；`workflow_dispatch:` 應併設為 fallback 手動 trigger（GitHub Docs 文檔化之公開 repo 60 天無活動自動停用之風險於本 repo 不適用，因有持續 push）。
- quarterly threat model workflow 之 issue 建立 API：`actions/github-script@v7` + `github.rest.issues.create({owner, repo, title, body, labels})`；採 SHA pinning（version pin 即可，本 repo 既有 workflow 採 v6.0.2 / v6.2.0 之 SHA pin 慣例）。
- quarterly threat model workflow 之 permissions：`permissions: { issues: write, contents: read }`；最小化權限，不開 PR write / actions write。
- quarterly threat model workflow 之 issue body：採 multiline template literal，引用 `docs/red_team_runbook.md` 與 `docs/security_cadence.md` 之 relative path；不嵌 dynamic `${{ }}` expression（per script injection guideline，所有 dynamic value 走 `process.env`）。
- quarterly threat model workflow 之 issue title：`[Quarterly Threat Model] YYYY-Qn — <YYYY-MM-DD>`；季度數採 JS Date 計算（month 1=Q1, 4=Q2, 7=Q3, 10=Q4）。
- quarterly threat model workflow 之 labels：`security, cadence, quarterly`；labels 須 repo 已建立或 actions/github-script 自動建（後者需 `issues: write` 已含此能力）。
- cadence doc（`docs/security_cadence.md`）之結構：每 cadence 條目含 `Trigger`、`Cadence`、`Artifact Destination`、`Owner` 四欄；setup steps 段列 `/web-setup` 授權 + Cloud Routine 建立 + GitHub Actions cron 確認三步驟。
- template/ 鏡像義務：新建 `.github/prompts/weekly-claude-audit.prompt.md`、`.github/workflows/quarterly-threat-model.yml`、`docs/security_cadence.md` 三檔須完整鏡像至 `template/`，SHA-256 一致；`docs/orchestration-workflow.md` 之引用增補（若涉及）亦同步。
- 不放 secrets / token / API key 字面於任一新檔；user-side `/web-setup` 之 GitHub auth 屬 user 帳號流程，repo 內僅以 placeholder 引用。
- 既有 `.github/workflows/security-scan.yml`、`.github/workflows/workflow-guards.yml`、`prompt_regression_cases.json`、`test_guard_units.py` 不動。
