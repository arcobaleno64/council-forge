## Research Questions

1. `git stash push -u -- <pathspec>` 是否同時對 tracked-modified 與 untracked 兩類檔執行 pathspec 過濾？
2. `:(exclude)<dir>/` pathspec magic 是否被 `git stash push` 接受，且其語義是否如 `git ls-files` 等指令一致？
3. 在 Git for Windows + PowerShell 之既有 wrapper 執行環境下，pathspec 字面值（含 `:(exclude)`、forward-slash dir prefix）是否可正確 parse 而不被 PowerShell quoting 或 cmd.exe 8191-char limit 擾動？
4. 經 exclude 後若 working tree changes 為空集，`git stash push` 之 exit code 與 stdout message 為何？
5. staged 檔（index `A ` / `M `）在 pathspec exclude stash 中之保留行為？

## Confirmed Facts

- 官方 `git-stash` doc 明文：「The new stash entry records the modified states only for the files that match the pathspec. The index entries and working tree files are then rolled back to the state in HEAD only for these files, too, leaving files that do not match the pathspec intact.」即 pathspec 限制 stash 範圍且 working tree 上未被 pathspec 命中之檔保留 disk 原狀（source: <https://git-scm.com/docs/git-stash>）。
- 官方 `git-stash` doc §`-u` 段明文：「When used with the push and save commands, all untracked files are also stashed and then cleaned up with git clean.」即 `-u` 擴展 stash 範圍至 untracked 檔；該 doc 並 reference `gitglossary` 之 pathspec 條目，未排除 exclude magic 之適用（source: <https://git-scm.com/docs/git-stash>）。
- 官方 `gitglossary` doc 明文：「After a path matches any non-exclude pathspec, it will be run through all exclude pathspecs (magic signature: `!` or its synonym `^`). If it matches, the path is ignored. When there is no non-exclude pathspec, the exclusion is applied to the result set as if invoked without any pathspec.」即 `:(exclude)` magic 可獨立使用（無 non-exclude）對全 result set 執行 exclusion（source: <https://git-scm.com/docs/gitglossary>）。
- 本機 smoke 於 Git for Windows 跑 `git stash push -u -m "smoke1" -- ':(exclude)artifacts/tasks/' ':(exclude)artifacts/code/'`，pre-stash 4 changes（`wiki/x.md` M、`scratch.md` ??、兩 `artifacts/tasks/` 與 `artifacts/code/` ??），post-stash 顯示兩 lifecycle 之 untracked 檔留 disk、其餘已 stashed；後續 `git stash pop` 4 changes 全恢復、stash 自動 drop（source: `artifacts/research/TASK-1060.research.md` §Source Cache smoke-1）。
- 本機 smoke 於 Git for Windows 跑 `git stash push -u -m "smokeA" -- ':(exclude)artifacts/tasks/' ':(exclude)artifacts/code/'`，pre-stash 含 staged `A scratch.md` + unstaged ` M wiki/x.md`，post-stash 兩檔皆 stashed、index 清空，post-pop staged 與 unstaged 兩狀態皆精確還原（即 staged 屬性保留通過 stash/pop round-trip）（source: `artifacts/research/TASK-1060.research.md` §Source Cache smoke-A）。
- 本機 smoke 於 Git for Windows 跑 `git stash push -u -m "smokeB" -- ':(exclude)artifacts/tasks/' ':(exclude)artifacts/research/' ':(exclude)artifacts/plans/' ':(exclude)artifacts/code/' ':(exclude)artifacts/test/' ':(exclude)artifacts/verify/' ':(exclude)artifacts/status/'` 對僅含 `?? artifacts/tasks/TASK-fake.task.md` 之 working tree，stdout 印 `No local changes to save` + exit code 0 + 無 stash 建立；lifecycle 檔仍於 disk（source: `artifacts/research/TASK-1060.research.md` §Source Cache smoke-B）。
- `git stash push` 之 SYNOPSIS 表 `<pathspec>` 為變參數（`<pathspec>...`）；本機 smoke 已在同指令並列傳 7 個 `:(exclude)<dir>/` pathspec 字面值並執行成功，總指令長度 ~500 chars 遠低於 cmd.exe 8191-char limit（source: <https://git-scm.com/docs/git-stash>）。
- PowerShell quoting 規則：single-quoted strings 為 verbatim、不對 `$` / 反引號做 expansion、不對 `:` / `(` / `)` 做特殊解讀；wrapper 在傳 `:(exclude)<dir>/` 至 `git.exe` 時須以 single-quoted 字面值傳入以避被 PowerShell parse 為 scope/grouping operator（source: <https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_quoting_rules>）。
- 既有 wrapper 之 `Save-PreDispatchState` 之 stash 指令僅含 `-u -m <msg>` 而無 pathspec，行為與本機 smoke 之全 stash 一致（無過濾）；修改點為該 helper 之 stash command 參數構建（source: `artifacts/scripts/Invoke-CodexAgent.ps1`）。
- `Pop-PreDispatchState` 與 `Restore-PostDispatchDelta` 之既有行為對 stash content 之子集為何不敏感——pop 對任意 stash entry（含 pathspec 過濾後之 stash）之恢復語義不變；本 task 不需修改此二 helper（source: `artifacts/scripts/Invoke-CodexAgent.ps1`）。
