## Research Questions
- **RQ1**: 現行 `CITATION_PATTERN` 與 `RESEARCH_SOURCES_ENTRY_PATTERN` 的具體限制與缺漏為何？
- **RQ2**: 實務研究寫作中常見的引用形態為何（含中文括號、裸路徑等）？
- **RQ3**: 如何在擴展 Regex 時防禦 Catastrophic Backtracking？
- **RQ4**: RT-002 紅隊 fixture 的現行機制與放寬後的重校準對策為何？

## Confirmed Facts
- 現行 `CITATION_PATTERN` 僅接受 `https?://\S+`、`` `gh api ...` `` 或 backtick-wrapped 且符合特定副檔名（`md|json|txt|py|ps1|csproj`）的檔名。 (Source: `artifacts/scripts/guard_status_validator.py:137`)
- 現行 `RESEARCH_SOURCES_ENTRY_PATTERN` 強制要求 `https?://\S+`，不支援 repo 內路徑（如 `docs/X.md`）作為來源連結。 (Source: `artifacts/scripts/guard_status_validator.py:165`)
- 常見的設定與腳本副檔名如 `ini`, `toml`, `yml`, `yaml`, `cfg`, `sh` 目前不在白名單內，導致引用這些檔案時驗證失敗。 (Source: `artifacts/tasks/TASK-1061.task.md`)
- Sub-agents 常用 `（Source: docs/X.md:42）` 或 `（source: ...）` 形態，其中全形括號 `（` 與 `）` 未被現行 `CITATION_PATTERN` 接受。 (Source: `artifacts/research/TASK-900.research.md`, `artifacts/research/TASK-961.research.md`)
- 寫作中常出現 `per artifacts/scripts/test_guard_units.py:10610` 形態，雖含明確檔名與行號，但因無 backtick wrap 而被 validator 攔截。 (Source: `artifacts/tasks/TASK-1061.task.md`)
- 對於內部規格文件（如 `docs/schemas/artifact-spec-research.md`），通常無外部 URL，實務上應允許以 repo 路徑替代。 (Source: `artifacts/tasks/TASK-1061.task.md`)
- 防禦 Catastrophic Backtracking 原則 1：避免巢狀量詞 (Nested Quantifiers)，如 `(a+)*` 會導致指數級回溯。在路徑匹配中應使用明確的字元集 `[A-Za-z0-9_./\\-]+` 且避免在其後緊接重疊的量詞。 (Source: [2] https://owasp.org/www-community/attacks/Regular_expression_Denial_of_Service_-_ReDoS)
- 防禦 Catastrophic Backtracking 原則 2：原子分組 (Atomic Grouping)。Python 3.11+ 支援 `(?>...)`，一旦分組匹配成功則不再回溯，可用於鎖定已匹配的路徑文字。 (Source: [1] https://docs.python.org/3/library/re.html)
- 防禦 Catastrophic Backtracking 原則 3：特定性優先。將具備明確定界符（如 backticks, brackets）的模式放在 alternative branch 前端，裸路徑放在後端並搭配字邊界 `\b`。 (Source: [2] https://owasp.org/www-community/attacks/Regular_expression_Denial_of_Service_-_ReDoS)
- 環境確認：當前環境為 Python 3.14.3，完全支援 `(?>...)` 與 `++` 等進階 Regex 特性。 (Source: [1] https://docs.python.org/3/library/re.html)
- `case_rt_002()` 透過 `re.sub(r"[（(]source:[^)）]+[)）]\.", ".", text, count=1)` 移除 citation。 (Source: `artifacts/scripts/red_team/case_builders.py`)
- 若放寬 `CITATION_PATTERN` 以接受不含 `source:` 字樣的裸路徑或括號路徑，現行 `re.sub` 可能無法完全移除 citation，導致 RT-002 漏接。 (Source: `artifacts/scripts/red_team/case_builders.py`)
- 重校準對策：應將 `re.sub` 的 pattern 改為與新版 `CITATION_PATTERN` 對應的「破壞性版本」（如移除任何符合 path token 的結構），確保 `must include an inline citation` 仍能觸發。 (Source: `artifacts/tasks/TASK-1061.task.md`)

## Constraints For Implementation
- **C1: Supersets Only**: 新 Regex 必須是舊版的超集，不得破壞既有合法 artifacts（如 backtick-wrapped 形態）。
- **C2: Extension Whitelist**: 確切擴展列表為 `md|json|txt|py|ps1|csproj|ini|toml|yml|yaml|cfg|sh`。
- **C3: Bracket Symmetry**: 支援 `(...)` 與 `（...）`，內部可含選擇性的 `source: ` (case-insensitive) 前綴。
- **C4: Atomic Path Matching**: 裸路徑匹配應使用 `\b` 字邊界，避免部分匹配非路徑文字。
- **C5: Repo Path in Sources**: `RESEARCH_SOURCES_ENTRY_PATTERN` 應改為 `(?:https?://\S+|[A-Za-z0-9_./\\-]+\.[A-Za-z0-9]{1,10})` 形態。
- **C6: Dual-Site Consistency**: `guard_status_validator.py` 與 `guard_helpers/markers.py` 的 `CITATION_PATTERN` 必須同步更新，建議在 plan 階段評估集中化。
- **C7: RT-002 Recalibration**: 破壞點應改為「移除所有包含路徑特徵的 token」，確保 RT-002 仍能報錯。
