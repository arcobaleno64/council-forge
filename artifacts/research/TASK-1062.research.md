## Research Questions

- RQ-1: 既有 `Save-PreDispatchState`（per `artifacts/scripts/Invoke-CodexAgent.ps1:129-181`）採 `git stash push -u` 並以 `:(exclude)<lifecycle>/` pathspec 排除 7 lifecycle dirs（TASK-1060）；此設計在 caller 傳 `-AllowedPaths` + lifecycle 內已存在 untracked prereq 之 dispatch path 上，post-dispatch guard（line 360-395）為何將該 prereq 視為 sub-agent write 並由 `Restore-PostDispatchDelta`（line 183-201）誤刪？
- RQ-2: post-dispatch guard 應如何辨識「pre-dispatch 已存在於 lifecycle 之 untracked 檔」與「sub-agent dispatch 期間新增 / 修改之 lifecycle 檔」之差異，使二者分類正確而 destruction-prevention 契約（TASK-1057）+ stash baseline（TASK-1059）+ lifecycle visibility（TASK-1060）三者同時成立？
- RQ-3: Codex wrapper 之 7000-char stdin pipe cutover（`artifacts/scripts/Invoke-CodexAgent.ps1:275`，per TASK-1054）為何在 5001-char multiline prompt 上失效，並造成 codex CLI 收到 prompt 第一行（`[ROLE]` ≈ 8 chars）後 9 retry × tier 全 deterministic 失敗？PowerShell → cmd.exe → node `process.argv` 鏈路上 multiline arg 之截斷點為何？
- RQ-4: Gemini wrapper（`artifacts/scripts/Invoke-GeminiAgent.ps1:215-235`）目前完全無 stdin pipe 路徑，僅以 `$processArgs += "-p", $Prompt`（line 225）走 native arg；本 task 同步修兩 wrapper 時，gemini CLI 是否支援 stdin pipe（取代 `-p`），需於 coding 階段 first-edit 直接驗證？
- RQ-5: 既有 wrapper-level pytest fixture（`artifacts/scripts/conftest.py:40-150` 之 `FakeExe` / `tmp_repo` / `run_wrapper`）+ TASK-1060 引入之 `_seed_lifecycle_artifacts` / `_build_lifecycle_inspector_exe` 是否足以撰寫 ≥ 4 條新 case 覆蓋 Bug A / Bug B 雙向（正向 + 反向）+ regression smoke，無需擴 fixture？

## Confirmed Facts

- F-1: `Invoke-CodexAgent.ps1:362-395` 之 post-dispatch guard 採 `git status --porcelain --untracked-files=all` 列舉 changedPaths，逐 path 用 `Test-PathInAllowed` 判斷是否在 `-AllowedPaths` 內；不在者列入 `$violations` 並由 `Restore-PostDispatchDelta` 處理（per `artifacts/scripts/Invoke-CodexAgent.ps1:362-395`）。
- F-2: `Restore-PostDispatchDelta`（`artifacts/scripts/Invoke-CodexAgent.ps1:183-201`）對 untracked path 採 `Remove-Item -Path $v -Force -Recurse -ErrorAction SilentlyContinue`；對 tracked path 採 `git checkout HEAD -- $v`。lifecycle 內既有未 commit 之 untracked 檔（如 `artifacts/tasks/TASK-1061.task.md`）落入 untracked branch，被 Remove-Item 刪除（per Bug-W3 事件 log，`memory/feedback_wrapper_known_bugs.md:27-32`）。
- F-3: `Save-PreDispatchState`（`artifacts/scripts/Invoke-CodexAgent.ps1:129-181`）之 `:(exclude)<lifecycle>/` pathspec 僅作用於 `git stash push -u --` 之 stash 範圍；不影響 post-dispatch `git status` 之輸出（per `artifacts/plans/TASK-1060.plan.md:50-58` §1.3 + R2 R3 設計記述）。
- F-4: TASK-1060 之設計文（`artifacts/plans/TASK-1060.plan.md:36-56`）明示「lifecycle exclusion 解 stash 階段之 visibility」；未涉及 post-dispatch classification。Bug A 為 TASK-1060 之 unhandled corner case：lifecycle exclusion 讓 prereq 在 dispatch 期間可見，但 post-dispatch 仍被誤刪。
- F-5: `Invoke-CodexAgent.ps1:275` 設 `$useStdinPipe = $Prompt.Length -gt 7000`；此值純由字元數決定，無 multiline / newline 條件。`prompt_size=5001` 之 multiline prompt（≥ 1 LF）走 native arg 路徑（line 290 `$null | & $Executable $processArgs 2>&1`，`$processArgs` 末尾包含 `$Prompt` per line 277）。
- F-6: PowerShell 透過 `& <native-exe> <args>` 呼叫 `.cmd` batch wrapper 時，args 經 PowerShell native command argument passing 序列化為單一 Windows CommandLine string；`.cmd` 之 batch parser（`%~1` / `%*`）對 multiline string 在第一個 LF/CR 處截斷，後續 line 在 cmd.exe 之 batch context 中視為新 command。codex.cmd 經 `node` 接到的 `process.argv` 因此只含 prompt 第一行（per Bug-W4 事件 log，`memory/feedback_wrapper_known_bugs.md:34-41`；TASK-1054 之 7000-char threshold 設計初衷正為規避此 quirk，per `artifacts/plans/TASK-1059.plan.md` 之 stdin pipe rationale）。
- F-7: Codex CLI v0.128 之 `exec` subcommand 既有 stdin pipe 路徑已被 `Invoke-CodexAgent.ps1:287-291`（`if ($useStdinPipe) { $procOutput = $Prompt | & $Executable $processArgs 2>&1 }`）使用；當 `$useStdinPipe = $true` 時 `$processArgs` 不含 prompt（line 276-278 `if (-not $useStdinPipe) { $processArgs += $Prompt }`），prompt 純由 stdin 傳入；TASK-1054 之 6 條 wrapper-level pytest 已驗證 long prompt 路徑可用（per `artifacts/scripts/test_invoke_codex_agent.py:96-127`）。
- F-8: Gemini wrapper（`artifacts/scripts/Invoke-GeminiAgent.ps1`）完全無 stdin pipe 路徑：line 225 永遠 `$processArgs += "-p", $Prompt`，line 235 永遠 `$null | & $Executable $processArgs 2>&1`。Gemini CLI 之 stdin 接收行為（`gemini` 無 `-p` 時是否 unconditional 讀 stdin）coding 階段須以 micro-smoke 直接驗證；驗證失敗即升級 decision 並停止此 fix path，wrapper 採單一 path（stdin），不額外引入分支。
- F-9: 既有 wrapper-level pytest fixture（`artifacts/scripts/conftest.py`）提供：(a) `FakeExe` class（line 40+）支援 `configure(stdout, stderr, exit_code, sequence)` 與 `calls()` log；(b) `fake_codex_exe` / `fake_gemini_exe` fixture（line 123-130）；(c) `tmp_repo` fixture（line 133-148）建獨立 git repo；(d) `run_wrapper` fixture（line 150+）以 PowerShell sub-process 跑 wrapper。POSIX 無 PowerShell 環境會 skip。
- F-10: TASK-1060 引入之 `_seed_lifecycle_artifacts`（`test_invoke_codex_agent.py` / `test_invoke_gemini_agent.py`）已支援在 `tmp_repo` 內種植 `artifacts/tasks/` / `artifacts/research/` 等 lifecycle dirs 之 untracked prereq；`_build_lifecycle_inspector_exe` 提供 dispatch-time disk stat。本 task 之新增 case 可直接複用。
- F-11: TASK-1054 之既有 `test_stdin_pipe_threshold_uses_wrapper_side_log`（`test_invoke_codex_agent.py:96-127`）以 `prompt_size=6999`/`7001` 為 cutover 邊界，斷言 `stdin_pipe=False` / `stdin_pipe=True`。本 task fix B 採「永遠走 stdin」後，此 case 之 short-prompt assertion（line 126）需從 `stdin_pipe=False` 改為 `stdin_pipe=True`；7000-char 邊界之斷言改為「兩端皆 stdin_pipe=True」。視為 spec 變更而非 regression（per `artifacts/tasks/TASK-1062.task.md` §AC-3 之 routing decision 推薦）。
