## Confirmed Facts
- PR #14 CI 八閘六綠、二紅：`validate` 之 `test_council_forge_release_manifest_matches_template_snapshot` 與 `test_publish_release_verify.py::test_integrity_gate_passes_on_valid_repo` 失敗（"published manifest does not match the template snapshot (fail-closed)"），`release-integrity` job 列眾 `docs/**.md`/`pytest.ini`/`requirements.txt`/`requirements-dev.txt` "digest changed" + "root digest mismatch"（CI run 27398511847/27398511900，PR `gh api`-able；本地對應檔 `artifacts/scripts/test_downstream_security_template.py`、`artifacts/scripts/test_publish_release_verify.py`）。
- `git config core.autocrlf` = **true**（本機 Windows）；repo 根**無** `.gitattributes`（`git ls-files` 列無之）——故行尾由 autocrlf 而非 attribute 決定，正規化未釘（對照 raw-byte 讀檔 `artifacts/scripts/snapshot_manifest.py`）。
- `git ls-files --eol` 證：文字檔 `i/lf w/crlf`（如 `.well-known/release-manifest.json`、`pytest.ini`、`requirements.txt`、`template/docs/workflow_state_machine.md`）——git **object 皆 LF**（autocrlf commit 時正規化），Windows **working tree 為 CRLF**（smudge）；`.py` 為 `i/lf w/lf`（如 `artifacts/scripts/snapshot_manifest.py`）。
- `git cat-file blob :template/docs/workflow_state_machine.md` = LF-only；同檔 working tree 讀 `rb` = HAS-CRLF——object/worktree 行尾歧異實證（對照 `artifacts/scripts/snapshot_manifest.py` 之讀檔法）。
- `snapshot_manifest.py::sha256_file` 以 `open(path,"rb")` 讀**原始 bytes**、無行尾正規化；`compute_manifest` rglob `template/` working tree 逐檔 `sha256_file`、排 cruft、sorted、Merkle-ish root；generate 與 verify **共用** `compute_manifest`（`artifacts/scripts/snapshot_manifest.py`）。其 docstring 自誓「byte-reproducibility is the whole point — a hash nobody can reproduce is theater」然只正規化路徑（POSIX）未正規化行尾（`artifacts/scripts/snapshot_manifest.py`）。
- 本機（CRLF working tree）`snapshot_manifest.py verify --manifest .well-known/release-manifest.json` → `[OK] manifest matches (230 entries)` exit 0；CI（Linux LF）同命令 root mismatch——manifest 自 CRLF working tree 生成、記 CRLF digest，與 LF 重算不符（`.well-known/release-manifest.json`、`artifacts/scripts/snapshot_manifest.py`）。
- 唯一 manifest 檔＝`.well-known/release-manifest.json`（root 為其內欄位、非另檔；`git ls-files` grep release-manifest/release-snapshot 僅此一）。
- repo **無追蹤二進位檔**（`git ls-files` 無 png/jpg/ico/woff/zip/gz/pdf/ttf/otf；`git ls-files --eol` 無 `w/-text`）——行尾正規化於現況無二進位之虞（text-only 不變量），**強判別（UTF-8-decodable 且無 NUL）**為未來 fail-closed 防（`artifacts/scripts/snapshot_manifest.py`）。
- `snapshot_manifest.py` 為 **source-only**：docstring 明載不入 `template/`、不入 `EXACT_SYNC_FILES`（同 scaffold_downstream.py/drift_dashboard.py/propagate_downstream.py）；`release_gate.py`（family source+template+EXACT_SYNC）為**結構**驗證、不重算 digest——本修**加其結構 `digest_canonicalization`/schema 核**（`SUPPORTED_SCHEMA_VERSIONS:49`、check:122；不動重算/crypto 邊界）＋同步 template EXACT_SYNC 對偶（`artifacts/scripts/snapshot_manifest.py`、`artifacts/scripts/release_gate.py`）。
- `snapshot_manifest.py` 現 100% cov（128 stmts，per memory + `validate` job 之 cov 表）；新增 branch 須測涵否則 cov gate 紅（`artifacts/scripts/test_snapshot_manifest.py`）。
