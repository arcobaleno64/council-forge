## Confirmed Facts

- CF-1（RQ-1，**樞要**）：`guard_status_validator.py` **全然不讀** `superseded_by` 或 `reconciliation_ref`——全檔 grep 二鍵零匹配（`artifacts/scripts/guard_status_validator.py`）。required_artifacts 由 `state_required_artifacts(state, …)` 經 `resolve_verification_policy(assurance, adapter)["required_artifacts_by_state"].get(state)` 算（`guard_status_validator.py:1604-1614`），**僅 keyed by (state, assurance, adapter)**，無 superseded/reconciliation 特例。故 approach A 須**為 guard 增一全新能力**（識別並放寬 reconciled-terminal），非既有 knob 之微調。
- CF-2（RQ-1）：DEFAULT `required_artifacts_by_state["done"]` = `{task, code, verify, status}`（`guard_status_validator.py:86`）；**docs-spec/mvp** 經 adapter 解析後 done = `{task, plan, verify, status}`（TASK-1095 closure 時 guard_status WARN 實證：`computed=['plan','status','task','verify']`）。TASK-1001 為 docs-spec → done 需 **plan**（其無），故 `guard_status --task-id TASK-1001` 於 state=done 必 FAIL（missing plan）。
- CF-3（RQ-3，**blast radius**）：現 repo **唯 1 任務具 `superseded_by`**（grep `artifacts/status/` 計數=1）、**唯 TASK-1001 具 `reconciliation_ref`**（`artifacts/status/TASK-1001.status.json`）。即 reconciled-terminal 之窘況**今僅 TASK-1001 一例（N=1）**。→ 通用 guard 機制（approach A）對單例恐 over-engineer（[[avoid-over-layering]]）；惟亦意味低破壞面（改動僅影響此一窄路）。
- CF-4（RQ-4）：**無獨立非捏造之 TASK-1001 plan 源**。`artifacts/plans/TASK-1001.plan.md` **不存在**；存在者為 `artifacts/plans/TASK-1011.plan.md`（reconciliation 任務之 plan，承載 TASK-1001 canonical closure 之規劃）。即 TASK-1001 之「規劃」實由 TASK-1011 承載。重建一獨立 TASK-1001 v3.4 plan 將虛構歷史設計（無真源）→ **approach B（歷史重建）違「不捏造」紅線，否決**。（另路：撰一**誠實薄 reconciliation-plan**——不虛構歷史設計、僅記「規劃由 successors 承載 + 處置依據」——係異於 B 之子選項，惟須核其是否合 plan schema 之 Proposed Changes/Files Likely Affected/premortem 結構。）
- CF-5（RQ-2）：`docs/workflow_state_machine.md` 之 8 態**無 task-state「superseded」**（superseded 僅見於 artifact-status 之合法值，`guard_status_validator.py:126-130`）。`blocked` 語意＝「任務卡住」（§1）、解除須 Gate-E `Status: applied` 之 improvement artifact（§5、§6.8）。→ approach C「永久留 blocked」係 sink 誤用（blocked 設計為暫態待解，非已竣終態）；欲以 blocked 為認可終態須**明改狀態機語意**（新增 reconciled-terminal 子類或類似），非零變更。
- CF-6（RQ-5）：TASK-1001 現具 `task/decision/status/verify` 四 artifact（無 plan/code/research）；`artifacts/verify/TASK-1001.verify.md` Pass Fail Result=pass、其 AC-5b 經 TASK-1095 已改 verified（§Acceptance Criteria Checklist + §Reconciliation Matrix）、open_verification_debts 清空；decision §Verified AC Summary 全 10 AC 皆有 evidence（canonical Phase1/2 + TASK-1011；AC-6/10 superseded-by-TASK-1007；AC-5b verified|TASK-1095）。即**狀態機 done 入條「verify 存在且 pass」（§3）已滿足，唯卡在 policy 之 plan-required（CF-2）**。
