## Confirmed Facts

- `detect_repo_root()` 之首條件索檔 `council-forge-governance-repair-plan-v3.5.md`（見 `artifacts/scripts/run_quality_gates.py:82`），該檔不存在於 repo root 且 git 無任何歷史 → 條件恆 False、`matches` 恆空、`detect_repo_root` 恆 raise（見 `artifacts/scripts/run_quality_gates.py:86`）。
- 同一死 marker 條件亦存於 sibling（見 `artifacts/scripts/run_precommit_check.py:167`），`SCRIPT_PATH` 定義同形（見 `artifacts/scripts/run_precommit_check.py:44`）。
- `.council-forge-source-repo` 為既存、git-tracked 之 file，且為源 repo 之 canonical sentinel `SOURCE_REPO_SENTINEL`（見 `artifacts/scripts/guard_contract_validator.py:14`），由 `detect_repo_mode` 用以判源/下游（見 `artifacts/scripts/guard_contract_validator.py:392`）。
- 二腳本各有 template/ twin（`template/artifacts/scripts/run_quality_gates.py`、`template/artifacts/scripts/run_precommit_check.py`），現與 root IDENTICAL、含同死 marker（見 `template/artifacts/scripts/run_quality_gates.py:82`）；`.well-known/release-manifest.json` 含此二腳本路徑；然二者不在 `EXACT_SYNC_FILES`（見 `artifacts/scripts/guard_contract_validator.py:19`）。
- `detect_repo_root()` 僅於 `main()` 內呼、非 module-level（見 `artifacts/scripts/run_quality_gates.py:979`），import 無此副作用。
- 現存 test 無覆蓋此二 detector：`test_detect_repo_root_no_match`（見 `artifacts/scripts/test_repository_and_pdca.py:1846`）測之為另一模組（其錯訊 "Unable to detect repository root" 異於本二腳本之 "Unable to detect repo root"）。
- 二腳本之 QC 邏輯經 pytest 之 fixture 以顯式 repo_root 跑（見 `artifacts/scripts/conftest.py`），現綠（baseline 1931 passed / 2 skipped，Stage 2 regression 實測）。
- `detect_repo_root` 之餘二條件索 `artifacts/governance/quality-baseline.v3.5.json` 與 `template/` dir，已可唯一定位源 repo root；`matches[-1]` 取最外層匹配（見 `artifacts/scripts/run_quality_gates.py:88`）。
