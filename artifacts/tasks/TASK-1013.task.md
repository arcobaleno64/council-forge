## Objective

修正 `artifacts/scripts/validate_context_stack.py` 的 import-time side effect：將模組層（module-level）的 `sys.stdout`/`sys.stderr` 替換移入明確的 `init_streams()` 函式，確保 import 時不產生任何 repo mutation、stream mutation、stdout/stderr 輸出或其他非預期副作用。

## Background

`validate_context_stack.py` 在 lines 18-21 包含模組層的 stream 替換邏輯：

```python
if sys.stdout.encoding != "utf-8":
    sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding="utf-8", errors="replace")
if sys.stderr.encoding != "utf-8":
    sys.stderr = io.TextIOWrapper(sys.stderr.buffer, encoding="utf-8", errors="replace")
```

此邏輯在 import 時無條件執行，違反以下原則：
1. 若 sys.stdout 為 io.StringIO（無 .encoding 屬性），會引發 AttributeError。
2. 作為 library 被 import 時，靜默替換呼叫者的全域 stream 物件。
3. 任何 side-effectful behavior 應受 `if __name__ == "__main__"` 或等效 CLI path 保護。

v3.4 plan §4.6b 要求：引入 explicit `init_streams` 函式，並提供 unit test 證明 import-only 無輸出。
