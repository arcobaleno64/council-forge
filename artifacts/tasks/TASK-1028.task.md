## Background

v3.5.0 治理品質控制面已封閉：TASK-1023..TASK-1027 五任務全 done、verify pass。control surface 包含：

- TASK-1023（commit `a40f6bc`）— v3.5.0 plan + manifest 引入。

- TASK-1025（commit `6da55ed`，repair_pass=2）— P0 quality gates bootstrap（QC-SYNC-001 / QC-SCHEMA-001 / QC-IMPORT-001 / QC-GOLDEN-001）+ baseline-aware enforcement。
- TASK-1026（commit `a3aaeec` + status seal `4ecafd8`）— Minimal PCACC（PCACC-001..004 結構檢查 + runner + template mirror）。
- TASK-1027（commit `d6d878b`）— Artifact Obligation Matrix（presence-only，11 條 rule）。

但 v3.5.0 之 control surface 證據結構僅含「正向 self-check」（每個 runner 對自身 commit 跑 self-check pass）。**負向證據**（受控 negative test 證明 control 真能擋下被預測之 violation）尚缺。validator monolith 之 characterization coverage 仍稀薄；FIND-30（validator/test monolith maintainability risk）若於缺乏 characterization 與 negative test 之下進入 module split，refactor 風險高。

v3.5 manifest `version_split_rule`：
- v3.5.0 — controls before refactor（已 closed）。
- v3.5.1 — refactor only after controls are green：allow small validator split candidates；forbid new governance plane。
- v3.5.2 — maintenance policies after evidence accumulates。
- v3.6 — structural evolution after behavior is characterized：requires v3.5.x characterization tests and gates green for at least one release cycle。

本任務將 v3.5.1 之主題明確化為「Gate Proving and Refactor Readiness」（即在做 split 之前，先**證實** v3.5.0 之 control 真能擋；先**特徵化** validator 之既有行為；先**決定** policy registry 抽法），並產出 v3.5.1 之 candidate task 序列（TASK-1029 QC-SYNC negative tests / TASK-1030 PCACC negative tests / TASK-1031 characterization expansion / TASK-1032 policy registry design decision）。

對 v3.5 plan §5.6 / version_split_rule「v3.5.1 refactor only after controls are green」之解讀：本 plan 將「allow small validator split candidates」**緊縮**為「allow split _readiness_ work；split 本身延至 v3.6」，理由為：v3.5.0 缺乏 negative test 與 characterization，立即 split 違反 v3.6 之啟動條件（characterization tests 與 gates 維持綠至少一個 release cycle）。此緊縮由本任務 decision artifact 顯式記載。
