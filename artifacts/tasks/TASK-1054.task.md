## Background

- **背景一（test_guard_units 巨檔風險）**：`test_guard_units.py` 自 TASK-9xx 系列累積至 12,848 行 / ~100 個 `Test*` class，covers `guard_status_validator` / `guard_contract_validator` / `prompt_regression_validator` / `build_decision_registry` / `aggregate_red_team_scorecard` / `validate_scorecard_deltas` / `validate_context_stack` / `migrate_artifact_schema` / `legacy_verify_corpus` / `workflow_constants` / `classify_existing_tasks` / `backfill_pdca_labels`。單檔過大導致：
  - merge conflict 概率高（TASK-1056 / 1059 等多 task 同時改動皆撞此檔）
  - pytest collect 時間長（無 collection cache 時整檔重 import）
  - editor / Grep 之 navigation IO 成本高
  - 拆分為主題模組可保留 baseline、對 root↔template SHA-256 sync 友善（拆分後鏡像細粒度更高）

- **背景二（wrapper-level pytest 缺口）**：TASK-1053（commit `a0942d4`）修 wrapper bug + v2 ladder（mini / 5.4 / 5.5；effort=high）+ Gemini 兩階 fallback；TASK-1059（commit `646af55`）修 `-AutoRestore` stash-based baseline；TASK-1057（commit `7e006fe`）加 sub-agent write scope guard。但這些行為皆以 **手動 mock smoke** 驗證，無 pytest 集成，回歸偵測依賴人工。**下一個風險點即 wrapper-side 未受 pytest 保護**。
  - `Invoke-CodexAgent.ps1` 待 cover：stdin pipe threshold（7,000 字 cutover）、args 順序（`-a never -s workspace-write exec`）、best-effort capture path（codex 0.128 review-only `exit_code=1` quirk）、`-TaskScale` ValidateSet 之 8 舊值 mapping 至 v2 三層
  - `Invoke-GeminiAgent.ps1` 待 cover：兩階 fallback（`gemini-3.1-flash-lite-preview` → `gemini-3-flash-preview`）、auto-fallback path 不含 `gemini-3.1-pro-preview` 字面值
  - `Invoke-CodexReview.ps1` 待 cover：`-DryRun` branch（不真呼叫 codex）、frontmatter 寫入 `artifacts/reviews/<timestamp>-<model>.md`、3 model dispatch 順序（mini / 5.4 / 5.5）

- **mock executable pattern 之 PS quirk**：TASK-1053 已遇 `$input` 在 in-session pipeline 中之 quirk；本 task 需以 `process { }` block 或 `cmd.exe` shim 解；fixture 方向為「temp dir 放 fake `codex.cmd` / `gemini.cmd`」+ `PATH` 注入。
