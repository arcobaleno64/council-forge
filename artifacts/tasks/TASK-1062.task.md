## Objective

修復 `Invoke-CodexAgent.ps1` 與 `Invoke-GeminiAgent.ps1` 之兩處獨立 wrapper bug：

**Fix 1：post-dispatch write-scope guard 之 lifecycle classification 漂移**
當 caller 傳 `-AllowedPaths` 且 lifecycle 內未 commit 之 prerequisite artifacts（task / research / plan / status）存在時，guard 應將其視為「user pre-existing untracked」而非「sub-agent writes」，避免被 `Restore-PostDispatchDelta` 誤刪。TASK-1060 之 lifecycle exclusion 只解 stash 階段之 visibility（讓 sub-agent 看得見 prereq）；未解 post-dispatch 階段之 classification（git status 仍視為 untracked，被 guard 當成 sub-agent write）。

**Fix 2：multiline prompt 之 cmdline truncation 風險**
TASK-1054 之 stdin pipe cutover 設於 7000 char。當 prompt < 7000 char 且含 newline 時，wrapper 走 `& codex.cmd -p $Prompt` 之 native arg 路徑；於 Windows `cmd.exe` batch 之 `%~1`/`%*` 解析過程，多行字串會在第一個 LF/CR 處截斷，使 codex CLI 收到 prompt 第一行（如 `[ROLE]`）而非完整 prompt，造成 9 retry × N tier 之 deterministic dispatch 失敗。Gemini wrapper 同邏輯但因 gemini.cmd 之解析路徑稍異，未必同樣失效；本 task 同步修兩 wrapper。

兩 fix 同位於 `Save-PreDispatchState` 前後 / `processArgs` 構造段；同一 task 修以減一個 commit / verify cycle。

## Background

### Bug A 起源（2026-05-08 TASK-1061 Research dispatch）

Claude 於 dispatch 前已 Write `artifacts/tasks/TASK-1061.task.md` 與 `artifacts/status/TASK-1061.status.json` 兩 untracked 檔；以 `-AllowedPaths @("artifacts/research/TASK-1061.research.md") -AutoRestore` 派發 Gemini 後：

1. `Save-PreDispatchState` 因 `-IncludeLifecycleInBaseline=$false`（default）排除 7 lifecycle dirs，未 stash 兩檔 → sub-agent 可見 ✓
2. Gemini 完整寫入 research artifact ✓
3. Post-dispatch guard 跑 `git status --porcelain --untracked-files=all`，仍見兩檔為 untracked → 視為 sub-agent writes outside AllowedPaths
4. `Restore-PostDispatchDelta` 對 untracked 走 `Remove-Item -Recurse` → 兩檔被刪 ✗

事件記錄：`memory/feedback_wrapper_stash_uncommitted_prereq.md` 之 claim「caller 傳 -AllowedPaths 即使 lifecycle 未 commit 亦可 dispatch」在此 path 失效。

### Bug B 起源（2026-05-08 TASK-1061 Coding dispatch）

同 session 派 Codex 跑 plan §CP-1..CP-6（5001 char prompt，multiline，起手 `[ROLE]`），wrapper log:

```
Attempt 1/3 (stdin_pipe=False, prompt_size=5001)...
[!] Intercepted API/Execution Error (ExitCode: 1)
[stderr tail]
user
[ROLE]
codex
請指定你要我扮演的角色...
```

Codex CLI 之 user-input 段只顯示 `[ROLE]` 一行（≈ 8 chars），剩餘 ~4993 char prompt 全失。3 model tier × 3 retry = 9 次 deterministic 同失敗。Root cause：Windows `cmd.exe` 批次解析在 `& codex.cmd -p $Prompt` 之第一個 LF/CR 截斷，codex CLI 之 `process.argv` 拿到的 `-p` value 為被截短之片段。TASK-1054 之 7000-char stdin pipe cutover 設計初衷正是規避此 bug；但 5001 < 7000 未觸發 stdin pipe，正好踩坑。
