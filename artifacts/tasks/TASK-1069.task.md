## Background

**起源 finding（2026-05-19 audit）**：TASK-1068 push 後查 GitHub Actions 跑列狀況，發現 weekly-council-audit cron 連續兩週失敗（2026-05-10 / 05-17 schedule runs，皆 3m+ 耗時但 fail）。Root cause from log：

```
##[error]Unhandled error: HttpError: GitHub Actions is not permitted to create or approve pull requests.
```

Workflow yml 已含 `permissions: pull-requests: write` (line 8-10)；但 repo-level toggle「Allow GitHub Actions to create and approve pull requests」未開覆蓋之。Two-layer AND 機制（yml-level + repo-level）導致 cron 跑 council-review 成功 + 生 review artifacts 成功 + 開 PR step fail。

**Doc 既有狀態（per docs/security_cadence.md line 55）**：「`Allow GitHub Actions to create and approve pull requests` 須 enabled（本 workflow 之 `Open PR` step 經 `actions/github-script` 開 PR 需求）」已記載；但「首次驗證」（line 61）step 2 未含 explicit toggle check；無 `gh api` 命令；無 drift detection 信號對應之 mitigation。屬 docs-yml-runtime 三層 gap：doc 寫了但 setup process 未驗證、runtime 未被監測。

**Already-applied immediate fix（user 2026-05-19 授權）**：

```
$ gh api repos/arcobaleno64/council-forge/actions/permissions/workflow
{"default_workflow_permissions":"read","can_approve_pull_request_reviews":false}  # 修前

$ gh api -X PUT repos/.../actions/permissions/workflow -F default_workflow_permissions=read -F can_approve_pull_request_reviews=true

$ gh api repos/arcobaleno64/council-forge/actions/permissions/workflow
{"default_workflow_permissions":"read","can_approve_pull_request_reviews":true}   # 修後 ✓
```

Runtime 驗證留下次 weekly cron（2026-05-24 Sunday 18:00 UTC）自然 surface。
