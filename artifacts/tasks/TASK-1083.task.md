## Objective

P8-D2（release-integrity，**校正 PS.2 之 under-claim**）：為 council-forge 自身**真實 release surface**——其經 `propagate_downstream.py` 釋予下游之 `template/` SSOT snapshot——建一**可機驗、可獨立復現**之完整性機制，使 **PS.2（Provide a Mechanism for Verifying Software Release Integrity）誠實由 `gap` 升 `partial`**；並以 additive overlay 並出下游 release-integrity 模板（map-don't-recreate，native verify 主驗）。

**recon（4-agent，逐字核 NIST SP 800-218 v1.1 官方 PDF p.10-11）**：**PS.2**＝「Provide a Mechanism for Verifying Software Release Integrity：Help software acquirers ensure that the software they acquire is legitimate and has not been tampered with」；**PS.2.1**＝「Make software integrity verification information available to software acquirers」（notional examples：①於善護之處張貼 release 之 cryptographic hashes；②CA code-signing；③定期審簽章流程）。**PS.2↔PS.3 界線**：PS.2 朝 acquirer（產+布 verifier 供消費者驗真），PS.3 朝 producer 自身（archive+protect，SBOM 居 PS.3.2）——**PS.2 ≠ SBOM、≠ PS.3，不得 double-count**。

**樞要發現（校正 under-claim）**：前態 mapping 稱 PS.2「gap、council-forge 無二進位→covered 結構不可達」實為**少報**。「不產編譯 artifact」≠「不釋出 release artifact」：council-forge 之 `propagate_downstream.py` 以裸 `shutil.copy2` 將 `template/` snapshot 釋予下游，**今零完整性機制**——下游無從驗所收檔確出自可信 council-forge snapshot 而未遭竄。PS.2.1 文義 artifact-type-agnostic。

**主公裁（2026-06-08，三問 + 雙審後一問）**：① **校正：建自身機制，PS.2 升 partial**；② **結構+可復現 manifest（partial；真簽章緩）**——NIST Example-1，真簽章+key-lifecycle（Example 2/3）記為 **path-to-covered，緩**；③ **並出下游模板**（map-don't-recreate）；④ **雙審後：release_gate 精簡為唯 `checksums`**，in-toto/Sigstore/Tauri 之結構與密碼學驗全交 native tool（cosign/`gh attestation verify`/minisign/`dotnet nuget verify`）於下游模板（純 map-don't-recreate，契 [[avoid-over-layering]]；gemini [medium] 過度設計之慮）。
