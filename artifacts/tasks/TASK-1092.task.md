## Objective

FB-5（承 TASK-1087 CP-4 + 本役親見五次）：`Invoke-CodexAgent.ps1` 之 retry-pattern 誤判——成功（exit 0）但 codex **review 答案內容（STDOUT）**含 transient-error 子串（`429`/`Failed to fetch`/`ECONNRESET`/`RateLimitError` 等，審錯誤處理碼、引 grep tool-output、或回顯 prompt 內錯誤詞時常見）即被當作失敗，致 **spurious retry / backoff / tier 升級 / 終「all fallback models exhausted」EXIT=1**——雖內容實為有效 review。

recon 親證根因：`$combinedText = "$outText`n$errText"`（**STDOUT 答案 + STDERR 合併**）；成功閘（line 420）`$lastExitCode -eq 0 -and -not ($combinedText -match $RegexPattern)` 與 backoff 判（line 442）`$combinedText -match $RegexPattern` 皆對**含答案之合併文**匹配。註（417-419）自承「exit code 為真，pattern 僅防 exit-0 漏之罕見 transient」。**本修據此將分類掃描限 STDERR、不掃 STDOUT 答案**：因 codex review 合法引/論「429」與 codex 真吐「429」**文本同形不可辨**，掃 STDOUT 必致觀測到之 false-positive；**exit-code 為契約之真，STDERR 為次級網**；「exit-0-stdout-only-transient」（須 codex 違 exit-code 契約）列 **accepted residual**（非已驗證為不可能——本 repo 無 codex 各版串流行為之可復現證據，本機實為 0.137.0；唯 codex 親跑證 PS `2>&1` 於 exit 0/1 皆保 stderr 為 `ErrorRecord`，分流可行）。本役 codex impl-v2 一段確認跑 **5 attempt**（每 attempt review 皆有效 approve），即此疾之實證。

修（surgical）：成功閘改 **`if ($lastExitCode -eq 0)`**——**exit-code 為唯一真，成功時不掃任何流之內容**；RetryPatterns 僅用於 **exit≠0/throw 之 backoff 日誌分類**（掃 `$errText`/exception，二支 sleep 同、僅 log 異）。catch 令 `$errText = $_.Exception.Message`（失敗信號）。best-effort STDOUT capture（TASK-1053）、tier 升級、RetryPatterns 陣列、diagnostic dump（`$combinedText` 全文）皆不動。**註（impl-layer 演進）**：初設「匹配限 STDERR」於實作層雙審**經運行時實證為不足**——codex CLI 將被審內容（含 transient 子串）echo 至 **STDERR 與 STDOUT 皆有**（tool trace/reasoning），故 exit-0 之**任何**內容掃描皆 false-positive；正解乃 exit 0＝無條件 success。
