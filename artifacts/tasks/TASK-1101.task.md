## Objective

校正 `run_quality_gates.py --self-check`（及 `run_precommit_check.py`）之 sync-coverage 檢查對**刻意源-only 腳本**誤報 `missing_template` 之 over-strict 行為——令該 self-check 不再因 ~23 個本就無 template/ twin 之源-only 檔（generators／dashboards／root-only tests）而報 `overall_status=fail`。承 TASK-1100 修復 detect_repo_root 後首度可跑該 CLI 而暴露之 R3 觀察。

## Background

- TASK-1100 修 `detect_repo_root` 死 marker 後，`run_quality_gates.py --self-check` 首度可跑，報 `overall_status=fail`：~23 個源-only 腳本（如 `snapshot_manifest.py`、`scaffold_downstream.py`、`drift_dashboard.py`、`propagate_downstream.py`、`ssdf_*`、諸 `test_*.py`，含 TASK-1100 新增之 `test_run_quality_gates.py`）被該 self-check 之同步檢查旗為 `current_status=missing_template`。
- 此等檔**刻意源-only**（不在 `template/`、非散下游）——Stage 1 audit 已確認 `snapshot_manifest.py`／`scaffold_downstream.py`／`drift_dashboard.py`／`propagate_downstream.py` 為 source-only generators（見 [[council-forge-campaign]]）；root-only test 亦有 ~16 既例。故 `missing_template` 對之為**誤報**（false positive），非真缺。
- 此乃該 self-check 之 **pre-existing over-strict 判據**（自始如此，唯因 detect_repo_root 死 marker 致 CLI 從未跑成、故未顯）；**非 TASK-1100 之回歸**（TASK-1100 僅修 detector）。
- 真 gate（pytest 1936、guard_contract、guard_status）皆綠；唯 run_quality_gates 自身 self-check verdict 因此誤報為 fail。
