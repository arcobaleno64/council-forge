### Codex FAIL Disclosure (Pre-Repair)

Codex post-commit verification 對 commit `ea8d09a` 之 TASK-1025 報 FAIL，blocking issue：

> QC-SYNC-001 does not enforce new post-baseline source/template drift. Static inspection shows `run_qc_sync_001()` only iterates `baseline.source_template_pairs`. Committed evidence contains exactly 20 QC-SYNC checks from the TASK-1024 baseline and omits the newly added:
> - `artifacts/scripts/run_quality_gates.py`
> - `template/artifacts/scripts/run_quality_gates.py`
>
> As a result, a new root-only or drifted post-baseline paired file would not be detected as blocking.

**Root cause**：原 `run_qc_sync_001()` 只 iterate `baseline.source_template_pairs`，缺 current pair discovery 步驟，致 post-baseline 新增 pair 不會被偵測。新增的 runner 自身（已 byte-identical）即使 by chance 在 sync，仍未在 evidence 中可見；若日後新增 root-only 或 drifted 的 post-baseline pair，gate 將 silently 漏報。

### Repair (commit hash 待 commit 後填入)

修復擴展 `run_qc_sync_001()` 為兩 pass 設計：

1. **Pass 1（baseline-existing pairs）**：保留原 baseline-aware 行為對 baseline 中 20 條 pair 不變。每條 check 加 `pair_classification: "baseline_existing_pair"`。
2. **Pass 2（post-baseline new pairs）**：新增 `discover_current_pairs()` 函式，依 `SOURCE_TEMPLATE_ROOTS` convention（首批 `("artifacts/scripts", "template/artifacts/scripts")`）枚舉 .py 檔，組成 union；對 baseline 未涵蓋之 source path 標 `pair_classification: "post_baseline_new_pair"`，依以下規則判 status：
   - source + template 都存在且 byte-identical → pass + reason_code=`post_baseline_new_pair_in_sync`
   - drift / missing_template / missing_source 無 waiver → fail + reason_code 對應狀態
   - drift / missing 含 valid unexpired waiver → skipped_with_reason_code
   - waiver shape / expiration 違規 → fail + reason_code=`post_baseline_new_pair_waiver_invalid:...`

修復同步至 template mirror（byte-identical），重跑 self-check 產出新 evidence。
